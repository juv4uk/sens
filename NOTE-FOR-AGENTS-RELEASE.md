## 2. `corridor-sterile`: хибне червоне — причина в ingress, не в `return`

**Виправлення попереднього висновку.** Раніше тут було написано, що гейт
шукає буквальний `return zig_transport::encode_f3(bytes);`, а код має
хвостовий вираз. **Це не так.** Регулярка вже толерантна:

```python
# scripts/check_sterile_zig_corridor.py:489
re.search(r"(?:return\s+)?zig_transport::encode_f3\(bytes\)\s*;?\s*\}\s*$", zig_egress)
```

`(?:return\s+)?` робить `return` необов'язковим. **Додавання `return` не
змінить результату гейта.**

Справжня розбіжність — у **ingress**. Checker вимагає стару форму:

```python
"zig_transport::decode_f3(bytes)?" not in zig_ingress
"zig_transport::decode_t5m_words(&restored)?" not in zig_ingress
```

А `crates/sens-cli/src/bin/sens-trit.rs:41-51` мігрований на T5M-only:

```rust
fn encode_f3_carrier(bytes: &[u8]) -> Result<Option<Vec<u8>>, String> {
    #[cfg(feature = "zig-transport")]
    {
        let words = zig_transport::decode_t5m_words(bytes)?;
        let parsed = sens::PhysicalT5Program::from_exact_words(&words)…?;
        if parsed.form_count() != 1 || bytes.len() > 16 {
            return Ok(None);
        }
        zig_transport::encode_f3(bytes)
    }
```

Немає ні `decode_f3(bytes)?`, ні проміжного `&restored`. Тобто **checker
перевіряє F3-форму, а код уже T5M-форма.**

### Що робити

- **Не** додавати `return` — це нічого не змінить.
- **Не** латати Python-checker (див. п. 6).
- Правильний шлях: перенести цю перевірку в дозволений механізм
  (Rust/xtask) і перевіряти **T5M-форму**, а не F3-форму.
- Після фіксу відтворити гейт на точному SHA. Не склеювати з іншими змінами.
