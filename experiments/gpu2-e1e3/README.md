# E1–E3: виконуваний свідок побітового контракту f32

**Статус:** механізм для evidence ledger ратифікованих A1/B1 (sens#1585, слово
власника 2026-09-28). Оракул працює сьогодні; ноги CUDA чекають cml#360.
Цей каталог — не семантична влада: рішення живуть у #1585/PR #1588, тут лише
їхня перевірка. Див. `CURRENT.md` для порядку авторитетності.

## Призначення

`witness.py` — єдина команда для експериментів E1–E3 із
`docs/research/2026-09-28-gpu2-bitwise-contract.md` §5. Він:

- несе незалежний оракул (чистий stdlib, без numpy);
- проганяє кейси через довільних виконавців (sens, cml CPU, cml CUDA);
- пише evidence ledger (TSV: час, кейс, виконавець, біти, еталон, вердикт);
- розрізняє збіг (PASS-BITWISE), NaN-тег (PASS-TAG, правило B1),
  **порушення контракту FMA (FAIL-FMA-CONTRACT — виконавець злив a*b+c
  у FFMA, отже зібраний без -fmad=false)**, і відмову (NAMED-UNAVAILABLE —
  виконавець назвав свою недоступність, це не тихий зелений).

## Оракул

```text
$ python3 witness.py --self-test
оракул: OK (E1 mul+add=39796000, fma=3979611e)
```

Еталони зафіксовано бітами, не десятками: `a=3e9c03e1`, `b=bf851e33`,
`c=3ea26003`; окремі mul+add → `39796000` (A1); FFMA → `3979611e`
(286 ULP різниці — еталон порушення, не істини). Коректність емуляції
f32-арифметики через f64 — класична умова подвійного округлення
p2 ≥ 2·p1+2 (53 ≥ 50).

## Протокол виконавця

Виконавець — будь-яка shell-команда:

```sh
python3 witness.py \
  --ledger evidence/$(date -u +%Y%m%dT%H%M%SZ)-owner.tsv \
  --run sens='<адаптер sens>' \
  --run cml-cpu='<адаптер cml CPU>' \
  --run cml-cuda='<адаптер cml CUDA>'
```

Свідок ставить середовище і чекає у stdout рядок `BITS=xxxxxxxx`:

- `WITNESS_CASE` — ім'я кейсу (`e1_muladd`, `e2_qnan_0div0`, ...);
- `WITNESS_PROGRAM` — шлях до шаблону програми (можна переписати під
  власний діалект виконавця, не змінюючи кейсу);
- `WITNESS_EXPECTED_BITS` — еталон для довідки.

Ненульовий exit або відсутність `BITS` → `NAMED-UNAVAILABLE` у ledger:
чесна назва недоступності (нема CUDA-пристрою, кейс не підтриманий),
не пропуск.

## Поточні обмеження (чесно)

1. **cml CUDA без `-fmad=false` сьогодні НЕ ПРОЙДЕ E1 — і це правильно.**
   cml компілює NVRTC лише з `-arch` (cml#360), отже чекати
   `FAIL-FMA-CONTRACT` на `cml-cuda` до закриття cml#360 — очікуваний
   результат, який і демонструє необхідність задачі.
2. CUDA-шлях cml сьогодні i32 (`gpu_cuda_live_test`); f32-мапа — GPU-1/#1565
   та #1567. E1 на CUDA стане можливим після них.
3. Шаблони програм у `--emit-programs` — українською поверхнею з десятковими
   літералами; адаптер виконавця відповідає за те, щоб літерали
   округлились до зафіксованих бітів (для цього свідок друкує біти
   в `WITNESS_EXPECTED_BITS`).
4. E2 не фіксує payload NaN — тільки тег (B1). Payload записується у ledger
   як факт, без порівняння.

## Кейси

| кейс | вид | еталон | правило |
|---|---|---|---|
| `e1_muladd` | біти | `39796000` | A1: окремі mul+add |
| `e2_qnan_0div0` | NaN-тег | — | B1: тег, не payload |
| `e2_qnan_inf_minus_inf` | NaN-тег | — | B1 |
| `e2_qnan_sqrt_neg` | NaN-тег | — | B1 |
| `e3_add_pos0_neg0` | біти | `00000000` | (+0)+(−0) → +0 (RNE) |
| `e3_mul_neg1_pos0` | біти | `80000000` | (−1)·(+0) → −0 |

Повна таблиця: `python3 witness.py --oracle`.
