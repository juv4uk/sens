# Семантика належить двійковому SENS

Ці фізичні файли `.sens` — **виконувані SENS-програми**. Їхнє джерело
`.bits` містить лише машинні слова `0/1`, без Lisp-команд і без текстових
ідентифікаторів. Імена файлів — лише для людини. Тести логіки НЕ написані
на Rust чи Python; ці мови можуть використовуватись виключно як механіка
компіляції або пакування.

Рівно D1=1 біт, D2=2 біти, D3=3 біти. D7=7 біт, D8=8 біт,
D9=9 біт, D10=10 біт залишаються незалежними типізованими доменами,
але НЕ отримують викличності лише тому, що їхню координату визначено.

**SENS-логіка:** кожен з перших 8 тестів використовує D3:110 COND,
D3:010 ATOM, D3:101 EQ, D3:001 QUOTE, D3:111 CONS,
D3:100 CAR, D3:011 CDR та D1:1 / D1:0. Сама SENS-програма
повертає точний предикат D1:1 у разі виконання своєї властивості,
D1:0 у разі порушення. `cond-short-circuit.sens` ставить
некоректний CAR у пропущену гілку — виконання її має впасти.

Три `reject-*.sens` — виконувані навмисно некоректні форми:
3-польовий COND, не-D1 умова, EQ пари. Вони повинні відхилятися
семантичним оракулом, а не транспортним декодером.

Фізичне представлення: T5, п'ять тритів на байт, `2` тільки як
роздільник слів та кінцевий padding. Немає жодних внутрішніх
байтових вирівнювань. Точна бітність кожного слова записана в `.bits`.

**Окремо:** 2000+ точнодоменних координат НЕ доводять, що всі вони
викличні або виконуються. Цей корпус доводить обмежений набір
виконуваних законів D1–D3, не приписує без перевірки семантику D4–D10.
Читання `.sens` виконує тільки SENS oracle `sens`, додатково
звіряється другий механічний вхід `sens-trit`.

Запуск із кореня репозиторію:
`bash scripts/test-current-semantic-slice.sh --native-binary-only`.
