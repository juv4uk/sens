## 2. Аксіоми, через які читати кожний коміт

1. **Ідентичність:** точний `(domain, width, binary bits, law)`, а не історична назва/порядковий номер/байт.
2. **D1/D2/D3:** один біт відповіді, два біти структури, D3 `000 () / 001 QUOTE / 010 ATOM / 011 CDR / 100 CAR / 101 EQ / 110 COND / 111 CONS`. Старі розкладки залишаються лише в історії; L1–L5 D3 та ратифікований D4 мають свої закони.
3. **Розділення:** `owner ratification != mechanism admitted != tested native execution != transport roundtrip`. Тест Zig/Rust — свідок механіки, не джерело SENS-значення.
4. **D7/D24+:** цифри D7 — текст; десяткове відображення допускається лише для явно кваліфікованої математики D24+, не є внутрішнім посередником жодного коду.
5. **Транспорт:** звичайний Zig T5 до D9; координатний — до D10. D11 відкладено рішенням власника; збереження провідних нулів і точного домену обов'язкове.
6. **Доказ:** для семантичного PASS потрібен справжній нативний SENS-свідок; позитив/негатив, binary input і receipt. SHA-256 для цілісності; FNV-64 допустимий швидкий некриптографічний відбиток, не доказ походження.

Нормативне джерело: `language-contract.lisp` Contract 11.9 (blob `2b32e4e894046e7ad92792866beea610d3d9396e`). `knowledge/sens-primary.lisp` — **операційна** доктрина, яка сама в заголовку заперечує повноваження творити мовну семантику; `docs/language-core-axioms.md` — історичний текст зі статусом draft, не привід переназначити чинний Contract.

## 5. Готовий формат handoff кожної атомарної міграції

```text
CLAIM: real executor/login | one write-set | baseline main SHA | owning issue
SOURCE: path@original_sha | introduction commit/date | last semantic-change commit
LAW: (domain, exact width, bits, ratification ref, role)
MIGRATION: source.lisp -> packed source.sens -> exact-bit source
MECHANICAL: input SHA-256 | Rust byte parity | Zig byte parity | negative
SEMANTIC: native SENS binary receipt | positive | negative | expected/actual
CI: exact current HEAD + run URL + classification; no success without run
HANDOFF: READY / BLOCKED (specific evidence) / DONE (verified commit SHA)
```

Трактувати кожну проблему як конкретну «можливість розв'язати цікаву задачу», зберігаючи чесний машинний статус FAIL/UNVERIFIED там, де він існує. Відсутність допуску D11 не зупиняє роботу над незалежними підтвердженими D1–D10 програмами. Злиття/force або ратифікація не випливають із цього дослідницького файлу; інтегратор — [#5041](https://github.com/juv4uk/sens/issues/5041), exclusive claims — [#5029](https://github.com/juv4uk/sens/issues/5029).
