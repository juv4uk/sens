# #2460 — Автономне двійкове зростання та виведення за вимогою в Core-Math

Статус: реалізація дослідження рівня P0.
Базова онтологія: #2490.
Фундамент виконавця: #2485 / PR #2623.
Доменний фаєрвол: #2508 / #2509.
Мінімальне насіння: #2426.
Закони: #2425.

## Результат

Автономне зростання двійкових об'єктів та виведення за вимогою (on-demand derivation) реалізовано мовою Rust із нулем зовнішніх залежностей у каталозі `benchmarks/core-math-binary-growth/`.

У канонічній онтології #2490:
```text
семантичний об'єкт = двійкове число + домен + доведений закон
```

Безпосередньо виконується закон зростання із задачі #2460:
```text
відомі біти + доведений закон -> нові біти -> повторне використання нових бітів
```

### 1. Чисте двійкове зростання та ланцюгове виведення
- Двійкові об'єкти є виключно бітовими рядками точної ширини (`BinaryNumber`), типізованими явним доменом `Domain`.
- Ланцюговість є першокласною: новостворені двійкові об'єкти відразу слугують батьками/операндами для подальших застосувань законів.
- Жодних людських імен, рядків у реєстрах результатів чи таблиць підстановки не потрібно і не дозволено для семантичної ідентичності.
- Перевірено на кількох доменах:
  - `SelectorPath`: закон факторного розширення `output = 2 * parent + delta`, розгорнутий ланцюжком до глибини 5 (корінь `101` -> `10101011`).
  - `QGroupFactor`: адитивні та мультиплікативні факторні закони з розширенням ролей.
  - `AffineFunctionGF2`: моноїд афінних ендоморфізмів у GF(2)^2 (`(A, b) ∘ (C, d) = (A * C, A * d XOR b)`) над 6-бітовими координатами.

### 2. Виведення за вимогою (Demand Construction)
- Чітко розмежовує математичне замикання та жадібне перерахування (#2473, #2474).
- Рушій `DemandEngine` будує ВИКЛЮЧНО необхідний підграф DAG проміжних бітових вузлів, потрібних для конкретної цілі виведення.
- Для селектора глибини 3 виведення за вимогою матеріалізує рівно **4 вузли** (1 корінь + 3 кроки), тоді як жадібне повне замикання перелічує **15 вузлів** (коефіцієнт матеріалізації: 4/15).

### 3. Свідок паритету (Parity Witness)
- Обмежений рушій `EagerClosureEngine` систематично генерує всі досяжні об'єкти до глибини `d`.
- Доведено 100% біт-у-біт точний паритет: кожен двійковий об'єкт, отриманий за вимогою, точно збігається з відповідним вузлом у повному замиканні.

### 4. Набір фальсифікаторів
Реалізація задовольняє всі обов'язкові фальсифікатори:
1. **Відсутність насіння**: Спроба виведення без необхідного насіння падає із закриттям помилкою `GrowthError::MissingSeed`.
2. **Відсутність закону**: Спроба виведення з невідомим законом падає із закриттям помилкою `GrowthError::MissingLaw`.
3. **Доменний фаєрвол (#2508)**: Міждоменне застосування закону блокується помилкою `GrowthError::DomainMismatch`.
4. **Інваріантність порядку**: Порядок, у якому виводяться незалежні цілі, не змінює їхні семантичні об'єкти чи бітові рядки.
5. **Інваріантність кешу**: Кешування (мемоізація) не змінює семантичну ідентичність; прогони з холодним і теплим кешем дають абсолютно однакові двійкові об'єкти.
6. **Антинумерологія**: Довільна перестановка бітів або осей руйнує математичний закон і відхиляється.

### 5. Архітектурні інваріанти
- Нуль зовнішніх залежностей від крейтів (секція `[dependencies]` суворо заборонена в `Cargo.toml`).
- Для виконання не потрібні Lisp-середовище, JSON, AST, SHA-геші чи реєстри.
