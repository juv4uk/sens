# Два універсальні дослідні закони D10: Беббідж і Райтер

Дата: 2026-10-09. Першоджерела підтверджено, але **жодного нового ратифікованого значення чи двійкової координати**. Відібрано **два research candidates** у спільному D10: **635 → 637/1024**, unplaced 379 → 381, remaining 389 → 387.

## 1. Скінченні різниці Беббіджа — `FINITE-DIFFERENCE-CERTIFICATE`

**Витоки:** Charles Babbage, *A Note respecting the Application of Machinery to the Calculation of Astronomical Tables*, *Memoirs of the Astronomical Society*, Vol. I, p.309; доповідь 14 червня 1822 р. [Первинний текст](https://en.wikisource.org/wiki/Page:Memoirs_of_Royal_Astronomical_Society_Volume_01.djvu/332). [Музейний опис різницевої машини](https://collection.sciencemuseumgroup.org.uk/objects/co62243/difference-engine-no-1-difference-engine).

**Не стверджувати**, що запропонована нами сучасна функція сертифікації або її повідомлення про помилку існували у Беббіджа. Історичний донор — математичний механізм обчислення таблиць додаванням.

**Контракт:** `(exact_samples, max_degree d) -> CERTIFIED(initial_differences[0..d], next_exact_value) | NOT_CERTIFIED(first_nonzero_delta_order_d+1) | INSUFFICIENT-DATA`. Для сертифікації потрібні **щонайменше d+2** спостережень із однаковим кроком, а всі їхні скінченні різниці порядку d+1 мають бути **точно нульовими**. Наступне значення:
```
f(n) = Σ[k=0..d] binomial(n,k) · Δ^k f(0)
```
Верифікатор використовує незалежне рекурентне додавання останніх елементів різницевої таблиці. Жодного float. Сертифікат гарантує тільки алгебраїчну узгодженість наданих зразків зі степеневою межею, **не істинність майбутніх фізичних вимірів**.

**Фальсифікатори:** `[1,4,9,16],d=2→25`; `[1,4,9,17],d=2` має отримати NOT_CERTIFIED; лише `[1,4,9]` не сертифікує d=2 без четвертого зразка.

**Де корисно:** астрономічні таблиці, калібрувальні сигнали SDR, тактування FPGA/годинників, періодичні музичні параметри, точна перевірка послідовностей. Поліноміальна інтерполяція, якщо її можна побудувати композиційно, є сусіднім законом, але не виправдовує автоматичного виключення: наш контракт містить фальсифікатор і критерій ступеня.

## 2. Символьна діагностика Райтера — `MINIMAL-CONFLICT-DIAGNOSES`

**Першоджерело:** Raymond Reiter, *A theory of diagnosis from first principles*, Artificial Intelligence 32(1), 57–95 (1987), [DOI:10.1016/0004-3702(87)90062-2](https://www.sciencedirect.com/science/article/pii/0004370287900622).

**Контракт:** `(finite_components, complete_conflict_family) -> all inclusion-minimal hitting sets`. Якщо жодного конфлікту немає, результат `{∅}` — жоден компонент не потрібно оголошувати несправним. Якщо хоч один конфлікт порожній, результат `∅` — жоден вибір несправних компонентів не перетинає цей порожній конфлікт. Порядок виводу лише детермінована серіалізація, не нова істина.

**Головний тест:** `conflicts={{A,B},{B,C}}` ⇒ `diagnoses={{B},{A,C}}`; виводити лише `{B}` як найкоротший варіант неправильно, бо `{A,C}` теж inclusion-minimal. Виводити `{A,B,C}` неправильно, бо є власні підмножини, що перетинають усі конфлікти.

**Дуже важлива межа:** функція **не обчислює конфлікти з даних сенсорів і не доводить реальної несправності**. Вона отримує *повне сімейство конфліктів*, яке вже виведено логічною моделлю. Це математична частина діагностичного обчислення; неповне сімейство дає неповну підставу для діагнозів.

**Де корисно:** ремонтування радіотракту, ESP32, FPGA, SDR, пошук зіпсованого модуля у Lisp-машині, символьний експертний агент. Це не тотожне D9 `UNIFY` / `PROVE-GOAL` / JTMS або навчанню правил. Близько до абдукції #4965 — тому потрібен окремий Core-vs-library/semantic-equivalence розгляд.
