# #2590 — Фактор нелокального виходу, батьківство RETURN/PROG та бар'єр ширини

Бар'єр тиску на ширину: #2573, #2584

## Резюме

Цей звіт встановлює структурну факторизацію та чесний аналіз батьківства для фактора пост-D4 `non-local-exit` (F2 у загальному графі факторів #2583/#2593).

```text
Статус фактора: BOUNDED-INDEPENDENT (обмежено-незалежний)
Атака видаленням одиниці (remove-one) з D1-D4: ПРОВАЛ (не реконструюється)
Здатність джерела проти компілятивності у CPS: НЕЗАЛЕЖНІ на рівні джерела / прямого обчислювача
Класифікація PROG: COMPOSITE (композиція: зв'язування + послідовність + локальний перехід + делімітер виходу)
Найсильніший чесний батько: NO-PARENT (усі запропоновані кандидати D1-D4 змінюють базову операцію)
Ортогональність до оновлення спільної пам'яті (#2589): ДОВЕДЕНО (4 чіткі стани в сітці 2x2)
Двійкова координата: UNPLACED (резидентів=0, координат=0, коренів=0)
```

## 1. Атака видаленням одиниці (Remove-One Reconstruction)

В межах допущеної семантики D1-D4 (EVAL, APPLY, LAMBDA, COND, локальна хвостова рекурсія):
- Кожен фрейм активації функції повертає керування виключно своєму безпосередньому викликувачу.
- У вкладеному стеку викликів `PROG(P0) -> middle -> inner`:
  - За умови вилучення `non-local-exit`, `inner` може лише штатно повернутися в `middle`.
  - Продовження викликувача `middle` неминуче виконується, якщо тільки `middle` не змінити для прокидання сигналів чи явних продовжень.
  - За наявності `non-local-exit`, оператор `(RETURN val)` розгортає фрейми напряму до межі `P0`, повністю оминаючи продовження `middle` без модифікації самого `middle`.
- Висновок: `non-local-exit` неможливо відтворити з допущеного локального керування D1-D4. Статус фактора: `BOUNDED-INDEPENDENT`.

## 2. Здатність на рівні джерела проти глобальної компілятивності CPS

Хоча глобальна CPS-трансформація (Continuation Passing Style) здатна перетворити нелокальні виходи на звичайні виклики продовжень, це вимагає глобального переписування програми:
- Кожна функція в системі має змінити сигнатуру зі звичайного повернення (`T`) на явне передавання продовження (`(T -> !) -> !`).
- На рівні семантики обчислювача мови джерела та машини виконання, здатність розгортати динамічні фрейми без глобальної зміни сигнатур є незнищенною примітивною здатністю.

## 3. Класифікація PROG як COMPOSITE (композиція)

Історичний конструктор `PROG` у Lisp розкладається на чотири ортогональні складові:
1. **Локальне зв'язування**: виділення локального лексичного/динамічного фрейму (еквівалент `LET`/`LAMBDA`);
2. **Послідовне виконання**: впорядковане обчислення виразів (еквівалент `PROGN`);
3. **Внутрішньофреймові переходи**: перехід на мітку в межах того самого фрейму (еквівалент `GO`);
4. **Динамічний делімітер виходу**: встановлення динамічної межі для перехоплення розгортання `RETURN`.

Оскільки `PROG` є композицією цих незалежних можливостей, він НЕ повинен примусово отримувати слот неподільного атомарного резидента в двійковій мапі. Його класифікація — `COMPOSITE`.

## 4. Чесний аналіз батьківства для RETURN

Закон розміщення #2236 вимагає, щоб кандидат у батьки поділяв **ту саму базову семантичну операцію**, відрізняючись лише за спостережуваними осями керування:
- **APPLY**: базова операція — застосування викликуваного об'єкта (`callable + args + env -> result`), ефект на стек — створення фрейму. Невідповідність бази.
- **EVAL**: базова операція — обчислення форми (`form + env -> result`), локальне обчислення. Невідповідність бази.
- **LAMBDA**: базова операція — побудова замикання (`params + body + env -> closure`). Невідповідність бази.
- **COND**: базова операція — локальний вибір гілки в поточному фреймі. Невідповідність бази.
- **GO**: базова операція — локальний стрибок вказівника інструкцій у поточному фреймі без повернення значення. Невідповідність бази.

Усі запропоновані кандидати змінюють саму базову семантичну операцію. Тому найсильнішим чесним висновком для `RETURN` серед D1-D4 є **`NO-PARENT`** (або `UNKNOWN` у ширшому просторі пошуку).

## 5. Контроль взаємної ортогональності (#2589 проти #2590)

Тестування фактора оновлення пам'яті (`shared-location-update`, F1) проти фактора нелокального виходу (`non-local-exit`, F2) у просторі 2x2:
- **Жоден**: звичайне локальне повернення, стан пам'яті залишається `OLD`.
- **Лише мутація**: пам'ять змінюється `OLD -> NEW`, керування повертається штатно через проміжні фрейми.
- **Лише вихід**: пам'ять залишається `OLD`, керування виходить нелокально з розгортанням проміжних фреймів.
- **Обидва**: пам'ять змінюється `OLD -> NEW`, після чого відбувається нелокальний вихід.

Усі 4 стани дають чітко розрізнювані сигнатури спостереження. Жоден фактор не зводиться до іншого і не випливає з нього. Вони є строго ортогональними.

## 6. Наслідки для ширини та не-висновки

- **Двійковий об'єкт (Binary Object)**: `UNPLACED` (не розміщений)
- **Доведених незалежних коренів**: 0
- **Нових резидентів D5**: 0
- **Виділених координат**: 0
- **Висновків щодо ширини (Width Inference)**: NONE
- Незалежність фактора НЕ дає права на виділення двійкової координати або суфікса бітів.
- Статус UNKNOWN / NO-PARENT не є залишковим сміттям і не дозволяє довільну мутацію мапи.
- Продакшн-семантика та двійкові мапи залишаються недоторканими.
