# D10 — циклічна напіввідкрита дуга з історичного Forth

**Статус:** research / **не selected, не ratified**, координати відсутні. Жодного втручання в D2-керування, D1–D9, T5, драйвер чи генератор інструкцій.

## Донор Forth 2012 CORE EXT

Першоджерело — [Forth 2012, §6.2.2440 WITHIN](https://forth-standard.org/standard/core/WITHIN). Стандарт описує напіввідкриту ділянку з верхньою межею *виключно*, в тому числі випадок переходу через межу представлення. Рівні межі дають FALSE. Реальна реалізація донора:

- [ncw/ccforth, core.fth:438](https://github.com/ncw/ccforth/blob/92b242f43cac97a4c527dd817706c500c52ed7a6/pkg/forth/core.fth#L438): `WITHIN` через різницю і порівняння беззнакових значень
- [Forth 2012 suite, core_ext.fth:256–263](https://github.com/ncw/ccforth/blob/92b242f43cac97a4c527dd817706c500c52ed7a6/testdata/end-to-end/forth2012/core_ext.fth#L256-L263): тести, включно з порожнім інтервалом
- `tests/oracles/d10-forth-within.fs`: **справжній Gforth** для 15 конкретних native-cell випадків.

**Межа еквівалентності:** у Forth `WITHIN` працює на ширині комірки реалізації; запропонована SENS-функція додає **явний** математичний модуль довільної точності. Ні Forth, ні AS5600 автоматично не доводять точність SENS. Дві спостережувані семантики зіставляються лише там, де їхні умови збігаються.

## Запропонований закон

`CIRCULAR-HALF-OPEN-CONTAINS(test,start,end,modulus)` повертає один біт, якщо всі аргументи — точні цілі, `modulus >= 2` і `test,start,end` уже канонічні (у `[0, modulus)`).

- `start < end`: істина для `start <= test < end`.
- `start > end`: істина для `test >= start OR test < end` (перетинає кінець циклу).
- `start == end`: завжди 0 (порожній напіввідкритий інтервал, **не ціле кільце**).
- Неправильний модуль, від'ємна/надмірна остача, нецілий тип: **явна помилка**, не приховане округлення або маскування.

Приклади на кільці з модулем 256:

| `test,start,end` | Результат | Закон |
|---|---|---|
| `250,240,16` | 1 | Частина дуги перед переповненням |
| `10,240,16` | 1 | Частина після переповнення |
| `16,240,16` | 0 | Верхня межа виключена |
| `100,240,16` | 0 | Розрив між частинами дуги |
| `7,7,7` | 0 | Рівні межі — порожня дуга |

## Звідки взялася потреба

У власному `juv4uk/esp32-pendulum` [`unwrap.c`](https://github.com/juv4uk/esp32-pendulum/blob/72d6b73d762cf389bad0d663e3d135534f5cbb1e/components/physics/unwrap.c#L3-L10) описано стару проблему переходу AS5600 через `0/4095` і необхідність симетрично врахувати обидва напрями. **Цей файл — TODO без готового алгоритму; наша дуга не є алгоритмом розгортання кута і не виправляє цей баг сама по собі.**

Та сама абстрактна *належність до циклічного сектора* застосовна до астрономічних кутів, радіофаз, музичних висот за октавою, тактових фаз і кільцевих буферів FPGA. Вона лишається чистим математичним предикатом, без I/O чи обладнання.

## Незалежний доказ

`tests/test_d10_forth_circular_arc.py` містить три незалежні погляди: умовні порівняння, явний перебір дуги в кільці та формулу за модульною відстанню. Заплановано **105 624** повних випадки (`modulus=2..25`) плюс межі 256/4096, інваріант щодо спільного обертання та негативні тести.

`tests/oracles/d10-forth-within.fs` перевіряє **15** базових Forth native-cell випадків на реальному Gforth. Стан CI видно на PR; не заявляємо PASS до виконання.

## Чому це не автоматичний D10 selected

Ратифіковані операції `DIVMOD`, порівняння та наявний `MODULO` можуть виразити цей предикат як похідну програму. Нова поведінка має бути перевірена на незалежність і власник вирішує Core або Core-Math/library. Також потрібно явно відокремити математичний модуль від physical cell-width. **HOLD** до такого рішення; не займати координату, не робити примусову ратифікацію.
