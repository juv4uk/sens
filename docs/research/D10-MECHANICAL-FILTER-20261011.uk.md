# D10 — механічний фільтр усіх історичних кандидатів (операційний контракт)

**Дата:** 2026-10-11. **Статус:** завдання виконання, **не** ратифікація. **Місце:** `juv4uk/sens/main` без нових Git-гілок, нових дослідницьких ланок чи паралельних writer-ів. Батьківський issue: [#4013](https://github.com/juv4uk/sens/issues/4013).

## Канонічні входи

1. **Один консолідований `all-candidates.tsv`** із реєстру `knowledge/d10-proposal-ledger.tsv`, поточного інвентарю через `knowledge/d10-current-inventory.json` (з перевіркою SHA поточного `canonical_current`), історичних intake, усіх `knowledge/d10-*.json`, `docs/research/historical-branch-intake-20261011.tsv`, результатів попередніх PR/гілок, збережених свідків. Ітеративно розширювати перелік до обліку *всіх* гілок/PR від початку проєкту, не лише тих, де в назві є «D10»; перевірені джерела й непрочитані джерела рахувати окремо.
2. На кожному запуску зафіксувати **точні SHA** канонічного інвентарю, `knowledge/d1-d9-foundation.json`, донорських файлів та HEAD; не змішувати історичні знімки зі станом HEAD. Порожня координата історичного кандидата не є конфліктом.
3. Стабільна ідентичність рядка: `candidate_id` + `semantic_name` + **нормалізований закон, типи входу/виходу, крайові випадки, ефекти та негативний приклад**, а не одне ім'я. Повтор джерела — додаткова provenance-позиція цього самого кандидата, а не новий резидент.

## Обов'язкові поля TSV

`candidate_id, semantic_name, semantic_law, donor_provenance, source_pin, witness_command, witness_artifact, witness_sha, witness_exit_status, witness_verdict, semantic_dedup_certificate, duplicate_target, coordinate, ratification_state, decision, reason` (tab-separated; поле допускає пустоту **лише** до проходження відповідного gate).

## Порядок фільтра — fail closed

| Gate | Перевірка | Невиконання |
|---|---|---|
| **Ф1** | `donor_provenance` містить реально доступний commit/blob+шлях+рядок, URL+розділ або сторінку; pin верифікований | `rejected.tsv`: `EXCLUDE_NO_PROVENANCE` або `HOLD_UNVERIFIED_PIN` |
| **Ф2** | Позитивний **і** негативний свідок виконувані; незалежний оракул/цільова реалізація реально запущені на зафіксованих версіях і повернули PASS; artifact+exit status+SHA відтворювані | `rejected.tsv`: `EXCLUDE_NO_WITNESS`, `HOLD_NOT_RUN` або `REJECT_FAILED_WITNESS` |
| **Ф3** | Семантичний дедуп за законами/типами/ефектами/контрприкладами щодо ратифікованих D1–D9 та *всього* поточного відібраного D10; документований сертифікат порівняння | доведений дубль → `EXCLUDE_DUP` + `duplicate_target`; дедуп не доведено → `HOLD_DEDUP_UNPROVEN` |
| **Ф4** | Немає суперечності з ратифікованими D1–D9, поточними відібраними D10 законами або з уже зайнятою **канонічною** координатою | `escalated.tsv`: `ESCALATE_OWNER` + обидва закони/координати/докази |

**Нюанс:** `witness exists` ≠ `witness PASS`; `NO-MATCH` з попереднього текстового ledger ≠ математично доведена нетотожність. Невідомі результати не проходять у `accepted-queue.tsv`. Недоведена семантична нетотожність — **HOLD**, не автоматичне підтвердження й не привід заблокувати всі наступні джерела.

## Три виходи (детерміновані, відсортовані)

- `accepted-queue.tsv`: лише записи з PASS Ф1–Ф4, доказовими посиланнями, станом `RESEARCH-ACCEPTABLE-OWNER-BULK-REVIEW`. Не видавати це за вже selected/ratified.
- `rejected.tsv`: відкинуті **на поточному проході**, з `reason`, вихідним provenance, `duplicate_target` для дублів; `HOLD_*` можна перевірити й повернути в наступний запуск без втрати історії.
- `escalated.tsv`: **тільки справжні нормативні конфлікти** Ф4 з чітким порівнянням. Невідомі чи не запущені докази тут не ховати.

Сума `accepted + rejected + escalated` дорівнює кількості унікальних `candidate_id` на вході; жоден рядок не губиться і не дублюється. Зберігати також окрему звірку source inventory: `scanned/total/unreadable/unique/merged`. У кожному виході мають бути `source_pin` і snapshot HEAD.

## Дія рою (single-writer)

1. Інвентаризувати всі історичні джерела, включно зі старими Lisp/1–1.5, MacLisp, Interlisp, PSL, Lisp Machine, PAIP, Scheme, CLOS/CLHS та накопиченими PR; звірити назви, закони і повтори. **Не відкривати нових гілок.**
2. Реалізувати детермінований CLI фільтр та unit-тести, включно з негативними тестами: відсутній pin, не запущений тест, test failure, текстовий дубль з іншим законом, семантичний дубль з іншою назвою, колізія координат, порожня координата, неповна гілкова інвентаризація.
3. Запустити збережені оракули; за відсутності runtime писати `HOLD_NOT_RUN`, не `PASS`. Повторно запускати після зміни доказів.
4. Атомарно додати в **main** код, тести, `all-candidates.tsv` та три виходи зі SHA; у звіті надати точні числа, коміт і стан CI. Не змінювати чинні D1–D9, SENS/T5/codec чи канонічні D10-координати на етапі фільтра.
5. Одна **bulk-перевірка власника** над `accepted-queue.tsv` (вилучення спірних рядків). Після неї окремими доказовими переходами робити `selected`, розміщення у вільні 10-бітні координати і **окремо** ратифікацію. Жодний bulk-«так» не дає автоматичної фізичної інструкції або ратифікації.

**Критерій закриття:** реально сформовані й протестовані три TSV, інвентар усіх джерел, нуль загублених рядків, пройдені перевірки, визначені точні accepted/rejected/escalated counts, git SHA на `main`; без цих артефактів говорити «D10 заповнено» заборонено.
