# D10 — навчання правил через простір версій (дослідження)

**Джерело:** Tom M. Mitchell, *Version Spaces: A Candidate Elimination Approach to Rule Learning*, IJCAI 1977, с. 305–310. [Зміст історичної конференції](https://www.ijcai.org/proceedings/1977-1) та [оригінальна праця](https://www.ijcai.org/Proceedings/77-1/Papers/048.pdf).

На відміну від `UNIFY` (зробити два терми сумісними підстановкою) чи anti-unification (одне спільне узагальнення), простір версій описує **усі** гіпотези, що досі не спростовані **позитивними й негативними** спостереженнями.

Точний *обмежений* контракт: для скінченних переліків значень кожної ознаки, позитивних і негативних прикладів, і гіпотез як кон'юнкцій конкретних значень або `*` повернути простір усіх сумісних гіпотез та дві антиланцюгові межі. Спеціальна гіпотеза `BOTTOM` не покриває жодної комбінації. `S` — найконкретніші елементи, `G` — найзагальніші. Будь-яка гіпотеза простору лежить між відповідною парою `s ∈ S`, `g ∈ G` за включенням множин покриття.

## Чому це нам цікаво

Це чисті символічні дані: гіпотези щодо астрономічних умов спостереження, класифікації радіосигналів, несправностей електроніки чи морфологічних ознак санскриту. Ніяких драйверів, GPU-специфічних викликів або нових способів керування кодом.

**Безпека значень:** порожня множина гіпотез — не доведена хибність твердження; одночасно протилежні мітки для того самого спостереження мають окремий результат `CONTRADICTORY-OBSERVATIONS`. Гіпотеза `BOTTOM` відрізняється від пустого списку/даних D3 і D1:NO.

## Фальсифікатори

1. 81 можливий набір позитивних/негативних/невідомих міток для чотирьох спостережень: повний перебір гіпотез має дорівнювати відновленню з `S/G`.
2. Перестановка прикладів не змінює результат.
3. Негативний приклад дає **кілька непорівнюваних** найбільш загальних гіпотез.
4. Позитивна діагональ із негативним протиріччям кон'юнкційному представленню дає `NO-CONSISTENT-CONJUNCTION`, а не вигадану закономірність.
5. Неприпустима категорія, дубль значення, не-D1 bool, некоректний кортеж — відмова.

Модель Python потрібна лише як незалежний контроль гіпотез. Це НЕ реалізація або прийнята бітова ідентичність у мові. Актуальна координата: `null`, ратифікація: `false`, selected inventory не змінюється. Перевірка семантичної похідності від D1–D9/D10 та Core-vs-library — обов'язкова перед відбором.
