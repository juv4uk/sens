# Міграція SENS: датована семантична хронологія та межі доказу

**Зріз:** 14.10.2026. **Статус:** дослідницька provenance-карта для рою; **не** ратифікація, не другий контракт, не CI-gate. Джерела: [CURRENT.md](../../CURRENT.md), [мовний Contract 11.9](../../language-contract.lisp), [карта семантичної влади](../semantic-authority-map.md), [рішення власника щодо виконавців](../../AGENTS.md). У разі розбіжностей чинне ратифіковане джерело переважає цю нотатку та історичні документи.

## Закон читання історії

Розрізняти чотири окремі події:

1. **Власницька ратифікація** — затверджує домен/резидента/закон у визначеному обсязі.
2. **Зміна чинного контракту** — фіксує семантичну норму, але не робить кожний резидент виконуваним.
3. **Технічна реалізація/транспорт** — може підтвердити точні біти та координати, але не ратифікує значення.
4. **Тест, звіт, benchmark чи архів** — дає спостереження/provenance, а не нормативну владу.

Канонічна ідентичність: **точні біти + точний домен + допущений/доведений закон**. Однаковий payload, стара назва, позиція в таблиці чи фізичний байт не встановлюють тотожності, callable-допуску або математичного числа. Чинна семантична влада — у SENS, а не в Rust, Zig, Python чи цьому документі.

## Міграційні межі, які можна перевіряти локально

- **Чинна ідентичність:** source-span → ратифікований домен → точні n бітів → підтверджений закон/допуск. Порівнювати payload **разом** із доменом і шириною. Не створювати посередника через десяткове число чи старий восьмибітний реєстр.
- **Цитата/символ:** спершу встановити, чи об'єкт уже має канонічний код у затвердженій драбині; D7 застосовувати лише до власне текстових даних, а не дублювати D3/функції.
- **Математика:** тільки явно кваліфіковані D24+ та затверджені композиції; D1–D10 не стають числами від того, що містять біти 0/1.
- **D11:** тестовий словник — окремий від Core і T5-admission; не переносити D11 у Zig execution path за самим фактом словникової ратифікації.
- **Транспорт Zig:** звичайний T5-профіль D1–D9, окремий механічний координатний профіль D1–D10; успішні canonical bytes ≠ нативний semantic PASS. D11 до T5 не допускати без окремого чинного рішення.
- **Доказ на одному stem:** пін exact source/commit SHA, доменну бітність, фізичний .sens SHA-256 та очікуваний розмір; порівнювати Rust↔Zig на **одному** corpus snapshot, а поведінку — окремим нативним позитивним і негативним SENS-свідком. FNV-64 можна вживати як швидкий не-криптографічний індикатор, **не** замість SHA-256.
- **Пошук першої регресії:** з'ясувати дату рішення/перший SHA і конкретну зміну закону; міграцію робити малими незалежними write-set через [#5029](https://github.com/juv4uk/sens/issues/5029), без самовільного merge або нової гілки. Невідоме = названий локальний стан без глобальної зупинки рою.

## Локальна «можливість розв'язати цікаву задачу»: foundation index provenance

**Спостережуваний факт, без нормативного виправлення.** Поточний [knowledge/d1-d11-foundation.json](../../knowledge/d1-d11-foundation.json), blob `ab8dece771527c76e66a34f70e6f066e8be194c5`, має `schema=d1-d9-foundation-ratification/v1` і `current_domains = [D1,D2,D3,D4,D5,D6,D7,D8,D9,D11,D11]`. Отже у списку **D11 повторений, D10 пропущений**; водночас об'єкт `domains` містить **і D10, і D11**. Цей стан з'явився у [commit 0b4fceac](https://github.com/juv4uk/sens/commit/0b4fceac9074ab683571bebf0fc8f577cfd51b30), який додавав тестовий D11.

**Наступна перевірка для окремого виконавця:** визначити, які читачі використовують `current_domains`, які — `domains`, які — чинний Contract 11.9, і чи є поведінкова регресія. Задокументувати позитивний/негативний свідок та точний SHA. **Не** трактувати аномальний список як скасування ратифікації D10; **не** переписувати нормативну таблицю або тести здогадом, не запроваджувати загальний HOLD.

Так само [docs/language-core-axioms.md](../language-core-axioms.md) сам називає свій історичний текст *draft, not yet ratified* (2026-08-09). Його ідеї корисні для дослідження, але при суперечності переважає чинна конституція SENS. Аксіоми пояснюють напрям; лише актуальний нормативний акт визначає чинне значення.
