# #2236 — закон розміщення після D4

Статус: лише дослідження.

Після історичного reset питання розміщення змінюється з:

```text
яке вільне D5-слово віддати наступній можливості?
```

на:

```text
яка історична можливість усе ще не виводиться з D1-D4,
і чи є вона рівно одним новим двійковим уточненням вже існуючого батька?
```

## Закон

Дочірній код ширини `N+1` допускається лише тоді, коли:

```text
той самий базовий семантичний об'єкт/операція
+ рівно одна нова спостережувана відмінність
= дитина
```

Тобто код має пояснювати себе як локальний шлях побудови, а не як номер рядка у плоскій таблиці.

Порядок перевірки:

1. уже представлено в D1-D4;
2. виводиться засобами самої мови;
3. локальна породжена дитина;
4. residue без чесного батька;
5. більша ширина, якщо потрібні дві чи більше незалежні нові відмінності.

Порожня адреса — нормальний і бажаний результат.

## Вектор спостережуваних відмінностей

Перед тим як дитина може використати ще один біт, треба явно назвати незалежні
спостережувані зміни між батьком і дитиною.

Для однобітної дитини:

```text
той самий базовий об'єкт = так
незалежних delta-осей = рівно 1
```

Це не глобальна метрика семантичної відстані. Це локальний фальсифікатор після
того, як кандидат на батьківство вже запропонований.

Поточне порівняння LABEL:

```text
LAMBDA -> LABEL
  базовий об'єкт: closure/callable
  delta-вісь: local-self-binding
  кількість: 1

DEFINE -> LABEL
  базовий об'єкт: persistent binding operation -> closure value
  delta-осі:
    base-object-kind
    binding-lifetime
    local-self-reference
  кількість: >1
```

Тому DEFINE-контррозміщення зараз не проходить як чесна однобітна породжена
дитина.

## Орієнтація біта

Слабку ратифіковану полярність D4 можна повторно використовувати лише там, де її підтверджує виконувана семантика:

```text
0 = поточне / фокус / вже розв'язане
1 = продовження / розширення контексту
```

Це не глобальна теорема D5.

Для селекторів діє сильніший окремий закон:

```text
0 = додати CAR
1 = додати CDR
```

## Перший споживач розв'язаний — LABEL

#2234 / #2238 розв'язали першого історичного кандидата:

```text
LABEL=DERIVED-D4
address=none
```

Поточна історична гілка LABEL у Core1 не ставить self-binding, але D4 LAMBDA
виводить локальну рекурсію через аплікативну нерухому точку. Сильніший witness
повертає escaping recursive closure, зберігає lexical capture і працює з
перейменованим self-змінним без LABEL та DEFINE.

Тому:

```text
0010  LAMBDA
00101 <unallocated>
```

Стара форма `00101 LABEL` лишається тільки контрфактичним тестом закону
розміщення, а не активним кандидатом.

## Гіпотеза LABEL

Історична форма:

```text
LABEL(name, lambda)
= LAMBDA-подібний callable
+ локальний рекурсивний self-binding
```

Якщо #2234 доведе, що такий self-binding є окремою невивідною здатністю, найсильніший поточний кандидат:

```text
0010   LAMBDA
00101  LABEL      ; лише кандидат
```

Чому suffix 1 виглядає природно:

- базовий об'єкт лишається closure/callable;
- нова відмінність одна — додати self-binding;
- self-binding розширює контекст обчислення closure;
- це узгоджується зі слабким значенням 1 як розширення контексту.

Це не ратифікація.

Скрипт спеціально зберігає протилежний результат:

```text
якщо LABEL виводиться з D4:
  LABEL -> без адреси
  00101 -> лишається порожнім
```

## Контррозміщення

LABEL під DEFINE зараз слабший варіант:

```text
0011 DEFINE
  ? -> LABEL
```

DEFINE розширює persistent/global середовище. Історичний LABEL локалізує self-reference біля функціонального виразу. Поки виконуваний witness не доведе, що це той самий базовий семантичний об'єкт плюс одна відмінність, таке батьківство не допускається.

Так само:

```text
0101 LABEL
1001 LABEL
```

було б лише використанням вільної місткості D4 без семантичної лінії спорідненості.

## Одне дочірнє слово не може нести дві незалежні осі

Точна пара parent/suffix є одним шляхом побудови. Тому дві незалежні
семантичні спеціалізації не можуть непомітно претендувати на те саме слово.

Для історичного reset це одразу важливо:

```text
0010  LAMBDA

кандидат A:
00101 LABEL
delta-вісь = local-self-binding

старий кандидат B:
00101 TRANSFORMER
delta-вісь = raw-staged-invocation
```

Якщо обидві відмінності виживуть як незалежні спостережувані можливості, D5
занадто вузький, щоб закодувати обидві під одним ребром LAMBDA+1.

Тоді чесні результати лише такі:

```text
вивести одну можливість
знайти іншого чесного батька для однієї можливості
перенести одну/обидві спеціалізації на більшу ширину
```

Не дозволено:

```text
одне точне слово = дві незалежні семантичні спеціалізації
```

Отже історичний порядок має реальну силу: LABEL перевіряється першим тому, що
він раніше з'явився в розвитку Lisp, а не через естетику адреси.

## Історичний порядок

Поки що нерозв'язані:

```text
LABEL
FUNCTION/FUNARG
EVALQUOTE
APPEND
PAIR/PAIRLIS
ASSOC
SUBST/SUBLIS
MAPLIST
SET/SETQ
PROG/GO/RETURN
```

Для кожного спершу шукається найсильніший природний батько:

```text
FUNCTION/FUNARG -> LAMBDA
EVALQUOTE       -> EVAL/APPLY
PAIR/PAIRLIS    -> BIND/структура
ASSOC           -> LOOKUP
SET/SETQ        -> DEFINE/BIND, але mutation треба довести як одну відмінність
```

Очікується, що більшість історичних назв зникне як derived або historical-mechanism-only. Це лише очікування, не доказ.
