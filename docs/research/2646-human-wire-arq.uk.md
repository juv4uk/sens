# 2646 — ARQ для людського каналу: блоки, CRC і вибіркова повторна передача

Статус: дослідження, лише механізм (доменний firewall #2508; парасолька #2642). Кадрування — це транспорт, а не семантична ідентичність.

English: [2646-human-wire-arq.md](2646-human-wire-arq.md).

## Варіанти
- A: len16 | payload | crc16 (ціле повідомлення).
- B: блоки фіксованого розміру `idx8, last1, len9, payload, crc16`.
- C: SYNC `11010011` + B, ресинхронізація скануванням.
- D: C з Хеммінгом(7,4) на тілі блока.

## Результати (benchmarks/human-wire-arq)
- Корисне навантаження 272 біти, очікувана вартість при одному фліпі: A 608, B(k=128) 527, C(k=128) 552, D(k=272) 555 біт.
- Один фліп завжди відновлюється (вичерпна перевірка). D: 90–98% без повтору для фліпів у тілі; фліп у незахищеному SYNC все одно коштує блок.
- Вставки/видалення (k=32): B каскадує (у середньому 5,09 з 9 блоків втрачено, макс. 9); C і D ресинхронізуються й втрачають рівно один блок.
- Монте-Карло: 0/20000 хибних повідомлень прийнято в кожному варіанті (межа ~ пошкоджені_одиниці · 2^-16).
- Масштаб відносно A (найкраще k): n=2048 B 0,636, C 0,645, D 1,0; n=8192 B 0,590, C 0,598, D 1,01.

## Чесні застереження
- На 272 бітах заголовок (26 біт/блок + CRC16) з'їдає виграш; кадрування окупається зі зростанням повідомлення.
- Хемінг (D) не окупається за вартістю (goodput ~0,44–0,49), але дає нуль повторів для одиночного фліпу.
- Сітка масштабу обмежена k≤256, тому best_k=256 лежить на краю сітки.
- Політика повтору: отримувач повідомляє, які індекси має; пересилаються лише прогалини й невидимий хвіст; конфлікти — повна пересилка.

Рекомендація для #2644: C (sync + блоки + CRC) за замовчуванням; D лише коли домінує затримка повтору.
