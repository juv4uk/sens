# D8: перевірка комутативного квадрата — #3618

Цей research-крок перевіряє, чи **поточні** семантичні докази D6 вже
містять достатньо структури для не-selector двобітної D8 product-family.

Для квадрата D8 потрібні дві незалежно спостережувані бінарні осі:

```text
        B=0      B=1
A=0      00       01
A=1      10       11
```

Квадрат приймається лише тоді, коли обидві осі мають окремий зміст і
порядок їх застосування не змінює результат.

## Поточний вхід

`knowledge/d6-v2-binary-law-families.json` містить 16 виконуваних
двочленних сімейств D6, разом 32 чинні резиденти.

У кожному сімействі зараз зафіксовано:
- рівно два семантичні члени;
- рівно один доведений бінарний зв'язок;
- evidence для цього зв'язку.

Цього вистачає для **однієї семантичної осі**, але не для квадрата D8,
який вимагає дві незалежні осі.

Машинна перевірка дає:

```text
перевірено D6-сімейств                 16
перевірено D6-резидентів               32
сімейств з однією доведеною віссю      16
готових до D8 product-square             0
```

Це не доказ неможливості другої осі. Це точний висновок про наявний
machine-readable corpus: другої осі в ньому ще немає, тому її не можна
домалювати з симетрії координат.

## Контролі

Позитивний контроль повторює форму #2506: дві незалежні policy-осі
комутують.

Негативний контроль навмисно використовує залежні від порядку
перетворення; такий квадрат відхиляється.

64 D8 selector-кандидати з #3615 використовуються лише як collision-control.
Старий D8 donor не є входом.

## Відтворення

```sh
python3 benchmarks/d8-commuting-square-screen/run.py \
  --out /tmp/d8-commuting-square-screen
```

Сімейство може перейти з `INSUFFICIENT-CURRENT-EVIDENCE` у
`PRODUCT-CANDIDATE` лише після появи другої незалежної семантичної осі
та executable commutativity witness.

Жоден D8 resident цим дослідом не ратифікується.
