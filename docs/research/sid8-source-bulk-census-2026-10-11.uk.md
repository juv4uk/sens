Це не нуль роботи: попередній механічний прохід помилково нарахував **1185** нібито придатних замін у п'яти файлах. Із них **1176** — згенерований запис ISA `lib/machine/encoding/admitted-iclass-index.lisp`, де `00101110` слугує ключем рядка, а не виконуваним викликом. Решта містили machine metadata, ратифіковану сучасну D8-кодову поверхню або сумісний host seam. Їхня механічна заміна була б некоректною. Другий прогін після provenance-guard підтвердив 0 таких false admissions.

## Незняті блокери

- **Складена ідентичність DEFMACRO** `00001010`: D5 `00011 MACRO` та D4 `0011 DEFINE` не дають універсальної однослівної заміни. Це утримує великий корпус `lib/core.lisp`, `lib/core4.lisp`, `lib/forward.lisp`, `lib/knowledge.lisp`, `lib/world.lisp` та `racket/boot/core.lisp`.
- **Стара тричленна COND / host truth**: `knowledge/guard-fact-policy.lisp`, `knowledge/guard-reference.lisp`, `scripts/enforce-function-table-mechanisms.lisp`, `scripts/enforce-island-math-evidence.lisp`, `scripts/semantic-authority-guard-enforce.lisp`. Не можна скоротити `00000111` до D3 `110` без формального закону перетворення полярності відповіді та двочленної форми.
- **Внутрішні нерезидентні коди** у `lib/core.lisp`, `lib/core4.lisp`, `scripts/generate-functions-md.lisp`. Відсутня точна ратифікована наступна ідентичність.
- **Нератифіковані D10-кандидати**: `lib/time.lisp` та `scripts/benchmark-semantic-registry-read.lisp`.
- **Змішана епоха / семантичний D8**, коли ратифікований сучасний 8-бітний код виглядає як невикористана клітинка старого SID8: скрипти й бібліотеки можуть зберігати такі значення. Таблиця SID8 не дає права перемапувати їх за бітами.

## Точна подальша стратегія

1. Спочатку довести macro-definition lowering D5+D4 і виконання в oracle/Rust; потім перевірити великі вихідні файли, не оголошуючи автоматично всю партію семантично еквівалентною.
2. Окремим незалежним свідком довести стару поляризовану COND проти нового D3 `110`; перетворювати AST/гілки, а не лише перший токен.
3. Здійснювати source-era attribution до аналізу 8-бітних слів. Згенеровані свідчення й сучасний D8 залишати без змін.
4. Для кожної перенесеної партії: Git blob SHA, source diff, незалежний runtime oracle, regression CI, атомарний запис у `main`. Жодної нової гілки чи фізичної .sens підміни.

**Інструмент:** `scripts/migrate-sid8-source-batch.py` (readonly за замовчуванням, `--write` лише за пройденими воротами), тести `tests/test_migrate_sid8_source_batch.py`, CI `.github/workflows/sid8-source-bulk-census.yml`. Це інвентаризація відповідності коду, **не** сертифікація фізичного codec та не завершена міграція.
