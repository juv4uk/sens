## Об'єкт дослідження: які саме докази існують

| Рівень | У канонічному v18 | Що це доводить / чого НЕ доводить |
|---|---:|---|
| Whole-domain owner ratification | **1024/1024** | Власник ратифікував усю 10-бітну кодову книгу, не індивідуальне F2/F3 виконання |
| Унікальні 10-бітні координати | **1024/1024** | Усі адреси розміщено без колізії; не є доказом поведінки |
| Конструктивно обґрунтовані selector coordinates | **256** | `C[AD]{8}R`: композиції CAR/CDR, адреси 256 листків, відмінність **усередині сімейства** |
| Інші координати (owner-directed gauge) | **768** | Успішне розміщення, **не** 768 незалежних F2 PASS |
| Записи з ненульовим `provenance` | **720** | Є посилання на джерела/історію; це не рівно 720 виконаних донорних тестів |
| Записи з `source_git_blob` | **349** | Присутня SHA-прив'язка джерельного об'єкта; сама SHA не запускає оракул |
| Рядки з одночасно позитивними та негативними **описами/полями** | **376** | Є матеріал для тестування; частина лише illustrative/text claims |
| `witness_independence` = PENDING або NOT-PROVEN | **349** | Явна невизначеність, не PASS |
| `independent_oracle` наявне, але не має підтверджувального PASS | **326** | Усі 326 містять NOT-EXECUTED / PENDING / NOT-YET-PROVED або посилання на донорський, **не SENS**, запуск |
| Явні позитивні `F2 PASS` / `independent_oracle=VERIFIED` у v18 | **0** | **Немає канонічної поелементної F2 атестації**; це не заперечує окремих зовнішніх математичних тестів |

**Межа формулювання:** число «≈800 доведених до виконання функцій» **не підтверджується** цим джерелом. Можливе походження оцінки — **768** заповнених неселекторних координат, **720** записів provenance або велика кількість незалежних *випадків тестування* кількох алгоритмів. Це різні одиниці вимірювання.

Джерела: [скрипт](../../scripts/check_d10_selector_semantics_20261012.py), [пояснення](D10-SELECTOR-SEMANTICS-PROOF-20261012.uk.md), [workflow](../../.github/workflows/d10-selector-semantics-20261012.yml).

Це **конструктивний доказ визначеної моделі**, не native SENS evaluator чи глобальне F3 порівняння з усіма D1–D10.

## Окремі реальні виконувані свідки: не змішувати зі 1024 resident F2

- [FINITE-CNF-UNIT-FIXPOINT](D10-DLL1962-UNIT-CLOSURE.uk.md): описано **2304** математичні випадки та **600/600** успішних випадків зовнішнього PySAT/Glucose3; поточний v18 **містить** ім'я на коді `1010110000`, проте зовнішній SAT-оракул **не** є SENS/T5 parity для цього координатного резидента.
- [STERN-BROCOT-RUN-PATH](d10-stern-brocot-runs.uk.md): зовнішні Python/SBCL свідки тисяч дробів; поточний v18 **містить** ім'я на `1010010100`. Досьє було складене як дослідна пропозиція до whole-domain ратифікації і його старий напис «unselected» не переважає актуальну кодову книгу. Математична правильність не є binary-runtime атестацією.
- [FINITE-C1P-CANONICAL-ORDER](d10-shiva-c1p-canonical-order.uk.md): **2256** незалежних модельних порівнянь, але цього імені **немає** у поточних 1024 rows D10. Не зараховувати ці тести як покриття D10-резидента.
- [FINITE-TRANSDUCER-COMPOSE](../../knowledge/d10-finite-transducer-cross-hobby-v1.json): окремий [GitHub Actions run 38230062572](https://github.com/juv4uk/sens/actions/runs/38230062572) має **SUCCESS**, SHA `aa69b4ac69e99e8122c56476230454fd3fccfad8`; поточний v18 містить код `1110001011`, але індивідуальне поле `independent_oracle` вимагає **NOT-EXECUTED-FOR-SENS**. Це позитивний доказ математичної моделі, не доведений runtime SENS.

Ці чотири приклади показують, чому кількість *тестових випадків*, *донорних реалізацій*, *математичних законів*, *канонічних резидентів* і *виконуваних фізичних інструкцій* треба вести в **п'яти окремих колонках**.

## Що виконати перед числом «N D10 реально виконуються»

1. Для **кожного** з 1024 записів з'єднати exact coordinate/stable_id із SHA-pinned донором, формальним/виконуваним законом, позитивним і негативним witness, незалежним від implementation oracle, поведінковою відмінністю та конкретним SENS evaluator receipt на одному commit SHA.
2. Створити машинний `d10-proof-coverage` ledger з окремими булевими або доказовими статусами **F1, F2 donor, F2 SENS, F3 global, F4 physical T5**; `UNKNOWN` не дорівнює PASS. Існуючі proof bundles не вважати загубленими: прив'язувати їх до stable_id, якщо є підтверджуваний точний збіг.
3. Глобально підрахувати унікальні stable_id з PASS для **кожного окремого рівня**. Заборонено рахувати сотні oracle input cases за сотні D10-функцій.
4. У `RELEASE-EVIDENCE.md` показувати 256 конструктивно доведених селекторів **окремо** від D10 runtime/T5 coverage. Після наступних змін blob перерахувати аудит, не переносити старі лічильники на новий SHA.

**Висновок:** SENS уже має суттєві математичні й донорські докази, які попередня фраза «докази ще не завершено» недостатньо конкретизувала. Але **800 поелементних повних F1–F4 PASS наразі не засвідчено**. Це не оцінка якості мови — це межа наявного машинного evidence ledger.
