# Видалення Sens8/Sid8 → драбина доменів: замір і безпечний шлях

> **Статус: рекомендація, не виконана зміна.** Цей документ **не** видаляє нічого.
> Він фіксує замір і пояснює, чому масове видалення легасі-коду суперечить
> чинним правилам репо, і який безпечний шлях веде до тієї ж мети.

**Ревізія заміру:** `7cbb5303bdfeca1e29d8766f33eda8053c501c87` (main).

## 1. Замір (скільки легасі реально є)

| метрика | значення |
|---|---:|
| файлів, що згадують `sens8`/`sid8`/`function8` | **420** |
| окремих згадок | **882** |
| з них `docs/` + `research/` | 177 |
| `knowledge/` + `contracts/` | 64 |
| `crates/` | 55 |
| `tests/` + `scripts/` + `.github/` | 109 |
| `benchmarks/` + `lib/` + решта | 40+ |

**Ключове:** `Sens8` — це **живий runtime-носій**, а не мертвий код. У
`crates/sens/src/sens.rs` досі `pub struct Sens8(pub(crate) u8)` і макрос
`sens!`; легасі згадується у **27 файлах ядра** `crates/sens/src/`, включно з
`value.rs`, `parser.rs`, `syntax.rs`, `presentation.rs`, `source_words.rs`,
`semantic_registry.rs` та всім `eval/*`. Файл `sid.rs` уже прибрано раніше.

## 2. Чому масове видалення тут заборонене й небезпечне

1. **Зламає збірку.** `Sens8`/`sens!` — поточний механізм парсера/eval. Видалення
   wholesale зруйнує Rust-референс, на якому тримаються всі перевірки.
2. **Прямо суперечить чинній доктрині.** `CURRENT.md` (рядок 62): «Historical
   exact-eight-bit Sens8/Sid8/Function8 forms remain **bounded compatibility,
   transport, backend and provenance mechanisms while #2817 migrates runtime
   consumers.**» Тобто легасі має **залишатися** обмеженим шаром під час
   поступової міграції, а не зникати одним рухом.
3. **Видалення форми — рішення власника per-form**, не масова операція. Драбина
   (D1–D9, `domain_ladder.rs`, `domain_identity.rs`, `domain_words.rs`) уже
   ратифікована — «замінити на драбину» вже відбувається, але керовано.
4. **Зовнішні споживачі.** `Sid8`/`sid!` тримали позначеними `#[deprecated]`
   саме для сумісності із зовнішнім `juv4uk/cml`; сліпе видалення ламає його.
5. **Міграція вже має tooling.** Є `migrate-sid8-source-batch.py`,
   `migration-readiness-census.py` і десяток `audit-sid8-*` workflow — тобто
   перехід роблять **інкрементально й доказово**, а не `rm`.

## 3. Безпечний шлях до тієї ж мети

1. **Класифікувати** кожну згадку за роллю:
   - *провенанс/док* (`docs/`, `research/`, `knowledge/`, `contracts/`) — лишається
     як історія; не чіпати;
   - *deprecated Rust-alias* (`Sens`/`Sid8`) — прибрати **після** переходу `cml`;
   - *тести* — оновити на доменну ідентичність;
   - *live logic* у `crates/sens/src/` — мігрувати на `exact bits + domain`, а не
     видаляти.
2. **Мігрувати конкретний bounded cohort** наявним tooling-ом (як роблять
   `audit-sid8-*`), з доказом і без зміни ратифікованих D1–D9/D2.
3. **Кожну форму видаляти окремо** — за рішенням власника, після незалежного
   свідчення, що жоден споживач (у т.ч. `cml`) не залежить від неї.

## 4. Що потрібно від власника, щоб рухатись

Скажи **конкретний bounded крок**, і я зроблю його атомарно й доказово, напр.:
- «прибрати `pub type Sens = Sens8` alias» (заміна на доменну ідентичність);
- «мігрувати cohort `<тека>` з `audit-sid8-*`»;
- «видалити `Sens8` з модуля `<X>` після переходу споживача».

Масове `rm` усього легасі я не робитиму: воно ламає збірку, доктрину та
зовнішніх споживачів.
