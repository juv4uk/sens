# D8: RASSOC/ACONS × орієнтація асоціації — #3741

Статус: **RESEARCH / UNRATIFIED**.

Мета — перевірити, чи поточна D6-сім'я

```text
RASSOC | ACONS
```

має незалежну другу вісь, що походить не з бітової естетики, а з математично простої транспозиції пари:

```text
tau((k,v)) = (v,k)
tau(A)     = map(tau,A)
```

Поточний D5 `ASSOC` використовується як уже ратифікована нижчодоменна семантика пошуку за ключем.

## Типізований квадрат

```text
                    value-oriented     key-oriented
query               RASSOC             ASSOC
extend              ACONS              ACONS-SWAPPED
```

Тут `ACONS-SWAPPED(k,v,A)` означає орієнтований варіант, який після транспозиції відповідає `ACONS(v,k,tau(A))`.

## Закони

Перевіряємо:

```text
tau(tau(A)) = A

tau(RASSOC(q,A))
  = ASSOC(q,tau(A))

tau(ACONS(k,v,A))
  = ACONS(v,k,tau(A))
```

`NIL`/відсутність збігу на query-шляху має зберігатися точно.

## Скінченний корпус

Атоми:

```text
{0,1,2}
```

Маємо 9 впорядкованих пар. Перебираємо всі alist довжин 0..2 без повторення тієї самої пари всередині списку:

```text
1 + 9 + 9*8 = 82 alist
```

Звідси:

```text
query cases     = 82 * 3 = 246
extension cases = 82 * 9 = 738
```

## Негативний контроль

Довільна інволюція не повинна автоматично ставати D8-віссю. Тому пробуємо `reverse(A)` як другу вісь для extension.

На 729 непорожніх extension-випадках закон комутації має зламатися у 720 випадках. Дев'ять дегенератних рівностей фіксуємо явно, а не приховуємо.

## Координатна калібровка

Поточна влада:

```text
D6 RASSOC = 001100
D6 ACONS  = 001101
D5 ASSOC  = 11100
```

D8-footprint:

```text
00110000
00110001
00110010
00110011
```

`00110000` — дубль RASSOC.  
`00110011` — інваріантний породжений кандидат ACONS-SWAPPED.  
Середні `00110001/00110010` утворюють gauge-orbit із нижчодоменними значеннями ASSOC та ACONS; абсолютний порядок не вигадується.
