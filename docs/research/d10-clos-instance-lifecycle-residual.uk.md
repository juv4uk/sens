# D10: другий історичний зріз CLOS — життєвий цикл об'єктів і методів

**Дата:** 2026-10-09. **Статус:** дослідження, не ратифіковано; **0 нових кодів D10**.

Старі історичні гілки не є канонічним джерелом тільки тому, що не злиті. Після #4841, #4842 і #4843 та перевірки чинних D1–D9/625 D10 selected знайдено 8 інших історичних написань, відсутніх як exact names. Це не підтвердження нової семантики.

## Ключові межі

**REVIEW (2)**:
1. MAKE-INSTANCES-OBSOLETE — переозначення класу та наступне оновлення його наявних примірників; відрізнити від CHANGE-CLASS і зміни окремого слота. Потрібний спостережуваний тест збереження старих слотів при зміні схеми.
2. FUNCTION-KEYWORDS — точна пара «перелік ключів методу» та «чи дозволені інші ключі»; перевірити, чи це не звичайна проєкція метаданих, уже доступних через DEFMETHOD.

**HOLD (6)**:
- UPDATE-INSTANCE-FOR-REDEFINED-CLASS — hook після переозначення класу, можливе D2/state/effect керування.
- METHOD-QUALIFIERS — може бути похідним читанням descriptor.
- NO-APPLICABLE-METHOD / NO-NEXT-METHOD — елементи обробки помилок та керування D2.
- ENSURE-GENERIC-FUNCTION — можливо похідна операція DEFGENERIC.
- REINITIALIZE-INSTANCE — зміна існуючих слотів без зміни layout, можливо похідне з існуючого state protocol.

Кожен кандидат має URL першоджерела, позитивний приклад і falsifier в JSON. Усі координати null; всі записи мають selected=false, ratified=false. Вони **не додаються** до 625 відібраних значень D10.

Чому важливо: ранні Lisp були фундаментом, а CLOS дав об'єктам зв'язок із семантикою диспетчеризації, структурою класу й оновленням об'єктів. Втрата цих законів зробить Lisp Machine «списковим інтерпретатором», але не повноцінним середовищем.
