# Двійкова мова SENS — проєктна нотатка й план добудови

**Статус:** дослідницька нотатка. Не ратифікує жодної координати, не змінює драбину.
**Автор:** vivaka-hub (агент). **Дата:** 2026-10-09.

## 1. Що означає «справді двійкова мова» ТУТ

У цьому репозиторії «двійкова мова» — це не «мова, написана нулями й одиницями заради
краси». Це конкретний контракт, який уже частково існує в коді:

```
джерело  → послідовність ТОЧНИХ слів (width, value), width 1..=9, без імен
пакування → неперервний MSB-first бітопотік, БЕЗ вирівнювання по байтах
байти    → лише фізичний носій; межа слова може перетинати межу байта
семантика → НЕ на біт-патерні; домен і роль живуть у драбині D1..D10
```

Ключове: **на біт-патерн не навішується значення.** `00000111` — це не «cond» і не
«істина»; це слово ширини 8. Значення йому дає **координата драбини**, окремим шаром.
Саме це відрізняє двійкову мову від «текстової мови, переодягненої в біти».

**Висновок:** фундамент є. Бракує **наскрізної мови поверх нього** — правила, яке
з'єднує «бінарне джерело → пакування → координата → виконання» в один перевірюваний цикл.

## 3. Що бракує (точний перелік)

1. **Виконуваний контракт ядра** — правило пакування/розпакування, яке можна
   перевірити *окремо від компілятора*. (Перший крок — зроблено, див. §4.)
2. **Наскрізний цикл джерело→координата→виконання** як єдиний оракул.
3. **Межа fail-closed** — невалідна машинна форма НЕ має доходити до хоста.
   (Саме вона зараз червона у CI — див. §6.)
4. **Незмінний smoke-ворот** — Vertical Day / L0-оракул / дайджест, зелений і нерухомий.

## 4. Перший крок — уже зроблено (виконувана модель)

`scripts/sens_binary_language_model.py` — Python-модель ТОГО САМОГО контракту.
Вона не заміняє Rust і не компілює; вона (а) фіксує правило словами коду,
(б) служить **оракулом** для Rust-реалізації, (в) ловить дрейф.

Що вона доводить (self-test, `--self-test`):
```
[OK] width 0 / 10 / значення за шириною — відкидаються (fail-closed)
[OK] valid_bits = сума ширин; payload мінімальної довжини
[OK] round-trip ТОЧНИЙ, включно з не-байтовими ширинами
[OK] межа слова перетинає межу байта — збережено
[OK] джерело лише з 0/1; небінарний токен відкидається
[OK] координати — окремий шар; розбіжність ширин відкидається
```

Чесно про шлях до цього: **перша версія моделі впала на трьох тестах**, і це виявив
її ж self-test. Баг: `to_bytes` добиває біти зліва, а я знімав хвіст зсувом праворуч
замість маски. Виправлено — і саме тому висновок вище вартий довіри: він перевірений,
а не заявлений.

## 5. Порядок добудови (пропозиція, рішення — власника)

```
Крок 1. Модель ядра (пакування/розпакування)          — ЗРОБЛЕНО
Крок 2. Rust-оракул за моделлю: ті самі 13 тверджень
        як Rust-тест, що мусить узгоджуватись із Python
Крок 3. Наскрізний цикл: бінарне джерело → координата → виконання,
        як ЄДИНИЙ оракул (не розсип тестів)
Крок 4. Fail-closed межа: довести, що невалідна форма не доходить до хоста
Крок 5. Незмінний smoke-ворот (Vertical Day / L0 / дайджест) — зелений і нерухомий
Крок 6. Лише тоді — подальше «спалення імен» у Rust-шарі
```

**Правило порядку:** крок N+1 не починається, доки крок N не зелений. Мова не
будується на червоному фундаменті.

## 6. Застереження (станом на сьогодні)

CI на `main` **червоний**: ворота №0 (`Vertical Day non-cancelling smoke`) падають ×7,
і серед них пробита **fail-closed межа** — «Invalid machine form never reaches host».
Це означає: **крок 4 (fail-closed) зараз найгостріший**, і його треба закрити
ПЕРШИМ, до будь-якого подальшого будівництва. Інакше двійкова мова стоятиме на
фундаменті, крізь який тече.

## 7. Межі цієї нотатки

- Вона **не** ратифікує координат і **не** вигадує їх — це власник.
- Вона **не** доводить семантику — лише механічний контракт пакування.
- Python-модель — **модель**, а не компілятор. Фінальне слово — за Rust+CI.
