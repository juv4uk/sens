# D10 — точний афінний перенос фізичної величини: POINT ≠ DELTA

**Стан:** один `pending-review` кандидат у спільному десятирозрядному просторі, `selected=false`, `ratified=false`, `coordinate=null`. Конкретний математичний закон є, але окремий машинний резидент **ще не обрано**.

## Чому це з наших давніх ідей

- Астрономія й орбіти: фізичні координати та зміщення в обраній системі відліку — різні типи; часові епохи не завжди переводяться лінійно, тому UTC із високосними секундами тут не підтримується.
- Маятник, AS5600 та ESP32-S3: абсолютні вимірювання з нульовим калібрувальним зміщенням і приріст кута/значення; 0 відносно каліброваного датчика не тотожний фізичному нулю.
- Аналоговий комп'ютер `spanda`, FPGA і АЦП: виміряне значення з точним коефіцієнтом і нульовим зсувом; аналоговий вхід не перетворюється автоматично на точний факт без явного контракту вимірювання.
- SDR, акустика, музика та хронометрія: фізичні величини й їх різниці мають розмірність; **логарифмічні децибели та UTC не є афінними одиницями**, їх не можна таємно підставляти до цієї функції.

## Джерела

**[NIST SP 811, розділ 8.5](https://www.nist.gov/pml/special-publication-811/nist-guide-si-chapter-8)**: абсолютний показ у °C має точний початковий зсув `273.15 K`, а інтервал температури °C та K має однакову числову величину.

**[BIPM, одиниця kelvin](https://www.bipm.org/en/si-base-units/kelvin)**: фундаментальна фізична розмірність і визначення кельвіна. Джерело не містить API для SENS і не визначає наші типи `POINT`/`DELTA`. Узагальнена семантика — **наша дослідницька гіпотеза**, не приписується NIST.

## Один кандидат

`AFFINE-QUANTITY-TRANSPORT` — `ук: афпв`, `укр: афінно-перевести-величину`.

Вхід: `(x, POINT | DELTA, unit_source, unit_target)`, де кожна одиниця задається сімома **точними** показниками розмірностей, позитивним масштабом `s` і раціональним зсувом початку `o`.

Для POINT:

```
base       = s_source * x + o_source
target     = (base - o_target) / s_target
```

Для DELTA:

```
target     = (s_source * x) / s_target
```

Обидві гілки мають однаковий тип результату `POINT` чи `DELTA`, точну `ℚ` арифметику; невідповідна розмірність і невалідні масштаби відхиляються.

| Вхід | Вид | Переклад | Результат |
|---|---|---|---|
| 0 °C | POINT | → K | 273,15 K |
| 5 °C | DELTA | → K | 5 K |
| 32 °F | POINT | → K | 273,15 K |
| 9 °F | DELTA | → K | 5 K |
| 100 °C | POINT | → °F | 212 °F |

Абсолютні шкали з зсувом початку і шкали приросту не можна змішувати. Інваріанти: `A→B→C == A→C`, `A→B→A == A`, а різниця двох POINT після переносу дорівнює переносу їх DELTA.

## Дедуп — важливіше за кількість

У selected D10 **вже є** `SCIENCE-MERGE-DIMENSIONS`, `SCIENCE-DIMENSIONS-VALID?`, `SCIENCE-NEGATE-DIMENSIONS`, `SCIENCE-ADD-DIMENSION`. Вони працюють із **показниками фізичних розмірностей**, а не з точним афінним перенесенням одиниць та різницею POINT/DELTA. Але з точного множення, ділення, порівняння й записів наш кандидат цілком може бути **похідною бібліотечною функцією**. Власник вирішує, чи потрібен окремий D10 SELECT, або залишити його в Core-Math. Ніяких заяв про нову математичну аксіому.

## Автоматизований доказ

- `scripts/check_d10_affine_quantity.py --self-test` — 7 груп Python тестів, точні раціональні `Fraction`, 5000 наборів із 2 kind кожен, усі A→B→C комбінації чотирьох різних одиниць, випадки несумісних розмірностей, 10 негативних мутацій machine evidence.
- `tests/oracles/d10_affine_quantity_sbcl.lisp` — незалежне реалізування формули в **справжньому SBCL**, без `float`, без доступу до файлів чи апаратури.
- `.github/workflows/d10-affine-quantity-proof.yml` запускає обидві перевірки в GitHub.

Обидві реалізації перевіряють **нашу формальну модель**, але не є доказом роботи відповідної двійкової програми в runtime SENS. Немає жодного нового `.sens` opcode, зміни D2, ратифікації, змін D1–D9 чи авторитету фізичних констант.

Запис у канонічний proposal-ledger після п'яти вже наявних пропозицій повинен пройти fail-closed gate і пройти людський огляд, до зміни selected inventory.
