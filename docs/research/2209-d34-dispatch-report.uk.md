## Межі інтерпретації

- `u8-flat-ready` — навмисно сприятливий механічний baseline із 256 слотами. Це не твердження, що історична таблиця Function8 симетрично містила всі D4-селектори.
- `d3d4-prefix-ready` використовує ратифіковані корені `101/110` і один D4 suffix-біт; окремого lookup для похідного селектора немає.
- `direct-static` використовується тільки для повторюваних статичних call-site і є нижньою межею для compile-away.
- `direct-dynamic` лишається switch-контролем для випадкових/змішаних потоків і не є нижньою межею скомпільованого коду.
- Парсинг identity та framing навмисно не входять у цей вимір; їх окремо досліджує #1993.

## Висновок для механізму

- Для D3 prefix-маршрут дешевший за сприятливий u8-flat: 12.0 проти 21.0 I refs/виклик на повторюваному навантаженні та 12.501 проти 21.0 на випадковому.
- Для D4 generic prefix interpreter трохи дорожчий за flat: 31.001 проти 28.0 I refs/виклик, але не потребує descendant lookup і таблиці.
- У mixed D3/D4 prefix майже зрівнюється з flat і трохи нижчий за I refs: 25.317 проти 25.656.
- Static compile-away показує значний запас для оптимізації: 8.0 I refs для D3 і 11.001 для D4.

Ці цифри є доказом вартості механізму, а не новою семантичною владою і не загальним рейтингом реалізацій.
