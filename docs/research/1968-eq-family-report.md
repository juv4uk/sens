# #1968 — bounded EQ-family result

Research-only. No allocation/runtime/contracts change.

## Question

Does `011 = EQ` have an immediate small binary family comparable to the
proven CAR/CDR selector action?

Candidates tested from the current bounded corpus:

```text
NULL
EQUAL
MEMBER
```

Positive controls:

```text
CAAR
CADR
```

## Bounded strength criterion

This experiment deliberately tests only the strongest/simple class:

- composition-only;
- fixed local primitive action;
- no new branching;
- no recursion;
- no candidate-specific hidden descendant table.

Passing this class is what makes CAR/CDR especially attractive.

Failing it does **not** prove that no richer generator can ever exist.

## Result

```text
CAAR  -> positive control PASS
CADR  -> positive control PASS

NULL  -> ATOM + COND + QUOTE
         no direct EQ dependency

EQUAL -> EQ + ATOM + CAR + CDR + COND + QUOTE
         self-recursive

MEMBER -> ATOM + CAR + CDR + COND + QUOTE
          self-recursive traversal
          structural comparison delegated through EQUAL
```

Therefore:

```text
EQ -> EQUAL   typed-family candidate only
EQ -> NULL    not an immediate strong EQ child
EQ -> MEMBER  not an immediate strong EQ child

0110 / 0111   remain unallocated
```

## Why EQUAL is still interesting

`EQUAL` is semantically related to `EQ`: current source directly uses
the exact EQ root while extending equality structurally.

But its law is not a one-bit local action of selector strength. It imports
multiple independent roots plus recursion/control.

That is exactly the distinction the new model needs:

```text
related to root
!=
generated by one local suffix bit
```

## Analyzer correction discovered live

The first WSL run failed because the dependency walker ignored calls in
the head position of a COND clause:

```text
((EQ a b) yes no)
```

The walker was corrected to traverse all list children and the experiment
was re-run green before accepting the conclusion.

This failure is preserved as useful research evidence: dependency tools
must understand clause structure rather than assume ordinary call shape.

## Conclusion

For the bounded Lisp I/Lisp 1.5/current-core evidence tested here, there is
no justified reason to occupy `0110` or `0111`.

Prefer:

```text
unallocated
```

over inventing a binary symmetry.

Future work may discover a richer EQ algebra, but it must beat this bounded
negative result with a smaller executable law.
