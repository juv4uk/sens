## Метод і його межа
`git ls-files 'crates/*/src/**/*.rs'`, рядки з `ExprKind::String`, `Value::String`, `TAG_STRING`, не коментарі. Скрипт відтворює таблицю з нуля. `Rc<str>` (25 сайтів) **виключено**: це імена (Symbol, слоти, host-handle kind), їх веде #1696, не #1700.
**Клас за шляхом файлу — прогноз (predicted), не читання кожного рядка:** 4 файли перевірено вручну (нижче), решта класифікована за роллю модуля.

## Що з цього справді «канонічна ідентичність» (source-confirmed, 4 місця)
1. `value.rs:564` — `(Value::String(l), Value::String(r)) => l == r`: рівність рядків = побайтова UTF-8, а не порівняння кодів Text7.
2. `syntax.rs:53` / `value.rs:494` — String як варіант AST і значення (`Rc<str>`).
3. `syntax.rs:120`, `syntax.rs:361` — теги fasl `3` і wire `0x55` серіалізують UTF-8 (`put_text`/`get_text`).
4. `eval/mod.rs:139` і `closures.rs:640` — літерал ↔ значення **без жодної нормалізації**, тобто перехід «людський текст → канонічний код» у рантаймі відсутній.

Єдине джерело нових String — `parser.rs:317`. Отже **точка входу для Text7 одна**: читач, який має відхиляти звук без клітинки UPC-7 (fail closed), як кодек у shiva-sutras#32.

## Що можна видалити без нової семантики (пропозиція, не перевірено)
- Нічого з 84 не можна прибрати ізольовано: String досі використовують `string-slice`, json, io, digest (33 сайти). Видалення починається з **читача + рівності + теги (12 сайтів)**, builtins слідом.
- 35 host-сайтів, схоже, лишаються людською межею (клас `human-boundary` за #1707), а не боргом.

## Чого не знаю (not-yet-verified)
- Скільки з 33 builtin-сайтів справді залежать від UTF-8 семантики (`string-slice` рахує Unicode scalar) проти простого проносу тексту.
- Скільки `.lisp`-фікстур містить літерали за межею таблиці UPC-7 (потрібен окремий скан, і він залежить від рішення по shiva-sutras#32).
- Чи `Value::String` десь використовується як ключ dispatch (потрібен окремий пошук `HashMap<Rc<str>`… уже за межею #1700).
