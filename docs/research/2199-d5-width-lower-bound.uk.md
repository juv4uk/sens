# #2199 — фальсифікатор нижньої межі ширини D5

Статус: лише research.

## Навіщо це існує

#2193 / PR #2194 доводить нижню межу семантики:

```text
звичайне closure -> eager operands
transformer      -> raw operands
```

Одна нерозрізнена call-policy не може задовольнити обидві поведінки.

Але це **ще не доводить**, що мінімальна нова exact-width identity мусить мати ширину 5.

У ратифікованій D4-карті все ще є:

```text
0101 <unallocated>
1001 <unallocated>
```

і #2158 називає їх навмисно незаповненими, але не доводить, що вони назавжди заборонені.

## Поточний результат

Виконуваний witness спершу перебирає коротші escape hatches, а вже потім дивиться на привабливого D5-нащадка:

```text
0101  allocation-only staged role
1001  allocation-only staged role
00101 staged child under 0010 LAMBDA
```

За поточним ратифікованим формулюванням обидві 4-бітні моделі ще не можна чесно відкинути лише законами репозиторію.

Тому поточний стан теореми навмисно такий:

```text
D5-WIDTH-LOWER-BOUND=NOT-PROVED
```

Це корисний негативний результат. Він не дозволяє переплутати:

```text
00101 є узгодженим placement
```

із:

```text
width=5 є математично необхідною
```

## Що потрібно для посилення результату

Майбутній ратифікований доказ мусить закрити обидва коротші класи:

1. членство в D4 семантично закрите, а не просто зараз майже заповнене;
2. unrelated allocation-only residency у `0101` / `1001` заборонена доведеним законом, а не естетикою.

Лише після цього, якщо 5-бітний staged witness виживе, скрипт можна змінити на:

```text
D5-WIDTH-LOWER-BOUND=PROVED
```
