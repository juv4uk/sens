# Зведений прогрес міграції `.lisp → .sens` без самообману

**Чинне уточнення · контракт 11.9.** Типовий фізичний `.sens` — **T5M**; історичний T5 дозволений лише явним сумісним маршрутом. `.lisp` є повною українською проєкцією, а файл без розширення — читабельним бітовим поданням, не виконуваним файлом. Для допущеної програми необхідні побайтове повернення `.sens → біти → .sens`, точна зворотна проєкція `.lisp ↔ доменні слова` і незалежні позитивні/негативні свідки виконання. Наявність однакових назв файлів цього не доводить.

**Архівна процедура 2026-10-08 · задача #4449 · механічний облік, НЕ семантичний оракул.** Наступний опис і назви інструментів стосуються історичного T5, не поточного T5M-допуску.

Наша мова — двійкова; `path/name.lisp` стає `path/name.sens` у фізичному T5: 5 тритів на байт, транспортна `2` **лише між** точними доменними словами; EOF — довжина файла без `22`; 0–4 фінальних pad-трити. Вміст `.sens` не є текстом із нулів та одиниць.

В історичному репозиторії були два незалежні механічні аудити (нині їхні звіти треба оцінювати з урахуванням T5M):
- `scripts/audit_t5_t5m_file_pairs.py`: перевіряє **кожний відстежуваний файл .sens** і однойменний `.lisp`, фізичний T5, хеші й точні доменні ширини.
- `scripts/migration-readiness-census.py`: у чинному режимі **AUTO** (історичні режими більше не дозволяють вибрати семантику) інвентаризує **оригінальні `.lisp` без .sens** і розрізняє історичні причини BLOCK та лише механічну готовність.

Новий `scripts/report_t5m_migration_progress.py` **не пише власного парсера, не конвертує і не створює .sens**. Він бере два результати та незалежний `git ls-files '*.lisp'`, перевіряє:
- усі відстежувані `.lisp` присутні **рівно один раз** або у файлі з парою, або в черзі;
- усі фізичні файли отримали **однойменний** `.lisp` (не файл без розширення);
- жодна пара не потрапила водночас у чергу «без пари»;
- жодне поле `would-write` не стало `semantic_admitted=true`;
- старі, дубльовані, незафіксовані або втрачені шляхи — **BLOCKED_DISCREPANCY**, не успішний реліз;
- зберігаються SHA джерела, SHA фізичних байтів, SHA typed-width identity і перша причина блокування, якщо є.

Файл дає класи `PHYSICAL_T5_PAIR_PENDING_INDEPENDENT_ORACLE`, `PHYSICAL_T5_PAIR_BLOCKED`, `UNPAIRED_SOURCE_BLOCKED`, `MECHANICAL_CANDIDATE_NEEDS_ORACLE`, `NONPROGRAM_ARCHIVED_NO_EXECUTABLE_T5`. Це **класи обліку, не статуси дозволу на виконання**.

## Сувора перевірка оберненості, 21.10.2026

**NO-GO до незалежного SENS-доказу.** Успіх `report_t5m_migration_progress.py`
без суворого режиму означає виключно повноту **механічного обліку**.
Він не означає, що кожний `.lisp` уже має `.sens`, що файл можна
перетворити назад в українську проєкцію або що така програма правильно
виконується. Архівні та доказово невиконувані DATA-файли не зобов'язані
стати програмами SENS.

У JSON є незалежні поля:

- `source_complete`: кожний Git-tracked `.lisp` має рівно один рядок обліку;
- `executable_roundtrip_coverage.executable_or_unclassified_sources`:
  кількість чинних/невизначених джерел, які вимагають окремого доказу;
- `executable_roundtrip_coverage.blocked_or_unverified`:
  кількість ще не сертифікованих програм;
- `all_executable_lisp_roundtrip_verified`: може бути `true` лише
  за повної пофайлової відповідності й незалежної виконавчої перевірки.

Для суворого fail-closed результату використовуйте вже створені
`/tmp/t5-pairs.json` та `/tmp/t5-readiness.json`:

```sh
python3 scripts/report_t5m_migration_progress.py \
  --root . --pairs /tmp/t5-pairs.json --readiness /tmp/t5-readiness.json \
  --out /tmp/t5-executable-roundtrip.json --require-executable-roundtrip
```

**Код виходу 2** означає, що повної оберненості/семантичного оракула
немає; цей стан не можна зробити зеленим зменшенням обсягу корпусу,
виключенням невідомих програм або підміною SENS-виконання Python.
Загальний релізний дозвіл додатково вимагає одного SHA, всіх трійок,
позитивних/негативних свідків та рішення власника.

## Відтворення

```sh
python3 scripts/audit_t5_t5m_file_pairs.py . --output /tmp/t5-pairs.json
python3 scripts/migration-readiness-census.py --out /tmp/t5-readiness.json
python3 scripts/report_t5m_migration_progress.py \
  --root . --pairs /tmp/t5-pairs.json --readiness /tmp/t5-readiness.json \
  --out /tmp/t5-progress.json
python3 -m unittest discover -s tests -p 'test_report_t5m_migration_progress.py' -v
```

Підключений CI `report-t5-migration-progress` публікує JSON-артефакти й короткий підсумок. Відсутність жодної пари, зниклий файл у ledger, зайва публікація чи вигаданий статус — не можуть називатися `100% migrated`.

**Релізний доказ окремо:** обов’язкові оригінальний pinned source SHA, canonical Rust D2-парсер, незалежний source/current semantic observer oracle і тільки після цього прийняття виконуваної програми. Цей облік **не послаблює** механізми `guard_original_sens_admission.py`, `admit-t5-migration.py` чи ratified D1–D9.
