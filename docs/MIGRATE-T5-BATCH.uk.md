# Керована міграція справжніх файлів Lisp → SENS

Це **транзакційний пакетний драйвер фізичної T5-підготовки**, а не новий парсер, альтернативна мова чи незалежний семантичний оракул.
Використовує єдиний історичний трипрохідний конвертер
`scripts/migrate-three-pass.py` та фізичний T5-кодек
`scripts/sens_t5_codec.py`. D2 єдиний власник структури.
Текстові файли з ASCII `0/1/2` не вважаються фізичним `.sens`.

**Безпечний стандарт — `--source-era auto`.** Якщо вихідний виклик має рівно 8 біт,
він може бути історичним SID8 або чинним D8. `auto` його **блокує**;
`--source-era legacy` дозволяється лише коли історичне походження доведене,
`--source-era current` — лише для сучасного ратифікованого D8. Жоден
режим сам по собі не доводить семантичну тотожність або можливість виконання.

## Запуск

```bash
# 1. Аудит конкретних файлів без жодного запису .sens (за замовчуванням)
python3 scripts/migrate-t5-batch.py \
    tests/fixtures/core1-third-domain-canary/third.lisp \
    --out /tmp/sens-staged --report /tmp/sens-batch-report.json \
    --source-era legacy

# 2. ЛИШЕ механічне дзеркало T5: усі джерела проходять, або ЖОДЕН .sens не записано
python3 scripts/migrate-t5-batch.py \
    tests/fixtures/core1-third-domain-canary/third.lisp \
    --out /tmp/sens-staged --report /tmp/sens-batch-report.json \
    --source-era legacy --write

# 3. Можна задати декілька файлів і каталогів, зокрема lib/
python3 scripts/migrate-t5-batch.py lib/ \
    --out /tmp/sens-lib-staged --report /tmp/sens-lib-report.json
```

Вхідні шляхи лише **відносно кореня репозиторію**.
Вихідне дзеркало і JSON-звіт мають бути **за межами** репозиторію.
Оригінальні `.lisp` не змінюються. Кожне `name.lisp` одержує
тільки однойменне `name.sens` у дзеркалі; повторний запуск нічого
не перезаписує. Список шляхів детермінований, дублікати усуваються.
Недійсні шляхи, симлінки, невідомі імена, числові та семантичні
неоднозначності залишаються **BLOCKED** із причиною.

**Атомарність когорти:** `--write` спочатку перевіряє **всі** вибрані файли,
включно з відсутніми джерелами, чинними адресами виводу, симлінками,
і повторно звіряє незмінність оригіналів. Якщо хоч один файл має `BLOCKED`,
**жоден** T5 не публікується; успішні форми зберігають статус
`would-write` у звіті, але `files_written=0`. Якщо помилка виникає вже
посеред запису, драйвер видаляє лише створені ним файли, не чіпаючи
раніше наявних адресатів. Якщо все гаразд — увесь пакет має `written`.
Це **механічне дзеркало**, а не дозвіл додати `.sens` у `main`. Код виходу
`0` — усі допущені; `2` — хоча б один BLOCK або немає допущених;
`3` — помилка налаштування, зокрема спроба запису в корінь джерел.

У звіті: SHA256 вихідного тексту, ратифікованого foundation, фізичного
байтового потоку та **типізованих слів із їхньою шириною**, кількість
проходів 1/2/3, обсяг і статус кожного файла. Звіт не є дозволом
на автоматичне злиття: перед PR потрібні окремі D2 parser/oracle parity,
CI і перевірка provenance. Поточний драйвер використовує **`auto` за замовчуванням**, щоби ніколи
мовчки не трактувати сучасний D8 як історичний SID8. Для перевіреного
історичного Core1 слід явно зазначати `--source-era legacy`; для чинного D8 —
`--source-era current` із його ратифікованими координатами. Після механічного
кодування потрібне окреме підтвердження роботи оракула.

**Приклад із реального коду**: наявний Core1 `C1-THIRD`, а не новий
вигаданий інтерпретатор. Тести порівнюють результат міграції
`third.lisp` із перевіреним 38-байтовим `third.sens`,
уже наявним у `sens/main`. Це доказ правильності інструмента
на конкретній спеціалізації, **не** заява про міграцію всього
`lib/core1.lisp` або 491 раніше заблокованих джерела.

## Чому скрипт не переводить старий `lib/` автоматично?

Це реальний виклик, а не заборона запуску: перевірений [CI #37827146878](https://github.com/juv4uk/sens/actions/runs/37827146878)
викликав драйвер на `lib/` і отримав **128 прочитаних, 0 механічно допущених, 128 BLOCKED**.
Без законів щодо локальних прив'язок, старої 8-бітної та сучасної D8 тотожності, чисел,
Text7 і викликів хоста конвертер **не має права** вигадати байти або заявити
про семантичну тотожність. Правило «сканувати 491 і переписати всі виклики»
ризикує пошкодити навіть процитовані дані та локальні функції.

## Автоматичне використання у GitHub CI

Workflow `.github/workflows/migrate-t5-batch.yml` тепер працює для кожного PR/
push до `main`, що змінює початкові `lib/**/*.lisp` або `scripts/**/*.lisp`,
а також зміни трипрохідного мігратора, T5-кодека, ратифікованої основи й
відповідних таблиць. Його також можна запустити вручну через
**GitHub Actions → safe-batch-t5-migration → Run workflow**.

Кожен такий запуск **дійсно виконує** наявний `scripts/migrate-t5-batch.py lib scripts`
у режимі dry-run, додає до GitHub Actions Summary лічильники допущених/заблокованих
джерел і перші 12 причин, а повний JSON реальних шляхів публікує у
`active-lib-scripts-t5-migration-ledger` (артефакт прогону).
Блокування не вважається зеленим доказом виконання програми. Жоден `.sens`
не публікується автоматично без незалежного oracle-підтвердження.

## Як агент переводить ОДИН справжній історичний файл

1. Відкрийте звіт запуску й візьміть **дійсний** раніше наявний `.lisp` із `lib/`
   або `scripts/`; не рахуйте вже відомі тестові пари вдруге.
2. Встановіть Git blob SHA джерела; розберіть конкретний `BLOCKED` без припущень
   про прив'язки, дані та стару/нову 8-бітну епоху; відповідні задачі — #4526 і #4449.
3. Після встановлення законної D1–D9 тотожності доведіть у поточному SENS
   незалежне семантичне виконання, D2 структуру, коректний T5 roundtrip
   і точний SHA у звіті.
4. Виконайте `scripts/migrate-t5-batch.py` у `dry-run`: якщо хоча б один
   учасник групи `BLOCKED`, виправляйте семантичну причину, а не публікуйте
   частковий пакет. Режим `--write` тут лише готує **усе фізичне дзеркало**.
   Для справжнього доказового допуску до `main` використовуйте вже наявний
   `scripts/admit-t5-migration.py` із Git-SHA джерела, фізичним SHA,
   реальним `sens-trit open` (Rust D2) та незалежними оракулами; 
   `scripts/migrate-sens.py` виконує перевірений T5-оператор з реальним
   Rust D2 перед записом. Лише перевірену пару приймайте в PR.
5. Без доказу — статус `BLOCKED`, **не** вигаданий `.sens`, не зміна доменів
   та не новий SID8-диспетчер.
