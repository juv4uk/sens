# Міграція SENS у два представлення до завершення Frame3

**Затверджена структура трійки:** `name.lisp` — канонічна українська поверхня `ук`; `name` — точні 0/1 слова з одним пробілом між ними і рівно одним LF наприкінці; `name.sens` — майбутній фізичний файл нового кодека.

## Тимчасовий етап: тільки перші два

`scripts/stage-two-projections.py` приймає **явні** джерела `.lisp`, застосовує чинне трипрохідне відображення історичних викликів, перевіряє ширини слів D1–D9 та використовує наявний **обмежений** зворотний рендерер канонічної української поверхні. Після незалежного зворотного порівняння точних слів створює **рівно два** однойменні файли в окремому дзеркалі:

- `name.lisp` — українська канонічна поверхня; оригінальне джерело залишається на місці;
- `name` — логічна послідовність точних бінарних слів, розділених пробілами.

Фізичний кодек **не викликається**, `name.sens` не створюється, код транспорту T5/Frame3 не обирається. Наявний трипрохідний модуль використовується тільки для логічної проєкції слів; залежність від його поточного Python-модуля — тимчасова, її можна прибрати після готовності Rust-проєктора.

```sh
# Лише перегляд, нічого не записується
python3 scripts/stage-two-projections.py \
  tests/fixtures/migration-d1-cond-cohort/branch.lisp \
  --mirror /tmp/sens-stage-two

# Атомарно створити два файли в зовнішньому дзеркалі, без перезаписів
python3 scripts/stage-two-projections.py \
  tests/fixtures/migration-d1-cond-cohort/branch.lisp \
  --mirror /tmp/sens-stage-two --write

# Перевірка самого етапу
python3 -m unittest discover -s tests -p 'test_stage_two_projections.py' -v
```

Команда за замовчуванням зупиняється на неоднозначних W8, непридатних Text7, неперевірених binder/quote/number та поза обмеженою українською граматикою. Вхідний `.lisp` не перезаписується. Усі файли підкорпусу перевіряються перед записом; один блокер — нуль результатів, а частковий запис відкочується. Шляхи із симлінками та існуючі результати заборонені. Вивід JSON містить SHA-256 вихідного файла й обох майбутніх проєкцій; для доказового журналу збережіть stdout окремо поза репозиторієм.

**Не плутати з ратифікацією.** Статус `TWO_STAGED_PHYSICAL_AND_ORACLE_PENDING` означає лише механічно узгоджені `ук` і точні двійкові слова. Семантичний оракул історичної/поточної програми — `NOT_VERIFIED`, `release_admitted=false`. Немає автоматичного зарахування до кількості мігрованих виконуваних програм.

## Коли Frame3 буде готовий

Взяти вже засвідчену послідовність точних слів із `name`, перевірити SHA і граматику, закодувати у фізичний `name.sens`, зворотно декодувати побайтово і зіставити **ті самі слова**. Потім незалежно перевірити оракул виконання. Результат додається до тієї самої трійки без нового перекладу `name.lisp` і без перезапису перших двох файлів. До ратифікації Frame3 типовим машинним носієм `.sens` лишається T5: новий формат не можна непомітно видавати за T5 під тим самим суфіксом.
