# Каталог доменних проєкцій у Rust

## Мета

Надати Rust-споживачам точний пошук коду та його наявних проєкцій у чинній
драбині SENS. Для ключа потрібні доменна ширина, точний бітовий запис із
ведучими нулями та явно названа проєкція. Це read-only погляд на джерела SENS,
а не друга семантична таблиця.

## Межі та авторитет

- Поточні таблиці `lib/domains/d1.lisp` … `d11.lisp` є джерелом їхніх колонок
  проєкцій і кодів. Ратифікований `knowledge/d7-keyboard-v2-ratified.json`
  залишається окремим точним джерелом D7 keyboard-v2, зокрема для керівних
  кодів, не відображених як друкований символ у Lisp-таблиці.
- `knowledge/number-width-ratified.json` і наявний Rust numeric domain code є
  авторитетом для D24+ числової родини. D24+ не є скінченною таблицею
  текстових міток і не копіюється в каталог як перелік чисел.
- Інших доменів чи проєкцій не виводити. Якщо поточне джерело не описує
  домен/клітинку, пошук повертає відсутність результату.
- Старі SID8/SENS8/Function8 таблиці й архіви не є входами генерації.

## Архітектура

`crates/sens/build.rs` читає чинні доменні таблиці та окремі ратифіковані
проєкційні дані D7 keyboard-v2 і D11 testing vocabulary, перевіряє їхній
точний формат і створює статичний Rust-каталог у `OUT_DIR`. Runtime API в
новому `domain_projection_catalog` приймає
`(домен, точні біти, простір джерела, назву колонки)` і повертає точне
збережене значення або `None`. Генератор не нормалізує Unicode, не знімає
ведучі нулі, не обрізає ширину й не вгадує колонки.

Простір джерела є частиною запиту: наприклад, поле `san` у D7 Lisp-поверхні
не можна автоматично ототожнювати з полем `san` у keyboard-v2 JSON. Колонки
`ук`, `укр`, `san`, `en`, `LISP`, `sym` та JSON-поля залишаються такими, як
їх назвали самі джерела. Явне `()` або порожній рядок зберігаються окремо від
відсутньої клітинки.

Каталог не вирішує доменну residency, право виклику, значення операції чи
фізичний формат. Він не замінює `semantic_registry`, доменні закони,
числову реалізацію або T5M. Наявність рядка в таблиці не означає, що його
можна викликати.

## Перевірки та міграція тесту

Rust-інтеграційний тест звіряє повний обсяг зібраних клітинок, перевіряє D11
authority parity (43 унікальні 11-бітні коди та точні `ук`/`укр`/`sym`) і всі
128 рядків D7 keyboard-v2, включно з керівними символами.
Негативні випадки підтверджують, що невідомий домен, код, проєкція або
неповна бітова ширина не отримують підстановки чи результату.

Дубльовану Python-перевірку D11 прибрати після проходження еквівалентного Rust
свідка; дві діагностичні перевірки клавіатурних помилок залишити, бо вони
не дублюють цей каталог. Не додавати workflow чи новий глобальний CI-гейт;
використати чинний Cargo test шлях.

## Критерій готовності

Споживач Rust може запросити точну проєкцію за повною доменною identity й
отримати значення, дослівно узгоджене з чинним джерелом; невідомий запит
відмовляється без fallback. Цільова команда: `cargo test --locked -p sens
--test domain_projection_catalog`. Перевірка технічної збірки не є
семантичною ратифікацією.
