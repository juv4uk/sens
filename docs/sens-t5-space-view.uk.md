# `.sens`: двійкова мова, трійкова межа всередині кодера, пробіл на екрані

**Рішення власника (8 жовтня 2026):** для першого `.sens` вибрано T5, фізично 5 тритів на 1 байт. **Це вибір транспортного кодера, не ратифікація повного файлового wire-v1**. SENS семантично залишається двійковою мовою; D2 контролює структуру, D7 text-space — окреме семантичне слово. Не перетворювати семантичну `0/1` мову на трійкову.

## Як виглядає відкритий `.sens`

```text
Вхідні SENS слова:       10 | 001 | 00 | 000 | 01
Транспортні трити T5:    1020012002000201     (16 змістових тритів + чотири pad-2)
Файл на диску, hex:      63 89 06 A1          (4 фізичні байти)
Перегляд на екрані:      10 001 00 000 01
```

**Логічний трит `2` існує тільки всередині кодера/декодера**. Він позначає межу між словами, але **не стає видимою цифрою**. При відкриванні декодер відновлює typed domain words `(width,0/1-bits)` та виводить один звичайний ASCII-пробіл лише МІЖ сусідніми словами. **Завершувача `22` немає**: кінець файла дає EOF файлової системи. Тільки 0–4 pad-трити `2` наприкінці останнього байта не відображаються. Сам файл **не містить ASCII пробілів як роздільників** і не є текстовим.

### Чому окремий EOF не потрібний

**У звичайному байтовому файлі EOF уже відомий із довжини файла.** T5 використовує логічну транспортну `2` **тільки між двійковими словами**. Кінець — останній біт останнього слова; решту останньої групи з 5 тритів доповнюємо 0–4 службовими `2`. Декодер видаляє ці кінцеві `2` до прочитання точних слів, відхиляє 5 або більше (`не мінімальне доповнення`), перевіряє канонічне повторне кодування.

Формула для `n >= 1` слів і `S` семантичних бітів:

```text
data_trits     = S
boundary_trits = n - 1
eos_trits      = 0
encoded_trits  = S + n - 1
physical_bytes = ceil(encoded_trits / 5)
tail_trits     = 5 * physical_bytes - encoded_trits   # 0..4
```

Це працює **не лише для дужкових форм**: один D1-біт, окремий атом D3 або кілька D2 верхньорівневих форм так само відновлюються, якщо синтаксис дозволяє. D2 закривальна дужка використовується лише для перевірки структури, не як сигнал завершення фізичного файла. Короткі приклади: `10 01` займає 1 байт, `10 001 01` — 2 байти. Внутрішній `2` ніколи не стає видимою цифрою: при відкриванні він перетворюється на пробіл.

**Сумісність:** цей кодек більше **не додає старий `22`**. Старі експериментальні `.sens` можуть залишитися byte-identical (коли попередній `22` уміщався в нове доповнення), а в інших випадках мають зайвий байт і будуть відхилені. Відгадувати формати автоматично не можна: перегенерувати `.sens` з перевіреної `.lisp` пари в новому місці; CLI не перезаписує існуючий файл. **EOF не є CRC:** будь-яка інша повністю допустима послідовність байтів теоретично може означати іншу програму; для цілісності потрібен окремий digest/контейнер, якщо це вимога.

### Перегляд за допомогою CLI

```shell
cargo run -q -p sens-cli --bin sens-trit -- open path/program.sens
cargo run -q -p sens-cli --bin sens-trit -- view path/program.sens
cargo run -q -p sens-cli --bin sens-trit -- path/program.sens
```

Усі три команди друкують одну строку з пробілами. Існуючий інструментальний `decode` збережений для виведення кожного слова на окремому рядку:

```shell
cargo run -q -p sens-cli --bin sens-trit -- decode path/program.sens
```

Створення та контроль пари:

```shell
cargo run -q -p sens-cli --bin sens-trit -- encode path/program.lisp
cargo run -q -p sens-cli --bin sens-trit -- verify path/program.lisp
```

`encode` **відмовляється перезаписувати** наявний `program.sens`; `open/view` тільки читають файл, перевіряють T5 canonical padding (0–4 кінцевих трити `2`) і чинні D2 структурні правила. Невідоме чи зіпсоване byte-пакування відхиляється. **Редактор ОС без інтеграції не вміє декодувати packed `.sens`**: щоб при подвійнім кліку файл виглядав так само, потрібно налаштувати асоціацію з T5-viewer або написати редакторний provider. Ця інтеграція поки не встановлена.

### Що значить `2`

- `2` — **не** член лексичного алфавіту SENS і **не** додатковий біт функції.
- `2` — **не** D2 structural separator `00`.
- `2` — **не** D7 text `sign.space=1100000`; коли той зустрінеться як справжнє слово, його біти буде видно як `1100000`, а не додатковий пробіл у поданні.
- `2` у T5 — лише технологічна вказівка «закінчилося поточне слово». Тому навіть коли слово — біт `0` або `1`, ширина зберігається без втрати ідентичності.

### Обмеження до релізу

- Підтримані механічні кодові слова D1–D9, їхній exact width та чинний D2 синтаксичний reader; повна семантична oracle parity не доведена.
- **Файловий закон власника:** нові виконувані `.lisp` є українською (`ук`) людиночитаною проєкцією; бітові слова належать фізичному `.sens`, а не джерельному `.lisp`. Поточний низькорівневий `sens-trit encode` ще читає лише видимі точні бітові слова — це **обмеження CLI, а не дозвіл** зберігати двійковий дамп як `.lisp`. Доведена вузька міграція українських D1 (`ні`/`так`) і D3 (`за-умовою`/`перше`) доступна через `scripts/migrate-three-pass.py` (fixture `migration-d1-cond-cohort`). Повне `ук` → T5 та обернений канонічний view/roundtrip залишаються відкритим release-блокером #4430.
- Number D24+ value layout, остаточне нормування доповнення байта й сумісності старих файлів із `22`, зовнішній тип файла/контекст, конфлікт розширення `.sens` зі ScanNet, GUI file association та magic/версія — окремі ворота #4444.
- Інші дослідні кодеки (BP, HDLC, width tags) не можна автоматично пробувати як fallback для T5 `.sens` — фізичний `8F` неоднозначний між T5 та BP.

**Пов'язані задачі:** #4438 (codec/reader), #4444 (wire-v1), #4445 (performance, без блокування вибраного власником T5). Розгорнутий донор: PR #4443. Цей документ описує реалізований командний перегляд, не заявляє, що всі редактори вже розпізнають `.sens`.
