# SENS: виконуваний двійковий вхід CLI (етап введення)

**Канонічна форма — двійкова.** Інтерфейс для людини — проєкція, а не дозвіл
на виконання англійських/українських імен як машинних ідентичностей.

## Використання

```sh
# Перевірити правильність бітового тексту без завантаження старого Core.
printf '10 001 00 000 01\n' | sens --binary-check -

# Те саме з файлом; позитивний результат: BINARY-SOURCE-PASS forms=1
sens --binary-check program.lisp

# Виконати program.lisp лише через canonical_reader (без fallback до parse()).
# Для повноцінного виконання потрібен зелений Lisp-owned bootstrap / oracle.
sens --binary program.lisp
```

**Два окремі фізичні представлення:** `program.sens` — пакований фізичний T5,
який чинний `sens` виконує чистим шляхом *без* текстового Lisp та Core4.
`program.lisp` може містити видимі D1–D9 бітові слова, але цей шлях потрібно
явно вибрати через `--binary`/`--binary-check`. Без прапорця `.lisp`
залишається історичним текстовим режимом сумісності. Розширення не замінює
перевірку фактичного типу вхідних даних.

- `--binary`: перевіряє D1–D9 точні бітові слова, D2 структуру, після чого
  передає дерево звичайному механізму виконання SENS. Жодної запасної спроби
  текстового `parse()`.
- `--binary-check`: без жодного bootstrap чи eval перевіряє канонічний AST;
  `BINARY-SOURCE-PASS` — **лише синтаксис**, не семантичний доказ.
  При помилці повертає ненульовий exit code і `BINARY-SOURCE-BLOCK`.
- Звичайний `sens program.lisp` тимчасово лишається **режимом сумісності**
  для міграції старого корпусу; його треба відключати поетапно після зелених
  оракулів L1–L7 та семантичного покриття. Не вважати його двійковим.
- `--binary`/ `--binary-check` не можна повторити чи поєднати.

## Невідступні межі

1. D1 — точний біт відповіді. D2 визначає OPEN/SEP/CLOSE/DOT, `000`
   лишається структурним порожнім об'єктом D3, не D1:0.
2. W7 не стає автоматично символом, функцією або числом. Text7/звук
   інтерпретується тільки у ратифікованому контексті D7.
3. Однакові числові payload на W7 і W8 — **різні** ідентичності.
4. Непізнане ім'я, бітова ширина понад D9, неузгоджені D2 дужки,
   неприпустима виконувана форма → BLOCK, без здогаданої D10 координати.
5. Виконання, CPU/FASL і проєкції повинні зійтися незалежними Lisp-оракулами:
   зелений parser CI сам по собі не доводить коректності програми.

## Фактичний стан

Цей текстовий binary-source шлях доповнює вже реалізований фізичний `.sens` T5.
CLI-кордон і тести є кроком до binary-by-default, але текстовий режим
ще доступний, а bootstrap на current main може блокуватися старими COND
формами. **Не оголошувати повний перехід успішним до зеленого end-to-end
Vertical Day smoke на точному SHA.**

Пов'язана регресійна перевірка:
`.github/workflows/binary-first-cli.yml` (GitHub-hosted runner).
