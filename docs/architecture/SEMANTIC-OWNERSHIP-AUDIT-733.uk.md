## 1. Мета та ментальна модель

Перш ніж `my-lisp` зможе бути остаточно спрощена навколо малого, чесного семантичного координаційного ядра (#726, #746), ми зобов'язані провести безкомпромісний аудит власності по всій кодовій базі.

Фундаментальним принципом цього аудиту є **Критичне розрізнення**:

> **Чи визначає цей компонент ЩО ОЗНАЧАЄ МОВА, чи лише ЯК РЕАЛІЗАЦІЯ ЇЇ ВИКОНУЄ?**

Жоден компонент не класифікується лише за історичним місцем у файловій системі або назвою файлу. Файл `.lisp`, який реалізує експериментальний алгоритм логічного висновування, може бути історичним механізмом виконання, тоді як таблиця `.rs`, що відображає незмінні SID на конструкції обчислювача, є свідком канонічного значення.

```text
+------------------------------------------------------------------------+
|                          ЩО ОЗНАЧАЄ МОVA                               |
|   (Семантичний авторитет: Canon 0, McCarthy 7, реєстр SID, закони)     |
+------------------------------------------------------------------------+
                                    |
                                    v
+------------------------------------------------------------------------+
|                   ЯК ЦЕ ЗАСВІДЧЕНО В ДАНИХ LISP                        |
|   (Семантичні свідки: інваріантні чекери, конформанс-корпус)           |
+------------------------------------------------------------------------+
                                    |
         +--------------------------+--------------------------+
         |                                                     |
         v                                                     v
+-----------------------------------+ +----------------------------------+
|      ЯК СУБСТРАТ ЦЕ ВИКОНУЄ       | |      ЯК МИ ГОВОРИМО З ОСТРОВАМИ  |
|      (Механізми виконання)        | |      (Адаптери ядер)             |
|      - Rust парсер, Bignum, VM    | |      - C-ABI vtables             |
|      - Замикання, Env, алокації   | |      - Prolog, Datalog, CLIPS, CL|
+-----------------------------------+ +----------------------------------+
                                    |
                                    v
+------------------------------------------------------------------------+
|                 КАНДИДАТИ НА ПОНИЖЕННЯ АБО ВИЛУЧЕННЯ                   |
|    (Історичні експерименти / Lisp-рушії / доменні підсистеми)          |
|    - lib/reason.lisp, lib/forward.lisp, lib/knowledge.lisp, yantra.lisp|
+------------------------------------------------------------------------+
```

## 2. Таксономія класифікації

1. **`semantic-authority` (семантичний авторитет)**: Визначає непорушне значення мови (канони, закони, реєстри ідентичностей, базова похідна семантика).
2. **`semantic-witness` (семантичний свідок)**: Чисті Lisp-дані або засоби виконання, які засвідчують та верифікують дотримання мовних законів без опертя на зашиті в хост очікування.
3. **`compatibility-reference` (референс сумісності)**: Зовнішні стандарти або референси поверхневих синонімів (наприклад, ANSI Common Lisp, українські мовні профілі).
4. **`execution-mechanism` (механізм виконання)**: Конкретна реалізація на хост-субстраті (Rust рантайм, bignum, розміщення в пам'яті, парсери, обчислювачі).
5. **`kernel-adapter` (адаптер ядра)**: Механічна межа виклику / міст C-ABI до автономних островів виконання.
6. **`historical-experiment` (історичний експеримент)**: Монолітний Lisp-рушій або складна підсистема, кандидат на винесення в опціональний пакет, делегування острову або архівацію.
7. **`unknown` (неоднозначне / потребує експерименту)**: Межовий елемент, що вимагає постановки емпіричного експерименту перед його переміщенням чи видаленням.

## 3. Аудит пріоритетних напрямків

### 3.1 Парсер та рідер (Parser & Reader)
- **Файли:** `crates/my-lisp/src/parser.rs`
- **Класифікація:** `execution-mechanism`
- **Обґрунтування:** Конкретний recursive-descent парсер на Rust, курсори токенів та відстеження діапазонів (Span) є суто механікою виконання на хості. Граматичні закони S-виразів належать семантичному авторитету, але ця конкретна Rust-реалізація є механізмом виконання.

### 3.2 Обчислювач та цикл трамплінування (Evaluator & Trampoline Loop)
- **Файли:** `crates/my-lisp/src/eval/mod.rs`, `crates/my-lisp/src/eval/builtins.rs`
- **Класифікація:** `execution-mechanism`
- **Обґрунтування:** Трамплінування хвостових викликів, фрейми стека Rust, крокове керування обчисленням та перехоплення панік є механікою субстрату.

### 3.3 Замикання та середовища (Closures & Environment Machinery)
- **Файли:** `crates/my-lisp/src/environment.rs`, `crates/my-lisp/src/eval/closures.rs`
- **Класифікація:** `execution-mechanism`
- **Обґрунтування:** Хеш-мапи `Rc<RefCell<Frame>>`, ітеративні списки задач для drop без переповнення стека та зіставлення параметрів представляють фізичну модель виконання.

### 3.4 Представлення значень у рантаймі та алокація (Runtime Value Representation)
- **Файли:** `crates/my-lisp/src/value.rs`, `crates/my-lisp/src/layout.rs`, `crates/my-lisp/src/ir.rs`
- **Класифікація:** `execution-mechanism`
- **Обґрунтування:** Теги переліків (enum), представлення вказівників, вирівнювання пам'яті та лінійні інструкції проміжного представлення належать до виконання на субстраті.

### 3.5 Реалізація арифметики та Bignum (Arithmetic Implementation)
- **Файли:** `crates/my-lisp/src/bignum.rs`, `crates/my-lisp/src/eval/arithmetic.rs`
- **Класифікація:** `execution-mechanism`
- **Обґрунтування:** Алгоритми довгої арифметики, множення Карацуби та скорочення раціональних дробів є алгоритмами хоста.

### 3.6 Списки, вектори та мапи (List, Vector, and Map Implementation)
- **Файли:** `lib/core.lisp` (`list`, `append`, `reverse`, `nth`), `lib/persistent-map.lisp`, `lib/persistent-vector.lisp`
- **Класифікація:**
  - `lib/core.lisp`: `semantic-authority` (канонічна похідна семантика в Lisp).
  - `lib/persistent-map.lisp`: `historical-experiment` (AVL-дерево мапи, винести в опціональний пакет).
  - `lib/persistent-vector.lisp`: `historical-experiment` (32-гілкове тріє, винести в опціональний пакет).

### 3.7 Нативні хуки виконання та взаємодії з хостом (Native Execution Hooks)
- **Файли:** `crates/my-lisp/src/eval/special_forms/` (`io.rs`, `json.rs`, `digest.rs`, `codepoint.rs`)
- **Класифікація:** `execution-mechanism`
- **Обґрунтування:** Доступ до файлової системи ОС, парсинг дротового JSON, обчислення SHA-256 та перетворення кодових точок UTF-8.

### 3.8 Зворотне логічне висновування (`lib/reason.lisp`)
- **Файли:** `lib/reason.lisp`
- **Класифікація:** `historical-experiment`
- **Обґрунтування:** Вбудований у Lisp backward-chaining рушій у стилі Prolog з індексуванням. В архіпелазі зворотна дедукція делегована автономному острову Prolog (`wsm-prolog-kernel`). `lib/reason.lisp` понижується до опціонального пакету міркувань.

### 3.9 Пряме висновування та продукційні правила (`lib/forward.lisp` & `lib/clips-import.lisp`)
- **Файли:** `lib/forward.lisp`, `lib/clips-import.lisp`
- **Класифікація:** `historical-experiment`
- **Обґрунтування:** Вбудований у Lisp RETE forward-chaining рушій правил у стилі CLIPS із робочою пам'яттю фактів. Продукційні правила тепер делеговані автономному острову CLIPS (`wsm-clips-kernel`). Понижується до опціонального пакету або архівується.

### 3.10 Уніфікація (`lib/unify.lisp`, `lib/unify-observe.lisp`)
- **Файли:** `lib/unify.lisp`
- **Класифікація:** `historical-experiment`
- **Обґрунтування:** Уніфікація першого порядку Робінсона з occurs-check у Lisp. Уніфікація та підстановки належать логічним островам (Prolog/Datalog). `lib/unify-observe.lisp` зберігається як свідок за потреби, а `unify.lisp` понижується.

### 3.11 Реляційне замикання та помічники Datalog
- **Файли:** Реляційні запити в `lib/knowledge.lisp`, `crates/wsm-datalog-kernel`
- **Класифікація:**
  - `crates/wsm-datalog-kernel`: `kernel-adapter`
  - Вбудовані помічники дедуктивного замикання: `historical-experiment` (делегуються острову Datalog).

### 3.12 Семантичний реєстр та закони Канону (Semantic Registry & Canon Laws)
- **Файли:** `lib/canon.lisp`, `lib/surface/semantic-registry.lisp`, `crates/my-lisp/src/eval/canon.rs`
- **Класифікація:** `semantic-authority`
- **Обґрунтування:** Canon 0 `()`, 7 аксіом Маккарті та щільний 8-бітний реєстр SID складають непорушний фундамент `my-lisp`.

### 3.13 Відображення мовних поверхонь (Surface Mappings)
- **Файли:** `lib/surface/uk.lisp`, `lib/surface/sa.lisp`, `lib/surface/український-профіль-джерела.lisp`
- **Класифікація:** `compatibility-reference`
- **Обґрунтування:** Мовні синоніми поверхонь, що відображають людські написання на канонічні 8-бітні SID.

### 3.14 Експерименти із семантичним графом (Semantic Graph Experiments)
- **Файли:** `experiments/ground-graph.lisp`, `lib/surface/semantic-registry-experiment.lisp`
- **Класифікація:** `historical-experiment`
- **Обґрунтування:** Дослідницьке індексування тернарних зв'язків `(endpoint relation endpoint)`. Виноситься в дослідницькі пакети.

## 5. Неоднозначні елементи та необхідні експерименти

Аудит виявив 6 компонентів, класифікація яких є справді межовою і які не можуть бути переміщені чи видалені без проведення цільових експериментів:

1. **`lib/si.lisp` та `lib/si-derived.lisp` (Фізичні одиниці SI)**:
   - *Неоднозначність:* Чи є перевірка розмірностей фізичних величин базовим семантичним типом `my-lisp`, чи це доменний пакет?
   - *Потрібний експеримент:* Побудувати відокремлений зріз `packages/si-units` і перевірити, чи потребує ядро або stdlib знань про SI для базової роботи.
2. **`lib/quantity.lisp` (Точні величини з одиницями)**:
   - *Неоднозначність:* Наскільки щільно `quantity` зв'язаний із точною раціональною арифметикою?
   - *Потрібний експеримент:* Перевірити, чи можуть величини бути реалізовані у просторі користувача як звичайні теговані пари над `Rational`.
3. **`lib/time.lisp` (Календарні розрахунки без системного годинника)**:
   - *Неоднозначність:* Чи місце григоріанському календарю в базовій stdlib, чи ці розрахунки варто делегувати бібліотекам острова Common Lisp?
   - *Потрібний експеримент:* Порівняти швидкодію, footprint та портативність `lib/time.lisp` проти виклику через міст до острова Common Lisp.
4. **`lib/translation.lisp` та `lib/narrate.lisp` (Переклад поверхонь)**:
   - *Неоднозначність:* Чи є переклад між людськими мовними поверхнями функцією мовного координатора, чи це окрема лінгвістична утиліта?
   - *Потрібний експеримент:* Виміряти, чи може координатор повністю оперувати лише 8-бітними SID, здійснюючи трансляцію на людські мови лише на межі відображення/REPL.
5. **`lib/content-store.lisp` та `lib/lisp-fs.lisp` (Контентно-адресовне сховище)**:
   - *Неоднозначність:* Чи повинно незмінне CAS бути примітивом хоста, чи суто Lisp-структурним сховищем даних?
   - *Потрібний експеримент:* Провести бенчмарк збереження SHA-256 CAS на стороні хоста проти S-виразів CAS у чистому Lisp.
6. **`lib/tcp.lisp` та `lib/process.lisp` (Обгортки можливостей хоста)**:
   - *Неоднозначність:* Де саме проходить межа безпеки між кодом мови координації та ізоляційним пісочником хоста?
   - *Потрібний експеримент:* Перевірити обмеження прав та списки блокувань capability-системи в умовах ізольованого виконання.

## 6. Наступні кроки для спрощення ядра (#726, #748, #747)

На основі цього аудиту, зафіксованого у машиночитних даних Lisp:
1. **Пониження пірамідальної логіки (#748):** Винести `lib/reason.lisp` та `lib/forward.lisp` в опціональні пакети; спрямувати запити до `wsm-prolog-kernel` та `wsm-clips-kernel`.
2. **Звільнення бюджету примітивів (#747):** Переконатися, що 10 елементів `semantic-authority` формують замкнене, достатнє ядро без роздування Rust-білтінів.
3. **Очищення репозиторію ядра (#726):** Безпечно вилучити або перенести 10 ідентифікованих файлів `historical-experiment` без ризику семантичної регресії.
