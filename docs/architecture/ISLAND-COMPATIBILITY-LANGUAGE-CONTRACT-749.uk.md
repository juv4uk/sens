# Мовний контракт сумісності з островами виконання (#749)

Англійський оригінал: [ISLAND-COMPATIBILITY-LANGUAGE-CONTRACT-749.md](ISLAND-COMPATIBILITY-LANGUAGE-CONTRACT-749.md).

## 1. Контекст та призначення

Відповідно до ADR-005 та задачі #749 (`[P0][KERNEL-COMPAT-LANGUAGE-1]`), `my-lisp` не вбудовує монолітні рушії міркувань для кожної формальної дисципліни безпосередньо в ядро інтерпретатора. Мова є малим, чесним семантичним і координаційним субстратом, який оркеструє автономні острови виконання:
- **Common Lisp**: багате символьне середовище виконання стандарту ANSI.
- **Prolog**: SLD-резолюція, уніфікація та пошук у глибину з поверненням (backtracking).
- **Datalog**: монотонне замикання нерухомої точки знизу-вгору (fixpoint closure) та реляційні запити.
- **CLIPS**: продукційні правила та активація порядку денного RETE (agenda).
- **Майбутні ядра**: спеціалізовані предметні доказувачі.

Будь-яка мовна можливість оцінюється за тим, наскільки чисто вона компонується з цими автономними островами, не нав'язуючи їм чужої онтології та не руйнуючи межі між різними мовними моделлями.

## 2. Ключові архітектурні інваріанти

### 2.1 Модель ідентичності та виконання

```text
SID -> ідентичність (identity)
ідентичність -> локальне значення Lisp та/або свідки виконання (execution witnesses)
виклик ядра -> непрозорий/нативний результат (opaque/native result)
результат -> звичайні дані my-lisp або явний нативний дескриптор (handle/view)
```

1. **Суверенітет семантичних ідентифікаторів (SID)**:
   Семантичні ідентифікатори належать виключно неперервному 8-бітному реєстру `my-lisp` (`00000000..10100111`) і законам мови. Жодне ядро не володіє і не перенумеровує SID.
2. **Відношення свідка (Witness Relationship)**:
   Ядро є свідком виконання для нуля, одного чи багатьох SID. Вилучення, відсутність або аварія ядра не змінює, не перенумеровує і не скасовує семантичний реєстр `my-lisp`.
3. **Онтологічна автономія**:
   Жодне ядро не примушується до внутрішньої онтології іншого ядра. Prolog працює з підстановками змінних та точками вибору; Datalog — із заземленими кортежами у відношеннях; CLIPS — із фактами робочої пам'яті та спрацьовуваннями правил; Common Lisp — із ANSI S-виразами.
4. **Єдина механічна межа виклику**:
   Уся комунікація через межу відбувається через непрозорий механічний транспорт (`island-exchange` / `island-call` через байти та C-ABI vtables).

## 3. Мінімальний мовний контракт виклику та результату

### 3.1 Зовнішній контракт

Зовнішній контракт виклику визначається як:

```lisp
(island-call target-kernel sid payload-bytes-or-expression [provenance])
  -> (island-result :status <status> :count <n> :items (<item> ...) :raw-payload <bytes>)
```

### 3.2 Множинність відповідей та розрізнюваність

Критична вимога задачі #749 полягає у чесному відображенні спектра кількості відповідей та усуненні неоднозначності між «відповіді немає» і «відповідь є, і це значення ()»:

1. **0 відповідей (Невдача / Недоведеність / Відсутність результату)**:
   - Статус: `:none`
   - Кількість: `0`
   - Елементи: `()`
   - Представлення: `(island-result :status :none :count 0 :items ())`
   - Семантика: Запит зазнав невдачі, ціль недоведена (negation-as-failure), або відповідне відношення порожнє.
2. **1 відповідь (Детерміноване значення / Єдиний розв'язок)**:
   - Статус: `:one`
   - Кількість: `1`
   - Елементи: `(значення)`
   - Представлення: `(island-result :status :one :count 1 :items (значення))`
   - **Важливий інваріант**: Якщо обчислене значення є літеральним порожнім списком `()`, воно представляється як:
     `(island-result :status :one :count 1 :items (()))`
     Це однозначно відрізняє `0 відповідей` (`items ()`) від `1 відповіді у формі порожнього списку` (`items (())`).
3. **N відповідей (Багато розв'язків / Потік / Реляційна множина)**:
   - Статус: `:many`
   - Кількість: `N`
   - Елементи: `(розв-1 розв-2 ... розв-N)`
   - Представлення: `(island-result :status :many :count N :items (...))`
   - Семантика: Множинні підстановки зі зворотного пошуку Prolog, множина виведених кортежів із фіксованої точки Datalog, або множинні спрацьовування правил у CLIPS.
4. **Помилка / Порушення межі**:
   - Статус: `:error`
   - Представлення: `(island-result :status :error :reason "..." :raw-payload ...)`

## 4. Потік даних між островами та містки (Cross-Island Data Flow)

Острови не розділяють внутрішні кучі пам'яті. Коли результат перетікає з Острова A в Острів B:

```text
[Острів A: Datalog]
       |
       | виводить кортежі досяжності
       v
[Координатор my-lisp]  <-- отримує (island-result :status :many :items ((reach a b) (reach b c) (reach a c)))
       |
       | інспектує та форматує звичайні S-вирази
       v
[Острів B: Prolog]     <-- отримує аксіоми + цільовий запит
       |
       | виконує SLD-резолюцію зі зворотним пошуком над фактами Datalog
       v
[Координатор my-lisp]  <-- отримує підтверджений шлях або логічний висновок
```

- **Проєкція у звичайні дані**: S-вирази є спільною мовою `my-lisp`. Дані, повернені одним ядром, розгортаються у звичайні пари та символи Lisp, які можна аналізувати, фільтрувати чи передавати як вхід до другого ядра.
- **Явні дескриптори**: Якщо розмір чи непрозорість вимагають збереження оригінального нативного стану, використовуються явні нативні дескриптори без примусового ламання внутрішньої онтології ядра.
