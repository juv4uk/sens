# Zig — чистий фізичний референс SENS · уточнення 14.10.2026

## Пріоритет чинної мовно-нейтральної доктрини

**Будь-яка мова програмування може застосовуватися до будь-якої задачі.** Це найновіше рішення власника записане в `AGENTS.md` і має пріоритет над колишніми формулюваннями «Zig лише для транспорту», «Python лише для CI» або «Rust лише для виконання». Zig, Rust, Python, Lisp, C/C++, Futhark та інші мови можна використовувати для інтерпретатора, компілятора, семантичних перевірок, GPU/FPGA, міграції, фізичних форматів і будь-якої іншої роботи.

**Чистота Zig — вимога до всіх `*.zig` без обмеження застосування мови.** Zig можна застосовувати до компілятора, інтерпретатора, GPU, FPGA, транспорту чи міграції, однак у жодному Zig-файлі не допускається історична семантична ідентичність SID8/Sens8/Function8/W8, її registry, legacy alias, source-era чи «old W8 ↔ new D8» oracle. Zig працює з чинними ратифікованими D1–D10 координатами та фізичними ширинами, бітами, структурами й кадровими правилами; семантику визначає тільки SENS.

**Перевірена хронологія:** чинний D8 v2 256/256 ратифіковано власником [#3960](https://github.com/juv4uk/sens/issues/3960) 06.10.2026 о 18:37 UTC і закріплено в [cf7011418](https://github.com/juv4uk/sens/commit/cf7011418d1daf583ce7cdfe78f16af74ef66e2c) о 18:55 UTC. До цього сучасної ратифікованої D8-ідентичності **не було**. Історичні плоскі 8-бітові коди не можна заднім числом перевіряти як D8. Можна зберігати їх у поза-Zig архіві provenance, але не в активному old-vs-new CI gate.

## Автоматичний аудит

`scripts/ci_zig_purity.py` механічно сканує **всі git-tracked `*.zig` у всьому репозиторії**, включно з новими Zig-файлами за будь-якими шляхами. Заборонено тільки проникнення історичних кодових ідентичностей/old dispatch; жодна роль Zig не обмежується, жодна нормативна семантика не встановлюється цим сканером. Вивід `ZIG_PURITY_PASS files=N contamination=0` та структурований `sens-zig-purity.json` показують тільки чистоту перевіреної ділянки; не видавати їх за універсальний доказ відсутності всіх помилок SENS.

```bash
python3 scripts/ci_zig_purity.py --self-test
python3 scripts/ci_zig_purity.py --report /tmp/sens-zig-purity.json
```

## Ефективність

Підтверджувати заяви про швидкість, пам'ять, розмір або енергію **бажано** відтворюваними порівняльними бенчмарками з однаковими входами, перевіреним результатом, SHA, інструментарієм, повтореннями та первинними вимірами. Наявні окремо затверджені **обов'язкові парні T5/F3C бенчмарки** залишаються обов'язковими. Інші правильні зміни не блокувати лише через відсутність необов'язкового вимірювання.

**Лише SENS має нормативну владу; всі інші — помічники.** Ратифіковані точні двійкові закони SENS визначають семантику. Zig, Rust, Python чи інша мова можуть допомагати реалізувати, тестувати, компілювати, транспортувати й вимірювати їх без обмеження ролі; жодна реалізація, тестова бібліотека, CI чи benchmark не отримує від цього право встановлювати нові закони SENS. Право ухвалювати нормативні зміни залишається за власником проєкту.

Мова реалізації — вільний вибір. Нормативний закон SENS та достовірність тесту не залежать від мови.

## Типова драбина в Zig — 14.10.2026

Канонічний допоміжний модуль `research/zig-codecs/domain_ladder.zig`
оголошує `DomainWord(comptime width)` для ширин **D1–D10**.
Кожен тип має `packed` поле `@Int(.unsigned, width)`: точна
`@bitSizeOf` відповідає ширині, провідні нулі не зникають.
`DomainWord(1)` та `DomainWord(2)` — **різні типи Zig** навіть
для однакового числового payload. Так само `D8` не визначається
фізичною місткістю байта.

Перехід `toCarrier()` лише явно знімає тип до транспортної
структури `t5.Word { width, bits }`, а зворотний `fromCarrier(width, word)`
відкидає неправильну ширину і вихід бітів за межі домену.
Транспорт не видає функціонального або семантичного дозволу.
`D10` підтримано як механічну координату, **не як виконуваний D9**.

Точкові тести всередині наявного `research/zig-codecs/tests.zig`
охоплюють усі **2046 координат** D1–D10 (сума місткостей),
відмінність типів за шириною, некоректні фізичні значення та
D10 → T5 roundtrip без самовільного розширення допустимості виконання.

Команда для ручної локальної перевірки із закріпленим сумісним Zig:
```bash
zig test research/zig-codecs/tests.zig
```
Не створювати для цього новий GitHub Actions workflow.
Компіляторний тест — технічна перевірка представлення, не мовний оракул SENS.
