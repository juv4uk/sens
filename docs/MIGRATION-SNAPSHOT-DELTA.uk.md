# Вимірювання реального прогресу міграції SENS

Мета: розрізняти **справжню роботу** й зміну формулювання блокера після злиття PR. Це допоміжний безпечний інструмент для [міграційного епіку #4449](https://github.com/juv4uk/sens/issues/4449), а **не** новий компілятор, конвертер, оракул або спосіб отримати дозвіл на публікацію `.sens`.

## Вхідні знімки

Отримуйте канонічні read-only JSON до/після змін тим самим викликом:

```bash
python3 scripts/report_original_migration_candidates.py --out /tmp/sens-before.json
# після вже виконаних перевірених змін у коді / іншому Git worktree:
python3 scripts/report_original_migration_candidates.py --out /tmp/sens-after.json

python3 scripts/diff_original_migration_snapshots.py \
  --before /tmp/sens-before.json \
  --after /tmp/sens-after.json \
  --out /tmp/sens-delta.json
```

Знімки повинні належати конкретним Git-комітам: фіксуйте SHA комітів у PR, CI/artifact metadata й назвах артефактів. Інструмент навмисно **не запускає мігратор** і не переписує `.lisp` чи `.sens`; він порівнює тільки перевірені свідчення.

## Що означають категорії

| Стан | Що відбулося | Чи зараховано нову виконувану `.sens`? |
|---|---|---|
| `FIRST_BLOCKER_CHANGED_NOT_MIGRATED` | Дійшли до наступного блокера на **тому самому source SHA** | **Ні** |
| `MECHANICAL_CANDIDATE_NOT_ORACLE_ADMITTED` | Трипрохідний аналіз допускає байтове пакування | **Ні** |
| `NEW_PAIR_REQUIRES_ORACLE_AND_SOURCE_RECHECK` | Новий same-stem `.sens` з'явився в списку пар, а оригінал виключено з unpaired | **Ні, поки немає доказу історичного та поточного оракула** |
| `NEW_NONPROGRAM_CLASSIFICATION_NOT_MIGRATION` | Документ визначено як DATA/архів, а не програму | **Ні** |
| `SOURCE_BYTES_CHANGED_REVIEW_REQUIRED` | Змінилися байти оригіналу `.lisp` | **Ні; потрібна повторна перевірка та дозвіл** |
| `NEW_SOURCE_NEEDS_ADMISSION` | З'явився новий .lisp | **Ні** |
| `MECHANICAL_CANDIDATE_REGRESSED_TO_BLOCKED` | Дослідний автоматичний прохід тепер блокує джерело | **Ні** |

**Заборона:** джерело не може зникнути зі звіту лише тому, що агент видалив файл чи змінив розширення. Вихідна пара мусить бути зафіксована в канонічному `already_paired_sources_excluded` і окремо доведена в [admit-t5-migration.py](../scripts/admit-t5-migration.py), з точними Git blob-SHA історичного джерела, фізичними T5 байтами, parser/eval і незалежними свідками обох поколінь.

## Структурна безпека

Зчитувач відхиляє підмінений `schema`, звіт із physical outputs, дублікати, небезпечні `../` шляхи, без-SHA рядки, хибні підсумки, зміни у вже спарених файлах без обліку і випадкове зникнення unpaired джерел. Будь-який новий `.sens` як такий є **свідченням існування файла**, але не свідченням семантичної парності.

Вихід має `semantically_admitted_by_this_tool = 0` і `physical_outputs_created = 0`. Він лише допомагає агентам вибрати наступну роботу без змішування структурної D2, транспортної T5-двійковості чи історичної семантики.

## Співпраця агентів

Публікуйте два Git SHA, два незмінні JSON-артефакти, delta JSON та окремі перевірені `SOURCE→T5→ORACLE` записи. Коли перший blocker перейшов у другий, **закривайте тільки той етап, який дійсно усунено**. Потім передавайте файл відповідному агенту, не оголошуючи міграцію всього репозиторію завершеною.
