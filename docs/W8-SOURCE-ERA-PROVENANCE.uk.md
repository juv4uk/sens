# Перевірка походження W8 до ратифікації D8

Це **доказ історії Git**, а не мігратор, не заміна невідомого коду
за схожою назвою і не дозвіл примусово вмикати `--source-era legacy`.

## Проблема

У поточній двійковій мові 8-бітне слово може бути ратифікованим D8.
У старому Lisp/Sens8 ті самі вісім символів могли означати стару SID8
функцію. За однією довжиною слова цього відрізнити не можна. Режим
`auto` навмисно блокує неоднозначність.

Ми можемо отримати **першу незалежну частину доказу** без змін до
мови — незмінний Git blob оригінального файла ще з **30 вересня 2026**,
до ратифікації нинішнього D8. Базовий коміт точно зафіксований:

`3bde35c014a565e1b15999fc3da79a9be8623ea1`
(комітер: 2026-09-30 21:40:48 UTC).

Використовуємо саме Git tree та повні SHA1 blob, а не дати файлів,
припущення щодо текстових назв або час створення останнього PR.

## Перевірка

```bash
git fetch --all --unshallow  # лише коли checkout є shallow
python3 scripts/audit_w8_source_era.py \
  --repo . --out /tmp/sens-w8-pre-d8.json
```

Скрипт бере чинний повний реєстр із `scripts/report_original_migration_candidates.py`,
залишає тільки **оригінальні непарні** `.lisp`, де ПЕРША проблема — W8,
і порівнює кожен Git blob із тією самою адресою у базовому коміті.

Статуси:

- `SAME_BLOB_BEFORE_D8_RATIFICATION` — ті самі оригінальні байти
  документально були в історичному знімку Git.
- `CHANGED_SINCE_PRE_D8_SNAPSHOT` — файл був, але нинішній blob інший.
- `NOT_PRESENT_IN_PRE_D8_SNAPSHOT` — такого шляху у базовому знімку
  не існувало.

JSON містить для кожного джерела назву, точні 8 біт ПЕРШОЇ проблеми,
чинний Git SHA, старий SHA (коли існує) та результат порівняння.
GitHub Actions публікує повний реєстр і підсумок за окремими словами.

## Що ще потрібно для реальної міграції

Навіть `SAME_BLOB` **не доводить**, що старий байт означає конкретну
функцію: у попередніх дослідницьких гілках могла існувати інша семантика.
Необхідно окремо довести історичну SID8 тотожність за контрактом,
відповідність поточному resident D1–D9, роль числа/тексту/локального імені,
правильний T5 та D2 і спостережувану відповідність оракулу.

Тому в цьому звіті для **кожного файла** стоїть
`permission_to_choose_legacy=false`, `historical_legacy_semantics=NOT_PROVEN`,
`executable_semantics=NOT_PROVEN`. Скрипт ніколи не створює
`.sens`, не модифікує `.lisp` і не вважає роботу завершеною.

Ця перевірка прискорює роботу агента #4459: для джерел з незмінним
blob до ратифікації D8 більше не треба повторно доводити саму хронологію;
можна досліджувати **точну функціональну тотожність та поточний оракул**.
