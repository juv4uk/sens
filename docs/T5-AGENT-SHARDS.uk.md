# Як розділити блокування міграції SENS між багатьма агентами

**Робоча домовленість власника:** `name.lisp → name.sens`, фізичний T5 (п'ять тритів на байт), логічна `2` **тільки між словами**, EOF файла без `22`. Джерело лишається незмінним. D2 зберігає монополію на структуру, а файловий кодек не стає мовною семантикою.

## Один канонічний список → незалежні робочі ділянки

```bash
# Читає тільки оригінальні ще НЕ парні .lisp, без генерування .sens:
python3 scripts/migrate.py candidates --report /tmp/sens-candidates.json

# Планувальник НЕ виконує перекладу/запису .sens і нічого не призначає сам:
python3 scripts/plan_t5_agent_work.py \
  --candidates /tmp/sens-candidates.json \
  --out /tmp/sens-agent-shards.json \
  --max-files 20
```

План перевіряє повний JSON канонічного звіту, режим `source_era=auto`, нуль фізичних публікацій, відповідність сум, Git-blob SHA-1 для **кожного** вихідного файла й відсутність вже парних `.sens`. План із пошкодженими або повторними шляхами **відхиляється**. Кожне джерело належить рівно одній ділянці. Ділянки групуються за класом першого блокування (наприклад, W8 provenance, I/O `print`, D2/data, локальна лексика) і розрізаються на контрольовані пачки; окремі механічні кандидати потрапляють у `oracle-pending`, а **не** в успішні програми.

Файл плану має вигляд:

```json
{
  "schema": "sens-t5-disjoint-agent-workshards/v1",
  "mode": "NO_WRITE_NO_AUTO_ASSIGN_NO_ORACLE_CLAIMS",
  "summary": {"original_unpaired": 490, "blocked": 490, "mechanical_pending_oracle": 0},
  "shards": [
    {
      "shard_id": "w8-provenance-001",
      "family": "w8-provenance",
      "status": "UNCLAIMED__BLOCKED_NOT_ADMITTED",
      "claimed_by": null,
      "input_sources_sha256": "контрольний SHA256 точних path + Git blob SHA",
      "next_action": "довести історичний source-era",
      "sources": [
        {"path": "каталог/вихідний-файл.lisp", "source_git_blob_sha": "Git SHA-1"}
      ]
    }
  ]
}
```

Це **приклад схеми, не знімок реальних кількостей**. Точні числа залежать від актуального commit GitHub і перегенеровуються командою. `input_sources_sha256` є хешем списку, **не** доказом семантики.

## Агент бере лише одну ділянку

1. Залишає коментар `CLAIM: shard_id / repo=juv4uk/sens / owner=агент / branch=гілка / PR=...` у [#4449](https://github.com/juv4uk/sens/issues/4449). **Скрипт навмисно не роздає CLAIM автоматично** і не зв'язується з GitHub.
2. Перед будь-яким редагуванням звіряє Git blob SHA кожного `.lisp` з маніфестом; якщо хтось змінив джерело або вже створив `.sens`, оновлює план замість перезапису.
3. Класифікує: архів/таблиця/бенчмарк/негативний тест чи справжня виконувана програма. Не кожне `.lisp` треба компілювати.
4. Доводить source-era (`auto` не вгадує W8), exact successor, D2 grammar, Text7/host effect за необхідності. Для `oracle-pending` потрібен незалежний source/observable oracle.
5. Лише після доказу створює **новий** same-stem `.sens` канонічним інструментом із точними `0/1` словами, фізичною `2` між ними, байтовим EOF. Додає negative controls і фізичний/typed SHA.
6. Власний PR містить перелік перевірених джерел, Git SHA, парні фізичні файли, Rust oracle evidence, тести й залишені BLOCKED. Ніякого `git rm master` або масового авто-merge.

## Чому це прискорює роботу

Усі агенти перестають сперечатися за єдиний великий список «майже 500 заблокованих»: кожен отримує **взаємовиключну**, прив'язану до Git обмежену чергу й одну конкретну причину блокування. Код *не стверджує*, що «майже 500» є виконуваними SENS-програмами. Зменшення кількості BLOCKED — це індикатор, **не доказ готовності релізу**.

Промисловий реліз перевіряється окремо в [#3915](https://github.com/juv4uk/sens/issues/3915), [#4449](https://github.com/juv4uk/sens/issues/4449) та задачах фізичного T5/оракула. Сам планувальник не має права ані змінювати первинні файли, ані вигадувати відсутній закон мови.
