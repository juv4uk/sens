# Поверхні інтерактивного REPL

`my-lisp` має одне семантичне ядро й три рівноправні людські програмні поверхні: англійську, українську та санскритську. `core` є канонічним машинним шаром для налагодження й сумісності, а не четвертою людською мовою.

Ключове рішення за [ADR-005](adr/ADR-005-TRILINGUAL-SURFACE-PARITY.md): **core is not English**. Те, що багато англійських назв сьогодні збігаються з канонічними ідентифікаторами, не надає англійській поверхні вищого семантичного статусу.

Перемикання поверхні є політикою REPL, а не новою Lisp-семантикою і не зміною `language-contract.lisp`.

## Чинний точнодоменний коридор SENS

У новому REPL вихідний `.lisp` пишеться **українською проєкцією**.
Слово фізичного кодека — це **(домен, точні біти)**, а не англійський
символ. Zig може перенести й перевірити це слово та T5-байти, але не
вибирає людську назву.

```text
Українське джерело .lisp → SENS: точний домен + біти → Zig: T5/байти
Zig: T5/байти → SENS: точний домен + біти → SENS: таблиця lib/domains/d*.lisp → ук
                                               └→ LISP/інші поверхні лише за явним вибором
```

Наприклад: `D3:001 → як-є`, `D4:0010 → функція`,
`D4:0011 → визначити`. За тією самою таблицею можна **окремо** показати
історичну колонку `LISP` (`QUOTE`, `LAMBDA`, `DEFINE`), але перетворення
`LISP → українська` **не є обов’язковим і не повинно бути проміжним
етапом**. Обидві назви — незалежні проєкції **одного точнодоменного слова**.
Однаковий числовий payload при різній ширині не дозволяє вибирати назву
без домену. Відсутня назва залишається непідтвердженою, не вигадується.

У поточній реалізації дані для `render_value_for_presentation` беруться
із згенерованої проєкції ратифікованих `lib/domains/` таблиць.
Тест `ukrainian_repl_domain_words_are_consumed_by_zig_without_width_loss`
звіряє шлях після фізичного Zig T5-декодування без англійського посередника.
Він не доводить повного відновлення програмного тексту з довільного T5 і
не робить старий byte-SID каталог нижче авторитетом над D3/D4.

## REPL читання D1–D10 мовою SENS/Lisp

Функції `репл-цикл-доменів`, `репл-доменний-рядок`,
`репл-читати-слово-з-доменом`, `репл-доменна-черга` написані
самим **SENS/Lisp, українською проєкцією**. Читач приймає
**1–10 буквальних бітів** як рядок. Він не користується десятковим
посередником і не відкидає провідних нулів.

Наявний `прочитати` поки не матеріалізує всі голі D10-токени
як типізовану машинну `DomainIdentity`, тому у живому терміналі
кожне слово вводиться **в лапках**, наприклад:

```lisp
(репл-цикл-доменів)
"0"
"001"
"0010"
"000000000"
"0100111111"
"0102"
(репл-завершити)
```

Після кожного прийнятого рядка повертається Lisp-запис
`(дN "0" "1" ...)` — `д1`…`д10` є структурною **міткою ширини**,
а кожен наступний елемент — початковий бітовий знак. Наприклад,
`"0010"` стає `(д4 "0" "0" "1" "0")`, тоді як
`"0100111111"` має мітку `д10`. Відсутній, зайвий або не-бітовий
знак повертає `(неправильне-доменне-слово)`.

Для відтворюваної перевірки без термінала:

```lisp
(репл-доменна-черга (як-є ("0" "00" "000" "0000" "00000"
                            "000000" "0000000" "00000000"
                            "000000000" "0000000000")))
```

Результатом є послідовність десяти позначених записів без відхилення
початкових нулів. `репл-мітки-черги?` здійснює суто мовне зіставлення
з `репл-доменні-позначки`. Наявний нативний SENS-свідок черги
перевіряє також D9 проти D10, надлишкову довжину й сторонні символи;
негативний свідок змінює рівно один біт D1.

**Чесна межа:** такий запис не є машинною ідентичністю D10,
не виконує D10-функцій і ще не робить повний T5 decoder → typed D10
→ українська назва із доменної таблиці. Таблиці `lib/domains/d1.lisp`
… `d10.lisp` лишаються єдиним авторитетом назви; їхні назви
не виводяться з міток `дN`. Необхідні ще typed D10 ingress,
наскрізне фізичне читання через Zig для живого вводу, ознака EOF,
негайний flush і відновлення після синтаксичної помилки.
Тут не додається жодна реалізація семантики в Rust або Zig.

## Мовний REPL для всіх поверхонь драбини D1–D10

`lib/repl-core.lisp` визначає **сам SENS/Lisp**: одну функцію
`репл-перехід-поверхні` використовують і живий
`репл-цикл-поверхонь`, і детермінований
`репл-пройти-поверхні`. Команда `репл-мова` змінює лише
проєкцію результату; лексичне оточення та точнодоменні коди не змінюються.

Після завантаження **справжнього** каталогу з
`lib/domains/d1.lisp` … `lib/domains/d10.lisp`:

```lisp
(репл-мова ук)
(репл-код д4 функція)
(репл-слово д4 (ні ні так ні))
(репл-мова укр)
(репл-код д4 функція)
(репл-мова san)
(репл-код д4 phalana)
(репл-мова en)
(репл-код д4 lambda)
(репл-мова LISP)
(репл-код д4 LAMBDA)
(репл-мова sym)
(репл-мова ук)
(репл-завершити)
```

Команда `репл-слово` читає список **імен D1** `ні`/`так`:
точні біти одержує через українську колонку реальної таблиці D1,
перевіряє заявлену ширину й показує назву через вибрану поверхню.
Якщо немає D1-таблиці, бітів або потрібної ширини, читання
відмовляє; воно не перетворює D10-слово на виконувану функцію.

Це **іменований** вхід без машинних літералів: `репл-код` явно
отримує домен і поверхню, шукає відповідний запис у SENS-таблиці
та повертає код **як дані**, а не автоматично виконує його. Порожня
проєкція `sym` не вигадує імені. Для перевірки коректної форми
всіх десяти записів перед початком є `репл-повний-каталог?`;
порядок записів канонічний D1→D10, дубль/пропуск блокуються.
SENS додатково перевіряє місткість кожної таблиці через подвоєння
структурних комірок: D1, D2, …, D10; порожній каталог не допускається.
**Це контроль заголовків і місткості, а не доказ унікальності
чи бітової коректності всіх його рядків.**

**Поточне обмеження:** `репл-запустити-поверхні` отримує вже
прочитаний каталог. Самостійне завантаження десяти файлів через
фізичний Zig-коридор, термінальне EOF та повне типізоване читання
довільних сирих D10 токенів ще не доведені. Дослідний читач
текстових бітів не стає runtime D10-identity. Не плутати
підтримку назв усіх поверхонь із повним виконанням D1–D10.

## Єдиний REPL з явним доменом

У SENS є **один Lisp-цикл**, `репл-цикл-поверхонь`. Його чинні
публічні посилання — `репл-цикл` та `репл-цикл-доменів`; останнє
починає з перевірки повного каталогу D1–D10. Джерело й усі визначення
пишуться українською проєкцією, навіть коли REPL показує іншу поверхню.
Zig переносить точні коди фізично і не вирішує значення слів.

```lisp
(репл-мова ук)
(репл-слово д4 (ні ні так ні))
(репл-код д4 функція)

(репл-мова san)
(репл-слово д4 (na na ām na))

(репл-мова en)
(репл-слово д4 (no no yes no))

(репл-мова LISP)
(репл-слово д4 (NIL NIL T NIL))

(репл-мова укр)
(репл-код д4 функція)
```

У всіх прикладах одна і та сама **D4:0010**, але D1-імена
беруться з колонки *обраної поверхні* в `lib/domains/d1.lisp`.
Режим `sym` також можна обрати; порожнє `sym` для бітів D1
не дозволяє вигадувати символічні назви. Можна користуватися
`репл-код` із наявними символічними проєкціями інших доменів.

Сирий рядок `"0010"` — **текстові дані**, не команда виклику
домену: ніякого неявного підняття бітових літералів. Для назв потрібен
явний домен, для точних бітів — явна команда `репл-слово` і
ратифіковані назви D1. Відсутні, неоднозначні чи не допущені до
виконання координати не стають викличними.

**Стан інтеграції:** для запуску потрібен попередньо перевірений
каталог усіх десяти доменів. Нативне читання сирих каталогів
`lib/domains/d1.lisp`…`d10.lisp` ще потребує доказу збереження
початкових нулів: звичайний текстовий reader не є автоматично
точнодоменним парсером. Це не свідчення повного terminal/EOF GO.

## Швидко

Типово CLI та Web REPL запускаються з повною українською проєкцією `укр`. Компактну `ук` можна вибрати явно командою `:мова ук` або `--surface=uk`.

```text
my-lisp[укр]> (атом? 'мама)
істина

my-lisp[укр]> :мова en
Поверхня: англійська (en)

my-lisp[en]> (atom 'мама)
t

my-lisp[en]> :мова sa
Поверхня: санскрит (sa)

my-lisp[sa]> (ādi (saṃyuj 10 20))
10
```

Доступні режими:

```text
:мова en       англійська людська поверхня
:мова ук       компактна українська людська поверхня
:мова укр      повна українська peer-поверхня
:мова sa       санскритська людська поверхня
:мова core     канонічний машинний шар
```

Технічний alias має ту саму поведінку:

```text
:surface en
:surface uk
:surface ukr
:surface sa
:surface core
```

## Інтроспекція поверхонь

Native REPL розрізняє людський словник і реальне лексичне середовище:

```text
:імена                 каталог поточної людської поверхні
:names                  той самий технічний alias
:ім'я <назва>           одна semantic identity у EN / UK / UKR / SA
:name <name>             той самий технічний alias
:поверхні                матриця завершеності EN / UK / UKR / SA
:surfaces                той самий технічний alias
```

Ці команди перехоплює інтерактивна оболонка до парсингу Lisp-коду. Вони не є спеціальними формами, примітивами або частиною `language-contract.lisp`.

### `:імена`

Каталог читається з одного машинного реєстру поверхонь. Для санскриту він чесно показує не лише ратифіковані `stable` назви, а й `candidate` та `missing`: кандидат позначається `~`, а відсутня назва — `—{numeric-identity}`. Таким чином каталог не видає дослідницьку назву за завершений API.

Поточна виміряна картина:

```text
UK  stable 140 · candidate 0  · missing 0
EN  stable 131 · candidate 0  · missing 9
SA  stable 36  · candidate 88 · missing 16
```

Ще 21 ряд у кожній поверхні належить до `compatibility-only` і не входить до вибраного 140-іменного публічного знаменника.

### `:ім'я`

Назву можна подати будь-якою з чотирьох людських поверхонь. Наприклад усі ці запити знаходять ту саму semantic identity:

```text
:ім'я map
:ім'я відобразити
:ім'я āvartana
```

Результат показує три поверхні поруч:

```text
identity: 0101
  UK: відобразити [stable]
  EN: map [stable]
  SA: āvartana [candidate]
```

Це принципова модель: `відобразити` й `āvartana` не є семантично залежними «перекладами англійського map»; усі три людські назви посилаються на одну канонічну тотожність.

### `:поверхні`

Команда показує release-parity без прикрашання стану:

```text
Рівноправність людських поверхонь · public identities: 140 · shared symbolic identities: 18
UK  stable 140 · candidate   0 · missing   0 · compatibility  21
EN  stable 131 · candidate   0 · missing   9 · compatibility  21
SA  stable  36 · candidate  88 · missing  16 · compatibility  21
trilingual stable: 29/140
release parity: OPEN
```

Повний тримовний статус можна буде назвати `CONFIRMED` лише коли всі 140 translation-eligible identities матимуть stable EN, UK і SA назви та відповідні виконувані докази.

## Публічна поверхня і реальне середовище — різні речі

```text
:env
:середовище
```

Це **діагностичні REPL-команди**, а не мовні форми: вони показують реальні видимі лексичні прив'язки з `Environment::snapshot` без фільтрації поточною поверхнею. Складні/непрозорі значення позначаються типами; команда не обчислює форм і не надає нових capability. Вони можуть одночасно містити канонічні імена, назви кількох поверхонь, сумісні aliases, бібліотечні helper-и та користувацькі визначення.

`(env)` / `(середовище)` залишаються **нереалізованими мовними викликами D10**: запис у каталозі домену не робить тотожність викликаною. Поки SENS-визначення для цієї тотожності не ратифіковане і не завантажене, така форма має відхилятися, а не тихо обходитися Rust-рефлексією.

Це навмисно не те саме, що `:імена`:

```text
:імена
    → чим людині писати на поточній поверхні

:env / :середовище
    → які зв'язування реально доступні lexical lookup (лише інспекція)
```

Тому, наприклад, одночасна видимість `atom` і `атом?` у сирому середовищі не означає дві реалізації й не порушує українську поверхню.

## Чому перемикання не губить роботу

REPL тримає три шари середовища:

```text
базове семантичне середовище
            ↓
вибрана людська surface
            ↓
користувацькі визначення
```

При `:мова ук → :мова укр → :мова en → :мова sa` замінюється лише середній layer. Верхній user-frame лишається тим самим, тому введені визначення та вже створені closures не відкидаються.

`uk` і `sa` не створюють паралельних реалізацій операцій. `lib/surface/uk.lisp` та `lib/surface/sa.lisp` прив'язують людські імена до вже наявних визначень і канонічних тотожностей.

## Машинні джерела

Єдина машинна authority для surface correspondence — [`lib/surface/semantic-registry.lisp`](../lib/surface/semantic-registry.lisp). Її semantic identities складаються тільки з цифр; UK/EN/SA є людськими surface rows, а спільна пунктуація живе окремо в `sym`. Історична [`lib/surface/uk-sa-coverage.lisp`](../lib/surface/uk-sa-coverage.lisp) лишається аудитом походження назв і не живить REPL introspection.

Українська вже має окремий повний документаційний індекс [`lib/surface/uk-docs.lisp`](../lib/surface/uk-docs.lisp), тому `:ім'я` в режимі `ук` може додатково показати категорію, тип, форму виклику та український опис. Повноцінні EN/SA docs-index-и є окремою частиною майбутнього release-parity доказу.

Виконуваний структурний gate:

```bash
python3 scripts/check_trilingual_surface.py
```

Строгий майбутній release gate:

```bash
python3 scripts/check_trilingual_surface.py --require-complete
```

Другий навмисно завершується помилкою, доки триєдина surface не справді завершена.

## Запуск одразу з потрібною поверхнею

```bash
my-lisp
my-lisp --surface=ukr
my-lisp --surface=uk
my-lisp --surface=en
my-lisp --surface=sa
my-lisp --surface=core
```

`--surface` належить інтерактивному REPL. Виконання `.lisp`/`.lisp`/`.lisp` файлів не отримує прихованої мовної політики від цього прапорця.

## Web REPL

Автономний Web REPL стартує з повною українською поверхнею `укр` і підтримує перемикання між `ук`, `укр`, `en`, `sa` та `core` над тією самою сталою WASM-сесією. Користувацькі визначення не replay-яться й не відкидаються.

Каталог `:імена` / `:ім'я` / `:поверхні` у цьому зрізі належить native REPL; web-REPL не вдає parity цієї interaction-функції, доки той самий registry не під'єднано там.

## Людське подання результатів

Українська surface вже має двостороннє presentation: локалізує системне подання значень і діагностик без зміни canonical `Value::Display`.

```text
my-lisp[укр]> (атом? 'мама)
істина

my-lisp[укр]> (перше 5)
Помилка типу: перше очікує непорожній список
```

Санскритський presentation шар ще не має такого самого рівня завершеності; це одна з причин, чому ADR-005 не дозволяє називати поточний стан повною тримовною release parity лише на підставі наявності багатьох SA aliases.

Ключовий принцип: **одна семантика, чотири рівноправні людські поверхні, окремий canonical core, чесна сира інтроспекція й вимірювана тримовна завершеність.**
