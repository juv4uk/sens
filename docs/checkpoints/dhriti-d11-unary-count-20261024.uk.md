# Dhṛti · D11 SRFI-1 unary count · 24.10.2026

## Первинний дефект

Початкові `порахувати-за-умовою-унарно` та `порахувати-пари-за-умовою-унарно` завершували обчислення на `порожній?`, але не затверджували структурної правильності всіх вхідних списків до обчислення предиката. Другий випадок міг мовчки прийняти неправильний хвіст довшого аргументу, якщо інший завершувався раніше.

## Виправлення винятково мовою SENS

- `правильний-список-для-підрахунку?` повертає D1 так тільки для скінченного D3 ()-завершеного списку.
- Публічні функції перевіряють всі аргументи, перш ніж викликати предикат або коротко замкнути підрахунок.
- На неправильному списку виконується `(перше ні)`, щоб саме SENS/D3 відхилив значення як Type, а не повернув частковий результат.
- Внутрішні `*-ядро` обробляють тільки перевірені структури; двосписковий підрахунок зупиняється на коротшому правильному списку.
- Унарне число — список D1 так; ніяких D24-літералів, нових машинних координат чи семантики Rust/Python/Zig.

SENS тут свідомо обмежено скінченними правильними списками. Оригінальний SRFI-1 `count` допускає також випадки із циклічним аргументом за умови існування скінченного; ця бібліотечна адаптація **не** стверджує повної тотожності SRFI-1.
