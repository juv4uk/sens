# Контрольна точка Sūtradhāra · 24.10.2026 · D1–D12+

## Обсяг, що перевірений цього ходу

- `main`, без створення гілок. Код зміни — **лише SENS/Lisp**.
- `lib/domains/d1.lisp`: 2 ратифіковані однобітні істиннісні значення; не два виклики.
- `lib/domains/d2.lisp`: 4 структурні коди для читача; не чотири функції.
- `lib/domains/d3.lisp`: 8 значень, серед них порожня структура та QUOTE, ATOM, CDR, CAR, EQ, COND, CONS.
- `lib/domains/d4.lisp`: 16 операторів/похідних операцій, включно з NULL (0101), LAMBDA, DEFINE, APPLY, EVAL.
- `lib/domains/d5.lisp`: 32 ратифіковані адреси. Наявність адреси окремо від свідка виконання.
- D6–D9: ратифіковані доменні каталоги (64/128/256/512 адрес); D7 — **текстові дані**, не виклики функцій.
- D10: **1024/1024** ратифікований каталог; за директивою власника всі функціональні резиденти повинні виконуватися. Показник незалежно доведених фізичних викликів цим ходом **не встановлено**.
- D11: бібліотечні визначення та кандидати, не підміняють ратифіковану семантичну таблицю D10.
- D12: за власницьким актом 24.10.2026 **перший точний числовий домен**; окремий runtime/transport-допуск не підтверджено.

## Першопричина, яку виправлено

Файл `lib/d11-srfi1-filter-map.lisp` виконував
`((атом? елементи) (як-є ()))` для **будь-якого** атома, не лише для
структурного порожнього списку D3:000. Для неправильної пари
`(сполучити (як-є збережено) (як-є сторонній-хвіст))` рекурсія
мовчки завершувалася і повертала частковий результат. Це порушує
контракт **скінченного правильного списку**.

Зміна: `порожній?` D4:0101 визначає єдиний нормальний базовий випадок;
інший атомний хвіст відхиляється викликом невикличного D1:ні;
непорожня пара обробляється попереднім рекурсивним законом D3 CONS/CAR/CDR.
Функціональних адрес не додано; Rust/Python не використовуються як
носії нової мовної семантики.

## Докази і невизначеність

- Повторно прочитано всі три файли з `main`: обидва негативні входи
  та бібліотека мають збалансовані дужки з урахуванням коментарів і рядків.
- Перевірено, що небезпечного базового випадку більше немає.
- **NATIVE_SENS_POSITIVE=NOT_VERIFIED** на поточному HEAD.
- **NATIVE_SENS_NEGATIVE=NOT_VERIFIED** на поточному HEAD.
- `scripts/verify-d11-staged-t5m.sh` охоплює позитивний бібліотечний
  сценарій, але два нові негативні входи **не приєднані до автоматичного
  фізичного CI**. Статичні перевірки НЕ дорівнюють виконанню SENS.
- Фізичний D12 і повний D10 не оголошені виконаними без свідків.

1. Виконати обидва негативні файли **справжнім SENS** після підключення
   `lib/d11-srfi1-filter-map.lisp`; вимагати помилку невикличного D1,
   а не undefined-symbol, parse error або мовчазний список. Додати
   їх до цільового фізичного CI як expected-rejection, не робити масових
   перезапусків червоних workflow.
2. У цьому самому SHA прогнати поточний позитивний сценарій
   `lib/d11-srfi1-filter-map.lisp` через SENS → Zig/T5M → SENS.
   Зберегти команду, SHA, вхід, очікуване і фактичне.
3. Перевірити **D5:01000 нуль?**, **D5:01001 число?** та арифметичні
   D5:01010, 01011, 10110, 10111 на ратифікованому D12; не
   підміняти D12 старим D24-профілем і не змінювати закон власника.
4. Провести міждоменні позитивні/негативні свідки
   D3 ATOM/CAR/CDR/CONS → D4 NULL/LAMBDA/EVAL → D5 операції →
   D8 `однакові?`, зокрема `D1:ні ≠ D3:()`, неправильні списки,
   текст D7 проти числових D12 об'єктів.
5. Після фактичних запусків створювати вузькі SENS-виправлення
   конкретних відсутніх механізмів, з точними Dn:біти,
   позитивними/негативними свідками і SHA. Заборонено називати
   `NOT_VERIFIED` «невиконуваністю» або «PASS».
