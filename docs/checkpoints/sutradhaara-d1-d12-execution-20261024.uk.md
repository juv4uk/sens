# Контрольна точка Sūtradhāra · 24.10.2026 · D1–D12+

## Обсяг, що перевірений цього ходу

- `main`, без створення гілок. Код зміни — **лише SENS/Lisp**.
- `lib/domains/d1.lisp`: 2 ратифіковані однобітні істиннісні значення; не два виклики.
- `lib/domains/d2.lisp`: 4 структурні коди для читача; не чотири функції.
- `lib/domains/d3.lisp`: 8 значень, серед них порожня структура та QUOTE, ATOM, CDR, CAR, EQ, COND, CONS.
- `lib/domains/d4.lisp`: 16 операторів/похідних операцій, включно з NULL (0101), LAMBDA, DEFINE, APPLY, EVAL.
- `lib/domains/d5.lisp`: 32 ратифіковані адреси. Наявність адреси окремо від свідка виконання.
- D6–D9: ратифіковані доменні каталоги (64/128/256/512 адрес); D7 — **текстові дані**, не виклики функцій.
- D10: **1024/1024** ратифікований каталог; за директивою власника всі функціональні резиденти повинні виконуватися. Показник незалежно доведених фізичних викликів цим ходом **не встановлено**.
- D11: бібліотечні визначення та кандидати, не підміняють ратифіковану семантичну таблицю D10.
- D12: за власницьким актом 24.10.2026 **перший точний числовий домен**; окремий runtime/transport-допуск не підтверджено.

## Першопричина, яку виправлено

Файл `lib/d11-srfi1-filter-map.lisp` виконував
`((атом? елементи) (як-є ()))` для **будь-якого** атома, не лише для
структурного порожнього списку D3:000. Для неправильної пари
`(сполучити (як-є збережено) (як-є сторонній-хвіст))` рекурсія
мовчки завершувалася і повертала частковий результат. Це порушує
контракт **скінченного правильного списку**.

Зміна: `порожній?` D4:0101 визначає єдиний нормальний базовий випадок;
інший атомний хвіст відхиляється викликом невикличного D1:ні;
непорожня пара обробляється попереднім рекурсивним законом D3 CONS/CAR/CDR.
Функціональних адрес не додано; Rust/Python не використовуються як
носії нової мовної семантики.

Коміт виправлення:
`dd3425bd23f460f0219628e383d92322207aa083`.
Негативні SENS-входи:
- `tests/fixtures/d11-filter-map-improper-tail-must-error.lisp`;
- `tests/fixtures/d11-filter-map-atom-input-must-error.lisp`.

## Продовження Dhṛti · D11 list= · 24.10.2026

**Аватар:** Dhṛti (धृति) — непохитна перевірка законів D1/D3/D4.
**Подяка:** Sūtradhāra за попереднє відхилення некоректних списків
у `filter-map` і `group-by`; цей хід продовжив той самий інваріант.

### Факт і першопричина

Офіційна специфікація SRFI-1: list= працює **лише** з правильними
скінченними списками (неправильний аргумент є помилкою). Старий
`lib/d11-srfi1-list-equality.lisp` міг повернути D1:ні для
неправильного лівого/правого списку за ранньої розбіжності довжин;
`усі-списки-рівні-за-порівнянням?` міг повернути D1:так для
єдиного неправильного вкладеного списку, або D1:ні на першій
нерівній парі, не помітивши пошкоджений третій список.

### Реальне виправлення: `cd2fbb13ac15613fbaa4eea0bcecc93d82c5c7de`

У `lib/d11-srfi1-list-equality.lisp`:
1. `правильний-список-для-рівності?` — D4 порожній? для D3:000,
   D3 атом? для іншого атома, D3 решта для рекурсії.
2. `правильні-списки-для-рівності?` — перевіряє структуру зовнішнього
   переліку і кожного внутрішнього списку до порівняння.
3. `списки-рівні-ядро?` та `усі-списки-рівні-ядро?` — єдиний
   внутрішній алгоритм порівняння вже валідних аргументів.
4. Існуючі публічні `списки-рівні-за-порівнянням?` та
   `усі-списки-рівні-за-порівнянням?` зберігають назви,
   приймають тільки валідні списки та явно відхиляють інші.
5. Валідація одного списку **лінійна**, не повторюється на кожному
   рекурсивному кроці порівняння. Порівнювач не викликається при
   нулі/одному списку. Нових координат D11 немає.

Код зміни — виключно SENS; без іншого семантичного інтерпретатора.
Форма джерела не обіцяє обробки циклічних списків: це окреме
обмеження чинного контракту скінченних даних.
