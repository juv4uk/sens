# Kārya · 24.10.2026 · Racket/boot: точні правильні списки SENS

## Першопричина
У чинній `racket/boot/core.lisp` п'ять рекурсивних функцій `довжина-до`, `зворот-до`, `відобразити-до`, `відсіяти-до`, `згорнути` завершувалися на `(атом? значення)`. Це означало, що D1 `ні`, текстовий атом або неправильний хвіст пари могли тихо інтерпретуватися як порожній D3 список. Це незалежний залишковий борг bootstrap і не дублює зміни `lib/core4.lisp`, які в цей самий час виконували інші агенти.

## SENS-рішення
Для кожної з п'яти функцій спочатку перевіряємо `атом?` D3. Якщо так, використовуємо `тотожне?` тільки над двома атомами — поточним значенням та структурним `(як-є ())`. Лише точна атомна тотожність з `()` завершує обхід; для іншого атома SENS виконує `(перше (як-є ()))`, що має підняти D3 Type. Пари проходять попереднє рекурсивне тіло. Ратіфіковані D1–D12+ адреси, сигнатури, алгебра підрахунку, обернення, відображення, відбору і згортки не змінюються.

## Технічний доказ і стан
Вхідний GitHub blob зафіксовано до змін, п'ять цільових визначень замінено точно по межах форм; усі дужки SENS збалансовані, визначення унікальні. `STATIC_SOURCE=CHECKED`; `NATIVE_SENS_POSITIVE=NOT_VERIFIED`; `NATIVE_SENS_NEGATIVE=NOT_VERIFIED`; `PHYSICAL_T5M=NOT_VERIFIED`; `RELEASE=NO-GO`.

Потрібні мінімальні справжні SENS-свідки для кожного оператора: порожня структура, правильний список із двох елементів, ненульовий початковий акумулятор і неправильний хвіст `(сполучити так ні)`. У негативі очікується Type D3 `car expects a non-empty list`; `UnknownSymbol` або parser error не є доказом. Позитив перевіряє D1:ні ≠ D3:(). Вхід має бути обчислений з визначеннями `racket/boot/core.lisp`, без підміни його виконання host-інтерпретатором.

## Контекст CI

Паралельні агенти вже переписали визначення D5 у `lib/core4.lisp` та `lib/core4-parts/core4-language.lisp` на точний атомний D3 EQ. Цей чекпоінт не оголошує їхні нові тестові результати і не претендує на перевірку цієї окремої помилки. У даному коміті змінюється лише незалежне bootstrap-дзеркало.
