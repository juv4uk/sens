# Sūtradhāra · Контракт 12.0 · джерельний guard · 25.10.2026

## Аватар і спадкоємність

**Sūtradhāra (सूत्रधार)** утримує межу між мовним контрактом, машинною тотожністю та доказом виконання. Подяка команді Contract 12.0 за ратифікацію D1/порожнього D3 та бінарної доменної тотожності; цей крок виправляє форму запису версії, не змінюючи семантичних законів.

## Виявлена першопричина

Hosted CI на SHA `a971c7051a9a42647c717b2f2eafac437ac862ba`,
run [40152687796](https://github.com/juv4uk/sens/actions/runs/40152687796),
відхиляв нові SENS-файли контракту чинним `scripts/check_no_encoded_source_literals.py`:

- `contracts/language-contract-12.lisp:14` — числова голова `12` у формі версії;
- той самий рядок — числовий атом `0`;
- `language-contract.lisp:48` — числовий атом `0` у записі minor.

Це був справжній порушений інваріант вихідного коду: чинний guard навмисно забороняє вводити нові числові source literals у живі Lisp-форми. Послаблювати guard або додавати для контракту виняток було б неправильно.

## Виправлення у main

1. `42214aeee50c1a127e37798e44eea884e35b6100` — у канонічному `contracts/language-contract-12.lisp` версія тепер подана як рядкові метадані `"12.0"`, а не як обчислювана пара `(12 0)`.
2. `c1c1d4aa84f23b1666f30d1abd35fd5cfc1ff1ef` — у кореневому `language-contract.lisp` збережено поля `major` і `minor`, але їхні значення записано текстовими мітками `"12"` і `"0"`. Некваліфіковані числа не використовуються як викликані значення чи машинні коди.
3. Уточнення не змінює D1: двохзначну множину предикатних відповідей, D3:000 як структурний порожній список, межі COND, точний D12+ числовий домен чи правила зняття SID8/Sens8/Function8.
4. Нові D11 opcode, доменні координати чи compatibility fallback не додавалися; старий guard залишається незмінним.
