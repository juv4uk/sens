## D1–D12+: точна межа статусів

- **D1–D5:** базова істина, керування, структура, форми та арифметичні операції мають наявні SENS-закони й свідки. Статус кожного конкретного маршруту визначати за точним результатом direct/paired/standalone, а не за самим існуванням тестового файла.
- **D6–D10:** таблиця ратифікує тотожність, але це не автоматичний дозвіл виклику. `knowledge/d6-mechanism-ledger.json` відображає лише пряме exact-D6 admission (`4/64` на прочитаному blob), а не кількість функцій, визначених як звичайні SENS-замикання. Не позначати решту ні `CALLABLE`, ні `UNEXECUTABLE` без конкретного свідка. D10-таблиця має 1024 ратифіковані тотожності; сама місткість не доводить виконання кожної функції.
- **D11:** це місце для нових похідних функцій, якщо їх немає в ратифікованій D1–D10 драбині. Не створювати нових координат для дубля `відобразити`, `згорнути` чи іншої наявної функції.
- **D12+:** це числова драбина, а не пул функціональних opcode: D12, D24, D48, D96, D192… Числова ратифікація не є доказом фізичного виконання. `source_projection.rs` залишає загальний мінімум D24 для сумісності; явний D12-first маршрут існує окремо в `sens-math-t5m`. Typed Zig профіль `research/zig-codecs/numeric_domains.zig` на читаному зрізі ще описує D24/D48/D96/D192, отже його не називати D12-підтвердженим.

## Першопричини, які потрібно закрити

1. Прочитати hosted CI для актуального `main` після останніх F6/D9 змін. Якщо F6 досі RED — відтворити саме новий SHA, пакет `format`, очікуване/фактичне значення та direct/paired/standalone stderr. Не редагувати .sens байти вручну; перевидати їх лише чинним SENS/Zig/T5M mint.
2. Для кожного залишкового D6/D10 прямого виклику назвати точні `Dn:біти`, відсутній механізм і SENS-закон. Додати позитивний та негативний свідки у вже чинний proof-runner, не дублюючи іншу семантику в Rust/Python.
3. Окремо отримати exact-SHA D12 свідок меж, переповнення без wrap/truncation, явного домену й фізичного round-trip. Не змішувати це зі зміною глобального D24-first профілю без міграції та доказу.
4. Не вводити нові гілки, workflow, загальні HOLD або приховані fallback. Усі RED залишати видимими з шаром, входом, expected/actual і точним SHA.
