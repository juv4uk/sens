# Sūtradhāra — контрольний зріз D11 / фізичний T5M · 2026-10-25

## Обсяг і чесний статус

Це **контрольний запис невирішеної фізичної проєкції**, а не релізний GO,
не ратифікація D11/D12 і не твердження про стовідсоткову виконуваність.
Джерело семантики — SENS. Zig/T5M тільки переносить типізовані слова;
Rust не може підміняти семантичний вердикт.

Агент: **Sūtradhāra (सूत्रधार)** — відстежує безперервність точних
визначень між канонічним кодом, фізичним носієм і виконуваним свідком.
Дякуємо Hetu за встановлені правила відтворення до виправлення
(координація #5984) та авторам останніх D11-правок.

## Відтворюване розходження на 2026-10-25

Під час прямого перегляду `main` перед створенням цього запису:

- `lib/d11-clojure-partition-by.lisp` має blob
  `34ab31db92a0c771cff16d84ee050fb82a3854c0` і **8** форм
  `(визначити ...)`. Після коміту
  [1ae1e487](https://github.com/juv4uk/sens/commit/1ae1e487938643aa36fda6967e560f582fe1d726)
  обидва розділення сусідніх серій уже викликають
  `розділити-поки-умова-ядро`; повторно виправляти їх не потрібно.
- Людиночитаний потік `lib/d11-clojure-partition-by` має blob
  `53e85ecccac43bfff8ae29dc4c4bb982bfce4bbe`; у ньому можна
  прочитати **5** координат D4:0011 (DEFINE), зокрема старі
  `групувати-суміжні-за-ключем` і `прибрати-суміжні-повтори`
  без нових окремих `-ядро` DEFINE. Отже, видима проєкція **не
  відповідає актуальному набору визначень у джерелі**.
- Наявний `lib/d11-clojure-partition-by.sens` має blob
  `ee8f3bb0c87726aed6e5b99cb33f51d797f83424`.
  Байтову тотожність carrier ↔ view, UK-source parity та нативний
  SENS-verdict **не підтверджено**. Без фізичного reader-а не
  робити висновку, що цей blob валідний або що він точно відтворює view.

Це доказ **розриву source ↔ view за кількістю DEFINE**, не доказ
експлуатованої уразливості, не доказ поточного runtime-падіння.
Розбіжність означає, що готовність повної D11-трійки не можна заявляти.

## Чинний мовний закон і межі

- Публічні D11 `групувати-суміжні-за-ключем` та
  `прибрати-суміжні-повтори` проводять один повний прохід D3
  `підтвердити-правильний-суфікс` до ключа/скороченого шляху.
- Внутрішні `*-ядро` дозволено викликати лише з уже доведеним
  правильним D3-суфіксом; вони не є самостійним загальним API.
- D1-атомний improper tail має давати точний D3 CAR Type **раніше**
  за помилку отруйного ключа. Не підміняти його NIL/() або host false.
- Зберігати закони суміжності A–B–A (три серії), singleton-key,
  зупинку першого незбігу, порожній список та фальшиві хвости.
- D1–D10: наявність ратифікованої координати не доводить runtime
  callable. D11: бібліотечна композиція без нового opcode.
  D12+: потрібен окремий нативний профіль і свідки, а не перенесення
  статусу зі старших чи молодших доменів.

## Наступний виконавець: точний протокол

На **новому** SHA `main` спочатку перевірити `git status --short`
і blobs названих трьох файлів. Не перезаписувати чужі зміни.
У справжньому локальному SENS/Zig-середовищі, а не в Python-симуляторі:

```sh
cargo test --locked -p sens --test d11_clojure_partition_by
bash scripts/refresh-executed-t5m-pair.sh \
  lib/d11-clojure-partition-by.lisp target/debug/sens \
  --binding-source lib/d11-srfi1-span-break.lisp
bash scripts/prove-lisp-semantic-t5m.sh \
  target/debug/sens target/debug/sens-trit /tmp/sens-d11-proof
```

Команди — **завдання для виконання**, у цьому ході вони НЕ
запускалися. Список binding-source потрібно перевірити відповідно
до фактичного native loader; при BLOCK не публікувати пару.

Після mint слід окремо перевірити:
1. Кожна фізична D11 `DEFINE` точно відповідає джерелу і має
   справжній нативний виклик на тому самому SHA;
2. `.sens` ↔ extensionless view — точна побайтова оберненість Zig/T5M;
3. Позитивні та негативні SENS-свідки, зокрема
   `tests/semantic/d11-clojure-partition-late-bad-tail-negative.lisp`,
   не приймають неправильно сформовані хвости;
4. Тільки після PASS одного workflow/commit-SHA застосувати один
   атомарний коміт трійки, не створюючи довгоживучої гілки;
5. Далі інвентаризувати D11 `*-ядро` у решті бібліотек, D12+
   і F6 physical producer→consumer (issue #5984) окремими доказами.

## Результат цього зрізу

- Перевірено: код `PARTITION-BY` уже змінений колегою; одне й те
  саме виправлення не дублюємо. Виявлено явне source↔view
  відставання; описано точні blobs і негативні свідки.
- Не перевірено: запуск нативного SENS, свіжий Zig mint, всі CI,
  фізичний D12+, повний реліз.
- Реліз `l0.42.0`: **NO-GO** до окремого рішення власника
  та доказу на повному candidate SHA.
