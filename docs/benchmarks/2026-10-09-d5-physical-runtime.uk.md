## Що фізично доведено

- Дві **побудовані release CLI-програми** отримують однаковий фізичний T5 потік,
  а не текстові назви функцій. Протягом усіх вимірів їхній stdout збігався
  побайтно з допущеним початковим результатом.
- Робочі зразки охоплюють рекурсію, відтворення списку та функцію вищого
  порядку, передану у рекурсивний `MAP`, з D7-координатами зв'язування.
- `decode(encode(exact_words)) == exact_words` проходить до вимірювання;
  первинні дані містять 0/1-слова з доменними ширинами.
- Окремо зберігаються сирі проби `d5-raw.tsv`, агрегати `d5-results.json`,
  `d5-environment.json` і звіт `d5-report.md` як GitHub Actions artifacts
  цього конкретного SHA (тимчасове зберігання 30 днів).

## Обмеження чесності

Це **не** benchmark порівняння з Python, Chez чи іншим Lisp.
Програми мають різну алгоритмічну роботу, а обидва CLI використовують один
SENS evaluator, тому паритет CLI не є незалежним Lisp oracle.
Упродовж цього SHA загальний Hosted CI і native smoke залишались червоними
через невиведену стару тричленну COND; успішний фізичний D5 не означає
автоматично зелений повний `main`.

Наступний науковий крок — незалежний алгоритмічно ідентичний workload,
відокремлення CPU startup від hot execution для D5, а також
повторення вимірів на стабільному процесорі із зафіксованим SHA.
