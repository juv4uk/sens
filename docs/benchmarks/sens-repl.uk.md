# Мікробенчмарк REPL SENS

Команда `:бенч` у REPL вимірює три короткі сценарії через той самий шлях, яким виконується введений рядок: вибрана людська проєкція → розбір і проєкція → Zig T5M → двійкові слова SENS → виконання та відображення результату. Звіт показує p50, p95, p99 наносекунд, приблизну кількість рядків за секунду за p50 та RSS процесу.

## Запуск

У запущеному `sens` введи:

```text
:бенч
:бенч 5000
```

З pinned-середовищем і оптимізованою збіркою можна запустити `./guix/run dev -- cargo run --release -p sens-cli --bin sens`. За замовчуванням виконується 25 прогрівів і 1000 вимірів для кожного сценарію. Дозволено задати від 100 до 10000 вимірів. Ratatui форматує звіт у терміналі; після нього REPL одразу приймає наступний рядок. Профіль `debug` позначений у звіті й не придатний для порівняння швидкодії.

## Що вимірюється

- **Арифметика:** двоаргументне додавання точних десяткових значень.
- **Доступ до пари:** створення пари та вибір першого елемента.
- **Вкладені виклики:** вкладені створення пар, вибір елементів і додавання.

Кожен сценарій перевіряє очікуваний результат перед заміром і під час кожного повтору. Час охоплює повний шлях одного рядка REPL і форматування результату, але не час виводу терміналом, запуск процесу чи побудови. Сценарії не змінюють робоче середовище користувача.

RSS читається з `/proc/self/status` до й після всього запуску бенчмарка. Також звітується приріст process high-water mark (`VmHWM`) за цей запуск. Це загальна пам'ять живого процесу разом із REPL; вона не ізолює байти окремої операції, а алокатор може втримувати вже звільнені сторінки. High-water mark не скидається: приріст 0 означає, що запуск не перевищив попередній пік процесу, а не те, що алокацій не було. На платформах без `/proc/self/status` RSS буде позначений як недоступний.

## Як читати числа

Це мікробенчмарк одного процесу, а не рейтинг мов. Для порівняння двох змін фіксуй той самий commit, host, архітектуру, версію інструментів і профіль збірки; виконуй кілька запусків у спокійному середовищі. Порівнюй насамперед p50; p95/p99 показують розкид і вплив перешкод планувальника. RSS описує робочу пам'ять процесу під час вимірювання, але не холодний старт, пікову пам'ять окремої операції чи загальне використання RAM системою.

Методика прогріву, повторних замірів і `black_box` спирається на Rust-бенчмарки в `my-idea`; цей REPL-звіт не копіює їхні навантаження чи результати.
