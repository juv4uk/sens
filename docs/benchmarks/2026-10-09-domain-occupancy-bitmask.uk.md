## Технічна межа

`scripts/generate-domain-owner-registry.py` читає ратифіковані
джерела D3–D9. Для D3–D7 він породжує **бітові маски зайнятості**
разом з історично перевірюваним списком точних координат.
Для D8/D9 перед генерацією повного-width сертифіката він перевіряє
повні множини з відповідно 256 і 512 різних координат та резидентів
із `knowledge/d8-ratified.json` і `knowledge/d9-ratified.json`.
Маски D3–D7 побітово перевіряються на тотожність явному списку.

Rust не містить таблиці людських назв і не робить висновку про
можливість виклику за фактом зайнятості. D1/D2 тут не описуються як
реєстр функцій; D10 — дослідницький, тому `owner_residency()` для нього
повертає `None`, навіть коли 10-бітна координата механічно коректна.

## Повторення

```bash
python3 scripts/generate-domain-owner-registry.py --check
cargo test --locked -p sens --lib domain_ladder::tests::
cargo build --locked --release -p sens --example domain_occupancy_bench
SENS_OCCUPANCY_ITERATIONS=100000 SENS_OCCUPANCY_SAMPLES=9 \
  target/release/examples/domain_occupancy_bench
```

Первинні stdout, артефакти, SHA та середовище збережено в двох
посиланнях GitHub Actions вище. Зелений benchmark не є доказом,
що інші частини Hosted CI або Lisp-бібліотеки вже працюють без помилок.
