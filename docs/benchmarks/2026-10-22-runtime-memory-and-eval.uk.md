# Поточні виміри evaluator і пам’яті SENS · 22.10.2026

Цей файл описує два різні досліди, що закривають прогалину старих замірів:
малий D3 QUOTE більше не використовується як єдиний доказ runtime-швидкості,
а загальний процесний RSS не видається за пам’ять лише програми.

## Гарячий CPU-шлях D24+

`benchmarks/physical-sens-runtime/hot.py` та
`crates/sens/examples/physical_sens_hot_bench.rs` додають фазу `eval_d24_plus`.
Кожна ітерація запускає програму з числом D5 додавань, рівним розміру зі
стовпця форм, через SENS exact-domain evaluator. Вимір — час на виклик усієї
програми; throughput нормалізований до форм/с. Harness повторно використовує
сесію та перед заміром перевіряє точний D24+ результат `3`.

Це вимір D2 framing parse/lowering та виконання вже сформованих domain words:
Zig/T5M encode/decode, зчитування файла та запуск процесу не входять. Старі
фази T5/D2 і D3 QUOTE збережені, але окремо підписані; їхні результати не
узагальнюються на арифметику.

## Пам’ять числового evaluator clone-шляху

`benchmarks/interpreter-memory/run.py` лишає попередній однаковий малий
умовний сценарій для Python/Guile/Lua/SENS, але додає окремий SENS-only
процесний RSS експеримент. Rust harness виконує D3 `як-є` над одним точним
D24+ значенням через typed exact-domain evaluator і утримує повторені результати.
Один режим лишає звичайні evaluator-копії; другий після того самого evaluator
явно матеріалізує глибокі копії контрольного розміру. Результати обох режимів
порівнюються до виміру.

За замовчуванням це 196608-бітний (D24 × 8192) від’ємний двійковий шаблон і
128 утриманих значень. Оскільки внутрішній `BinaryNumber` зберігає по одному
байту на біт, глибокий контроль створює близько 24 MiB значущих бітових
буферів. Фактичний RSS включає runtime і старт процесу; тож це не точний
лічильник алокацій, а whole-process спосіб побачити масштабування пам’яті.
Deep-copy — контрольний шлях, не запуск старого коміту/бінарника.

CI запускає лише smoke із трьома свіжими процесами на режим; сирі виміри
зберігаються у GitHub Step Summary. Для надійного порівняння релізних змін
запусти `physical-sens-benchmark.yml` на однаковому hosted runner та SHA
до/після; короткий CI smoke сам по собі не дає заяви про універсальний виграш.
