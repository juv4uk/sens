# Незалежний аудит пар `.lisp` → фізичний `.sens`

**Мета:** захистити роботу агентів, які паралельно переводять програми в обраний T5, і не сплутати фізичний файл із доведеною семантичною міграцією.

## Правило

`каталог/ім'я.lisp` — оригінал, `каталог/ім'я.sens` — фізичні байти; НЕ файл без розширення, НЕ ASCII 0/1/2. У самому T5 трит 2 стоїть лише між exact-width 0/1 словами D1–D9. На 5 тритів припадає байт 0..242; 0–4 фінальні трити 2 тільки для доповнення. Файловий EOF — фізичний кінець файла, без `22`.

## Інструмент

`scripts/audit_t5_file_pairs.py` — **тільки читання**, працює з git-tracked `*.sens` за замовчуванням і не чіпає `.lisp` / `.sens` навіть у режимі помилки.

```sh
python3 scripts/audit_t5_file_pairs.py . --output /tmp/t5-file-pairs.json
python3 scripts/audit_t5_file_pairs.py . --strict-semantic --output /tmp/t5-file-pairs-strict.json
# Для локального незакоміченого канаркового файла:
python3 scripts/audit_t5_file_pairs.py /tmp/canary --include-untracked
```

Перевірки на кожну пару: відповідний той самий stem у `.lisp`, symlink/відсутні файли BLOCK; `T5_decode + reencode` byte-for-byte, фізичний SHA-256, typed-width digest, кількість semantic bits, кількість меж слів. Якщо `.lisp` уже є точними бітовими словами, потрібна тотожність exact typed words. Текстова Lisp-поверхня **не** стає перевіреною автоматично: отримує статус `PENDING_ORACLE`, а `--strict-semantic` повертає помилку. Автоматичне підтвердження її значення вимагатиме окремого незалежного ратифікованого перекладача й виконуваного оракула.

`--include-untracked` вживайте у локальних тимчасових каталогах, а не для масової безконтрольної конвертації.

## Статуси

- `EXACT_BINARY_PAIRS`: точна фізична ідентичність **і** джерело вже бінарне з тими самими межами; це ще не виконувана oracle parity.
- `MECHANICAL_ONLY`: T5 канонічний і source-файл існує, але `.lisp` символічний — семантику ще НЕ доведено.
- `BLOCKED`: сирота, symlink, неправильне пакування, невідповідні слова або `--strict-semantic` із недоведеною поверхнею.
- `NO_FILES`: немає перевірених пар; **це не успішна міграція**.

Приклади: `10 01` → фізичний 1 байт `64`; `0|00` і `000` мають однакову голу конкатенацію, але різні typed digests і різні T5 файли. `64f2` не є допустимим T5 з мінімальним доповненням.

## Координація

Головна задача [#4449](https://github.com/juv4uk/sens/issues/4449); фізичний мігратор уже в `main` через [#4468](https://github.com/juv4uk/sens/pull/4468). Цей аудит не змінює чужі corpus cohort-и, D2/D7 і не зливає чернетку альтернативних кодеків #4443. Кожен агент передає власний PR, source provenance, фізичний SHA та oracle evidence **окремо**, а не сприймає зелений механічний тест як схвалення виконання програми.

**Важливо:** перевірка суфікса й пакування сама по собі не захищає від зловмисних чи випадкових семантично коректних змін, якщо вони також утворюють канонічний T5. Для релізу потрібні криптографічне походження й перевірка семантики за контрактом.
