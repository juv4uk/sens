# Дійсна міграція `.lisp → .sens`: перевірений пакет із manifest

Цей інструмент уже існує у `scripts/migrate-approved-t5.py` — не другий універсальний транслятор. Він **використовує тільки** діючий трипрохідний resolver + канонічний T5. Відтепер **одна незмінна копія байтів `.lisp`** одночасно визначає SHA256 у звіті та текст, який перекладається. Перед будь-якою публікацією пакета всі оригінали перечитуються та звіряються. Якщо бодай один змінився/не визнаний, пакет нічого не публікує.

Створіть manifest з конкретними перевіреними файлами та **SHA256 їхнього вмісту** (без автоматичного масового обходу):

```json
{
  "files": [
    {
      "path": "tests/fixtures/migration-d1-cond-cohort/branch.lisp",
      "sha256": "<вставте sha256 перевіреного оригіналу>"
    }
  ]
}
```

```sh
python3 scripts/migrate-approved-t5.py . \
  --manifest /tmp/approved.json \
  --out /tmp/approved-sens-mirror \
  --report /tmp/approved-sens-report.json \
  --dry-run
# За наявності незалежного доказу й після схвалення — без --dry-run.
```

На виході буде відносний шлях `tests/fixtures/migration-d1-cond-cohort/branch.sens`. Дані — **12 фізичних T5-байтів**, як у вже перевіреному файлі головної гілки; читач `sens-trit open` показує двійкові слова через пробіли. Відсутність `22`, 0–4 фінальних padding трити `2` і збереження точних доменних меж перевіряються кодером.

Важливо: цей приклад **уже мігрований у main** і використовується як регресія, а не доказ перетворення історичних 491 неприйнятих файлів. Для кожного нового джерела окремо потрібні executable classification, реєстр доменів/зв’язування та oracle parity. Не замінюйте legacy імена довільними номерами й не конвертуйте Lisp-таблиці як програми.

**Захист:** вихідний mirror та JSON-звіт лише ПОЗА деревом початкового репозиторію; фізичний файл створюється атомарно без overwrite. Один заблокований файл зупиняє публікацію цілого пакета. Гілка `master`, `.lisp` оригінали та видимість репозиторію не змінюються.
