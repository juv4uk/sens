# Від 490 BLOCK до груп робіт

Основний скрипт не змінюємо: `scripts/migrate-three-pass.py` лишається єдиним
трипрохідним семантичним перетворювачем; `scripts/migrate.py` — оператор.
Ця зміна **розширює існуючий** `scripts/report_original_migration_candidates.py`.

## Одна команда

```bash
python3 scripts/migrate.py candidates --report /tmp/original-candidates.json
```

Звіт тепер містить `first_blocker_partition`: повний поділ **кожного
оригінального непарного** `.lisp` із поточного Git-дерева за **ПЕРШОЮ**
причиною відмови канонічного парсера у режимі D1–D9 / source-era auto.
У кожному записі є `path`, `source_git_blob_sha`, причина і, якщо
доступні, `token`, `line`, `column`. Сортування: найбільше однотипних
помилок спочатку, потім назва групи / код. Групи не перетинаються,
сумарно охоплюють усі заблоковані оригінали. GitHub Actions також показує
перші 12 груп у Summary та завантажує весь JSON.

## Типи робіт — не вигадані переклади

| Група | Що робити | Задача |
|---|---|---|
| `W8_ERA_AMBIGUITY:00001001` та інші W8 | Встановити історичне походження та ідентичність коду із Git SHA кожного файла; не вибирати legacy навмання | #4459 |
| `LEGACY_SUCCESSOR` | Довести наступника історичної функції в ратифікованих D1–D9, перевірити виклик на оракулі | #4577 |
| `NON_BINARY_WORD` | Розділити функціональне джерело й декларативні таблиці, текст і числа; встановити закон представлення даних | #4460 |
| `D2_STRUCTURE_AS_DATA` | Відокремити структурні слова D2 від звичайних даних | #4462 |
| `HOST_EFFECT` | Уточнити ефект IO/PRINT і незалежну спостережувану поведінку | #4449 |
| `TEXT7_OR_NUMERIC_LAW` | Довести типізований текст/число, не підміняти числа фонемами | #4449 |
| `OTHER_UNPROVEN` | Розслідувати шлях і семантичний закон, не виконувати сліпу заміну | #4449 |

Групування за першою помилкою **не означає**, що всі інші проблеми файла
усунуті; після одного виправлення відкриється наступна. Також група
`NON_BINARY_WORD` **не доводить**, що файл є програмою: схеми, каталоги
ISA, архіви та дослідницькі дані залишаються окремою категорією.

## Що вважати реальним результатом

Для кожного оригінального виконуваного `.lisp`: ratified source-era,
точний Git SHA джерела, доведена семантична відповідність, однаковий результат
поточного оракула, фізичний T5 `.sens` поруч з оригіналом, справжній
Rust `sens-trit open`, GitHub CI GREEN. Лише такий файл зараховувати
до міграції. Декларативні та архівні `.lisp` не слід сліпо кодувати
як виконувані програми.

**Цей звіт нічого не переписує і не сертифікує.** Він перетворює
блокування на конкретні неперетинні списки робіт, які різні агенти
можуть брати паралельно, не змінюючи ратифікованих законів.
