# ОСТАННІЙ КОРІНЬ: `main` НЕ ЗАХИЩЕНИЙ — тому червоні й зливаються

Автор: агент Pratirodha, 2026-10-25.

## Вимір (GitHub API)

```
GET /repos/juv4uk/sens/branches/main/protection/required_status_checks
→ {"message":"Branch not protected","status":"404"}
```

**Гілка `main` не має захисту — отже немає ЖОДНОЇ обов'язкової перевірки.**

## Що це означає — і чому це пояснює все

Крок «Core4 — точна фізична пара SENS/Zig T5M» **існує**, **не має
`continue-on-error`** і **справді валить job**. Тобто перевірка **працює**.

**Але merge вона не блокує — бо ніщо не блокує.** Ось чому:

```
1. хтось змінює lib/core4.lisp без пари (напр. 962ea550)
2. bootstrap-крок ЧЕРВОНИЙ — він це бачить і повідомляє
3. ... і нічого не стається, бо main не захищений
4. застаріла пара потрапляє в main
5. сім свідків профілю core4 падають у НАСТУПНИХ прогонах
6. хтось пере-карбовує пару ВРУЧНУ («ремонт пар»), і цикл повторюється
```

**Уся нитка — від семи червоних до винуватця `962ea550` — впирається в одне
настроювання репозиторію.**

## Чому це найважливіше з усього знайденого

- **Мій чек був не потрібен.** Наявний bootstrap-крок **уже ловить** проблему.
  Проблема не в тому, що **немає перевірки**, а в тому, що **перевірка не має
  наслідків**.
- **Я чотири рази будував інструменти там, де треба було одне настроювання.**
  Зашитий `0` → не той гейт. Латиниця → не та причина. Прогалини → не дефект.
  Чек → не потрібен. **Кожен раз корінь був на рівень вище, ніж я шукав.**
- **Жоден агент не може виправити це зсередини.** Захист гілки вимагає прав
  адміністратора репозиторію. **Це рішення власника.**

## Що робити (рішення власника — одне)

1. **Увімкнути захист `main`** і зробити обов'язковим хоч один job:
   **«Охоронець · Rust · Zig · SENS»**.
2. Тоді крок Core4, який **уже існує**, **уже ловить** `outdated-physical`, —
   **зупинить merge сам**. Без жодного нового коду.
3. Пере-карбування пар перестане бути ручною працею, бо **не злити** стане
   дешевше, ніж **злити й лагодити**.
