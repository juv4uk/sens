# ВИПРАВЛЕННЯ: «друга дірка» була НЕ діркою — це навмисний бюджет GitHub Actions

Автор: агент Vyaya, 2026-10-25. Це виправлення **мого** висновку і **моєї** правки.

## Що я стверджував

У документі `SECOND-HOLE-manual-only-ci-2026-10-25.uk.md` я написав, що
**526 із 531 workflow запускаються лише вручну — і це «друга дірка»**. І **перевів 25
із них на `pull_request`**, назвавши це «найконкретнішим результатом нитки».

## Що показала перевірка

У проєкті є **явний механічний бюджет GitHub Actions** —
`scripts/ci_one_focused_workflow.py`:

```python
if path.name == "ci.yml":
    if automatic != {"push", "pull_request"}:
        raise ValueError("очікується один централізований автоматичний workflow …")
    ...
elif automatic:
    raise ValueError(f"додатковий автоматичний тригер {sorted(automatic)}")
```

**Правило:** `ci.yml` — **єдиний** автоматичний workflow. **Будь-який інший
автозапуск — провал.**

Вимір:
```
на main:              SENS_CI_BUDGET_PASS {"automatic_workflows": ["ci.yml"]}
з моїми правками:     24 рядки SENS_CI_BUDGET_FAIL
після відкату:        SENS_CI_BUDGET_PASS  (знову)
```

## Отже

- **«526 лише вручну» — НАВМИСНИЙ бюджет, а не дірка.** Проєкт свідомо обмежує
  витрати GitHub Actions одним автоматичним workflow.
- **Мій висновок про «другу дірку» був ХИБНИЙ.**
- **Моя правка (25 тригерів) ПОРУШИЛА guard 24 рази** і **зламала б CI**, якби
  потрапила в main.
- **Я відкотив усі 25 файлів оригіналами з main.** Guard знову проходить,
  `workflow_files: 531`, `pull_request` має рівно один файл.

## Що з цього лишається правдою

**Перша дірка — справжня:** `main` **не захищений** (404), і саме тому **єдиний**
автоматичний workflow (`ci.yml`), падаючи, **не блокує merge**. Ось це — корінь, і
він лишається.

А «526 вручну» — **не корінь, а задум**, і його **не можна чіпати** без рішення
власника про бюджет.

## Чому я публікую це, а не приховую

Я **шість разів** за нитку висунув щось, що вимагало виправлення — і **цього разу
зламав власний guard проєкту**, чого не робив раніше. **Єдине, що зупинило помилку, —
це запуск guard'а ПЕРЕД тим, як вважати правку готовою.**

**Висновок для наступного агента: у будь-якому проєкті спершу знайди ЙОГО ВЛАСНІ
guard'и і прожени їх на своїй правці. Не довіряй здоровому глузду — він у цього
проєкту інший.**
