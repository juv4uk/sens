# Рішення власника: L1–L7 для спадкових конструкцій → exact-domain

**Дата:** 2026-10-09. **Обсяг:** правила *міграції*, а не нова онтологія або заміна чинного Contract 11.8. Ці L1–L7 **не тотожні** історичним біджа3-аксіомам L1–L5 у `contracts/bija3-l1-l5-ratification.lisp`.

**Єдине джерело семантичних рішень мігратора — наведена таблиця.** Жоден скрипт не вправі вигадувати нові значення або координати D10. Чинні ратифіковані D1–D9 лишаються авторитетом; D10 кандидати не набувають статусу резидентів автоматично.

| Рішення | Норма | Зобов'язання механізму |
|---|---|---|
| **L1** | Двочленна `COND` перевіряє **точний PredicateBit D1:1 / D1:0**, а не truthiness; вичерпання — **структурне D3:000 / `()`** | Довести джерело D1, інакше `BLOCK`; не змішувати Number(0/1), T/NIL, Bool чи `()` |
| **L2** | Тільки клауза `(t <expr>)` → `(1 <expr>)`; `t` **не спеціальний символ** | Заміна лише в AST-ролі тесту клауза COND; не міняти quoted data / символ `t` глобально |
| **L3** | Виконуване ім'я → **наявна** ратифікована доменна координата | Немає однозначної координати / текстової проєкції — `BLOCK` і D10-пропозиція з provenance; жодної нової локальної семантики |
| **L4** | `equal?`, `null` — резидент тільки за доказовим кодом | Поточна таблиця дає **D8:11110111 EQUAL** і **D4:0101 NULL**. Без резидента — доказова розгортка через D3 закони, не ручна заміна; інакше `BLOCK` |
| **L5** | `structural-kind`, `identity-relation`, `structural-relation` retired | Вилучити із *активного виконуваного корпусу* окремим доказовим PR, записавши source SHA / причину в археології; scanner блокує, **не видаляє навмання** |
| **L6** | Старі фікстури, зокрема тричленна COND | Перегенерувати **існуючим** канонічним тулом з oracle trace; без встановленого тула / trace — `BLOCK`, не переписувати руками |
| **L7** | Не розпарсений файл | Не торкатися джерела; окремий список з помилкою/координатою на розгляд власника |

## Архітектура без другого reader

```text
source .lisp (immutable)
 -> scripts/migrate-three-pass.py : strip_comments / tokenize / Parser
 -> scripts/owner_l1_l7_gate.py : AST triage + bounded L2/L4 staging
 -> scripts/migrate-three-pass.py : migrate_file -> exact-domain words
 -> scripts/sens_t5_codec.py : typed digest + physical T5 roundtrip
 -> independent witness + pinned digests + existing admit-t5-migration.py
 -> only then physical .sens publication
```

**Fail closed:** `BLOCK` чи `L7` не змінюють початкових байтів. Звіт `STAGED-REVIEW` означає **лише механічну проєкцію**, не семантичний успіх; навіть `STAGED-ORACLE-MATCH` означає збіг поданих digest, а **незалежність і походження оракулів** доводяться тільки в чинному `scripts/admit-t5-migration.py`. Scanner ніколи не записує `.sens`; жодного bypass CI.

Запуск лише для огляду:

```sh
python3 scripts/owner_l1_l7_gate.py path/to/source.lisp --report /tmp/l1-l7-report.json
python3 -m unittest discover -s tests -p 'test_owner_l1_l7_gate.py' -v
```

**Обмеження першого кроку:** сканер допускає лише статично доведені D1-предикатні джерела (D3 ATOM/EQ або літерали D1:1/0). Джерельні DEFINE/LAMBDA (включно з локальним затіненням імен резидентів) теж **BLOCK** без незалежного scope oracle: жодного перетворення визначених користувачем функцій у вбудовані лише за однаковим написанням. Це консервативний *піднабір* L1, не заборона всіх інших функцій назавжди: складні предикати потребують окремих оракулів, scope/provenance та власного доказу. L5/L6 не видаляються автоматично. До повного корпусного parity та зеленого CI цей компонент має залишатися допоміжним механізмом без промоції у `main`.
