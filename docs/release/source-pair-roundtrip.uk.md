# P0 release gate: двійковий SENS ↔ український .lisp (#4430)

## Інваріант

- Для кожного активного каталогу/назва.lisp потрібен сусідній каталог/назва.
- Файл без розширення — лише непорожній потік байтів ASCII 0/1, без пробілів, BOM і завершального переводу рядка.
- Файл .lisp — непорожня канонічна українська UTF-8 NFC-проєкція, без латинських підмін та невидимих символів.
- Дві операції encode(U)=B і decode(B)=U перевіряються **побайтово**, як і обидві композиції.
- Семантика, D1–D9, D2 як єдиний власник структури, а також точна ширина кодів належать справжнім кодеку й оракулу, не цьому guard.

## Стан інтеграції

scripts/verify-source-pairs.py — незалежна read-only перевірка, вона не є новим джерелом доменної семантики та **не перекодовує файли**. Старі міграційні скрипти й PR #4420 залишаються недоторканими.

    python3 -m unittest discover -s tests -p 'test_verify_source_pairs.py' -v
    python3 scripts/verify-source-pairs.py --root . \
      --include '**/*.lisp' \
      --encoder scripts/sens-uk-encode.py \
      --decoder scripts/sens-uk-decode.py

Шляхи до кодеків у CI є **контрактними слотами, а не твердженням, що вони вже існують**. Їхні виконавці мають приймати байти зі stdin та віддавати лише байти результату в stdout без повідомлень. Відсутність будь-якого кодека — блокер релізу. --inventory-only перевіряє тільки структуру/алфавіт і не є доказом оборотності.

Поточний CI census суворо перевіряє всі .lisp у дереві репозиторію, включно з кореневими, тестовими та скриптовими. Перед релізом #4430 повинен класифікувати історичні матеріали: обґрунтовані винятки можливі лише через явний переглянутий реєстр, а не мовчазну фільтрацію. До завершення аудиту не можна вважати часткові перевірки доказом готовності релізу.

Консервативний дозволений алфавіт є початковим профілем стандартної української клавіатури. Розширення профілю робити лише з перевіреними розкладками й окремими тестами. Поточний перевіряльник не доводить бієкцію доменних назв сам по собі; для цього потрібен повний encode/decode та семантичний оракул.

## Координація

- #4430 — власник інваріанта та інтеграції кодека.
- #4329 / PR #4420 — чинна робота над власністю D2 у міграційному скрипті; не переписувати паралельно.
- #4313 / PR #4429 — чинна активна міграція; повторити перевірку пар після merge.
- #4250 / #4198 / #975 — freeze, exact-SHA і preflight тільки після повного PAIR-PASS.
- release.yml виконує guard у test до create-release, щоб не опублікувати збірки на невірному SHA.

Проміжний стан: guard і тести не дорівнюють готовому кодеку. Червоний release gate до завершення парування — очікувана правильна поведінка.
