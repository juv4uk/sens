# SENS Yantra — мінімальний coding agent у `.lisp`

> Yantra — мінімальний evidence-aware агент, уся керувальна логіка якого
> написана безпосередньо мовою SENS.

Yantra є власною реалізацією Володимира. Її ідентичність та архітектуру
визначають код цього репозиторію й явний контракт доказів.

## Архітектура

`lib/yantra.lisp` реалізує повідомлення, стан агента, представлення tool calls,
dispatch, цикл ходів, жорсткий `MAX_TURNS` і перевірку завершальної відповіді.
Агентної логіки в Rust немає.

Host-межа складається з універсальних, не специфічних для агента можливостей:

| Можливість | Реалізація | Межа |
|---|---|---|
| bash tool | `process-run` | дозволяється через `--allow-process=bash,curl` |
| HTTP POST | `process-run` + `curl` | транспорт можна замінити без зміни agent loop |
| JSON decode | примітив `json-parse` | `\uXXXX` потребує integer→character операції, якої немає в `.lisp` |
| JSON encode | чистий `.lisp` | `json-encode*` поверх рядкових і спискових операцій |

## Представлення повідомлень

Повідомлення — це alist із `role` та `content`. Assistant-повідомлення може
нести `tool-calls`; кожен tool result містить `tool-call-id`, скопійований із
відповідного виклику. Кореляція є частиною структури даних, а не текстовою
домовленістю.

## Головне правило доказів

Текстове твердження, що команда була виконана, не є доказом виконання.
`valid-final?` дозволяє таку завершальну відповідь лише тоді, коли їй
безпосередньо передують результати власних tool calls цього ходу. Старий або
чужий tool result не може підтвердити нове твердження.

Відповідь LLM завжди повертається зі статусом
`(epistemic-status . hypothesis)`: завершення agent loop не перетворює
гіпотезу моделі на доведений факт `reason.lisp`.

## Цикл агента

`run-agent` створює початкові system/user повідомлення й передає їх до
`agent-loop`. Кожен хід або виконує tool calls і додає корельовані результати,
або перевіряє фінальну відповідь. Після шести ходів цикл повертає
`max-turns-reached`, а не продовжується без межі.

Transport failure не маскується під порожню JSON-відповідь: Yantra повертає
структурований `blocked` разом із кодом виходу `curl` та stderr.

## Live wiring і перевірка

`ollama-complete` звертається до OpenAI-compatible endpoint
`http://127.0.0.1:11434/v1/chat/completions`. Тести не потребують живої моделі:
вони інʼєктують детерміновані `complete`-функції, але bash tool виконують
насправді.

Цільова перевірка:

```bash
cargo test -p sens --test yantra
```

На 2026-09-08 перевірено 10/10 тестів: JSON round-trip, реальний bash,
кореляція `tool_call_id`, transport failure, hard turn limit, статус
`hypothesis`, відмова від текстового псевдодоказу та від застарілого tool
evidence.
