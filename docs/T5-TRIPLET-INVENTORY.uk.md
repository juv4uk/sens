# Інвентаризація трьох файлів SENS — без підміни семантики

За чинним рішенням власника для *допущеної виконуваної програми* існують
три однойменні представлення:

- `name.lisp`: українська людиночитана канонічна `ук` проєкція;
- `name.sens`: фізичний T5, ратифіковані exact-width D1–D9 біти;
- `name` без розширення: текстовий ASCII перегляд тих самих бітових
  слів, **рівно один пробіл**, **рівно один завершальний LF**.

Цей скрипт — **інвентар**, а не генератор, перекладач або семантичний
сертифікатор. Він читає **лише Git-tracked `.sens`** за замовчуванням,
викликає чинний `scripts/audit_t5_file_pairs.py` для фізичної
`.lisp`/`.sens` пари, незалежно декодує/пакує T5 через
`scripts/sens_t5_codec.py` і порівнює *точні байти* існуючого
безрозширеневого `name` із `' '.join(typed_words) + '\n'`.

## Виконання

```bash
python3 scripts/audit_t5_triplets.py . --output /tmp/t5-triplets.json
```

Сканер друкує підсумок: число фізичних пар, число перевірених,
відсутніх або зіпсованих файлів `name`. У JSON для кожного stem:
`source_sha256`, `physical_sha256`, `typed_word_sha256`, плюс
`expected_view_sha256` і фактичний `view_sha256`, якщо файл існує.

- `VIEW_PASS`: canonical T5 ↔ extensionless ASCII view **точно**;
- `MISSING_VIEW`: повної трійки нема, але існуючі `.lisp`/T5 не
  змінені, не слід вдавати успіх;
- `INVALID_VIEW`: симлінк, змінені біти, зайві пропуски, відсутній LF,
  CRLF, `2` або будь-який неконанічний вміст — **BLOCK**;
- `BLOCKED_PHYSICAL`: відсутній або зіпсований source/T5 pair — **BLOCK**.

Нормальний режим повертає успіх, коли немає пошкоджених файлів, але
повертає стан `PARTIAL_TRIPLES` для браку view, не `PASS`.
Для **окремої контрольованої вибірки, де всі views повинні існувати**:

```bash
python3 scripts/audit_t5_triplets.py . --require-all-views \
  --output /tmp/triplets-strict.json
```

Цей суворий прапорець буде **червоним** доти, доки всі фізичні пари
в області сканування не отримають рев'юваних view. Ніколи не
підміняти це автоматичною генерацією без source oracle; генератором
окремо займається #4694.

## Семантична межа

Навіть `VIEW_PASS` **не доводить**, що `.lisp` є канонічним `ук`
або що його виконання дорівнює SENS. У кожному записі залишається
`uk_projection_status=ORACLE_NOT_VERIFIED` і
`executable_semantics_admitted=false`. Український рендерер/parser
та незалежну семантику реалізує власна гілка #4430; лише після її
доказу можна окремо сертифікувати повний український roundtrip.

На знімку 2026-10-09 попередньо було **13** фізичних пар, з яких
**одна** мала extensionless view `tests/fixtures/migration-d1-cond-cohort/branch`;
усі інші не можна автоматично оголошувати мігрованими.

Заборонені будь-які перезаписи `.lisp`, `.sens` або `name`.
Звіт дозволений лише поза коренем джерельного репозиторію;
наявний звіт теж не перезаписується. Завершення всієї масової
міграції та реліз не випливають з позитивного механічного аудиту.
