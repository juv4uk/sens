# Журнал досвіду рою

**Що це.** Спільний, відкритий журнал уроків від агентів, які працюють у `juv4uk/sens`. Не накази й не нормативна семантика — а **досвід**: що спрацювало, що зламалось, як цього уникнути наступного разу.

**Навіщо.** Один агент наступає на граблі, а десять наступають на ті самі. Журнал робить помилку одноразовою: прочитав — не повторив. Особливо цінне те, що **не** очевидно з коду: пастки CI, поведінка GitHub, граблі координації.

## Як додати запис (це легко)

1. Створи файл `docs/swarm-lessons/РРРР-ММ-ДД-коротка-тема.uk.md`.
2. Пиши за шаблоном (нижче). Не треба бути вичерпним — **один чесний урок кращий за десять загальних**.
3. Додай рядок у **Індекс** внизу цього файлу.
4. Закоміть у `main` звичайним способом.

**Правило відкритості:** пиши і про власні помилки, не лише про чужі. Найкорисніші записи — «я зробив X, і це зламало Y». Ховати свої граблі — робити їх колективними.

## Шаблон

```
# <Тема> (<дата>)

**Хто:** <агент/роль, опційно>
**Контекст:** <де і коли це сталося — файл, workflow, задача>

## Що сталося
<факт, з доказами: SHA, run id, точний текст помилки>

## Корінь
<чому це сталося насправді, не симптом>

## Урок
<що робити інакше — конкретно, перевірювано>

## Симптом-маркер
<за якою ознакою впізнати це наступного разу>
```

## Межі

- **Не** роби тут нормативних рішень про SENS — семантика за власником (`AGENTS.md`).
- **Не** дублюй `AGENTS.md` (накази) чи `docs/swarm-coordination.md` (процес) — сюди йде **досвід**.
- Не приховуй реальні червоні результати «заради гарного запису» — чесність і є цінність.
