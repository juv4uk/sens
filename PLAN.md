## 1. Головний порядок робіт

### A. Core: historical-first

```text
HISTORICAL-INGEST
        ↓
STRUCTURAL-DISCOVERY
        ↓
SENS-DERIVATION
```

Пріоритет:

1. завершувати chronological early-Lisp ingest;
2. не стирати historical rows лише тому, що SENS їх derivable;
3. після ingest знаходити families/generators/independent axes;
4. лише після structural evidence мінімізувати native SENS semantics.

### B. D5/D6

D5 і D6 width/domain ontology ратифіковані.

Але occupancy та historical inventory не завершені; selector closure не є автоматично повною картою, а free coordinate не є resident.

Пріоритет:

- exact maps як baselines;
- historical capability ledger;
- D6 PURE-UNKNOWN attacks законами;
- NO-CANDIDATE як допустимий результат;
- жодного free-space placement.

### C. Parentless roots

Найважливіша незакрита foundation-проблема:

```text
PROVEN-ROOT
!=
PROVEN-WIDTH
!=
PROVEN-COORDINATE
```

Поточні lanes: residue/root domain admission law, semantic lower bound, independent root-domain model і proof-address attack. До доказу exact domain/width root лишається UNPLACED.

### D. Core-Math

Мета:

```text
binary input(s)
+ mathematical law
-> binary output
```

Пріоритет: minimal seeds/laws, domain-scoped executor, law-generated binary objects, exact-Q factor laws і falsifiers проти нумерології. Core placement не імпортується автоматично.

### E. Core ↔ Core-Math

Допустимі результати:

```text
DIVERGENT
COMPLEMENTARY
CONVERGENT
```

Convergence потребує незалежного збігу binary object + domain + semantic equation + law + cross-proof. Selector convergence — positive control; cross-domain same-transform — negative control.

### F. D7 / D14 / Number

- D7: Sound7 + local śloka/sūtra ordinals;
- D7 не general arithmetic Number;
- D14: Pāṇini grammar як graph domain;
- D24/D48/...: exact Number / FPGA-oriented research;
- однакова width не переносить law.

## 3. Mechanism roadmap

Mechanism не має semantic authority.

### Runtime / reference

- Rust reference implementation;
- independent implementations;
- fail-closed parser/decoder/lowering;
- exact-width carrier discipline.

### FPGA

FPGA work споживає admitted law/object, а не створює semantics зі зручної hardware width. Пріоритет: exact Number experiments, generated-law execution, instruction/work accounting і semantic parity before speed.

### Wire / manual / RF

```text
semantic object
-> canonical SENS wire
-> framing
-> physical transport
```

CRC/FEC/ARQ/frequency/modulation — mechanism only.

## 5. Benchmark roadmap

Benchmark має розділяти semantic parity і mechanism cost. CI блокує semantic regression; hosted wall time є evidence, не semantic proof.

Для domain/generator research збирати candidate count, rejects, generated identities, semantic classes, proof/certificate work, UNKNOWN/residue та instruction/allocation cost де доречно.

- повернення до flat 256-slot ontology;
- заповнення всіх вільних координат;
- forced Core/Core-Math convergence;

- hardware-specific opcode map як language ontology;
- global hash/AST/registry identity;
- speed optimization до semantic parity.

---

## 7. Stop rules

Зупиняти або звужувати hypothesis, якщо permutation/re-encoding зберігає claim без semantic law; domain визначений лише width; coordinate обраний із free capacity; chronology використана як binary law; mechanism metadata потрібна для meaning; cross-domain transform названий shared law; finite behavior corpus видається за theorem; або proof address не може пояснити exact domain без circularity.

Falsification — успішний результат.

---

## 8. Principle

**History supplies observations. Structure supplies laws. SENS is derived afterward. Binary objects carry meaning only inside explicit law-bearing domains.**
