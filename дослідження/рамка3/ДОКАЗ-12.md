# Рамка-3: вичерпний свідок до 12 тритів

**Дата:** 2026-10-10 · **Статус:** дослідний доказовий профіль, НЕ ратифікація і НЕ новий формат `.sens`.  
**Первинний код:** [`носій.py`](носій.py) · **виконуваний свідок:** [`перевірка_носія.py`](перевірка_носія.py), `test_вичерпно_усі_трити_до_12`.

## Межа перебору

Вичерпно перебираються **всі** `3^0 + 3^1 + ⋯ + 3^12 = (3^13−1)/2 = 797161` рядків над `{0,1,2}`; випадковий семпл не використовується. Незалежно від реалізації `дозволені`/DP розпізнаємо лише канонічну зовнішню рамку `102…201` без сусідніх `22`, з окремим випадком `10201` довжини 5.

Для кожної **нерамкової** послідовності `ранг` мусить відмовити; для кожної рамкової — `ранг` і `за_рангом` взаємно обернені та відповідають лексикографічному порядку, перевіреному незалежним перебором. Окремий малий незалежний синтаксичний предикат перевіряє зовнішній баланс `10`/`01` та точні слова ширини 1–9. Для кожної прийнятої ним рамки кодування й декодування фізичних байтів має бути біт-в-біт оборотним. Для кожної відхиленої рамки обидва фізичні шляхи мають fail-closed. Перевіряються також усі **256 можливих однобайтових кодів**.

З них **796782** рядків одразу непридатні до рамки. В однобайтовій множині `[0, 255]` допустимі **118** фізичних значень, решта **138** мусять відхилятися. Зазначені числа — **контрольні очікування**, а не безумовне твердження про зелене CI: результат саме цієї версії коду встановлює GitHub-hosted прогін `Дослід: оборотність рамки-3` на зафіксованому SHA.

## Фальсифікатори

1. Хоч одна нерамкова послідовність отримала ранг; одна рамкова не отримала.
2. Різні кандидати однакової довжини отримали той самий ранг або порушено лексикографічну послідовність.
3. `за_рангом(довжина, ранг(трити))` змінив хоч один трит.
4. Допустимий зразок після `упакувати → розпакувати` змінив хоч одне точне слово або отримав інші фізичні байти.
5. Недопустима рамка, незайнятий фізичний код чи зайве закриття були прийняті.
6. `місткість` не збіглася з незалежним числом рамкових кандидатів.

## Відтворення

```sh
python3 дослідження/рамка3/перевірка_носія.py -v
```

Використовується **існуючий**, не новий workflow `.github/workflows/ramka3-doslid.yml` на GitHub-hosted `ubuntu-24.04`. Новий тест додає вичерпність до попередніх граничних, випадкових і негативних свідків.

## Що це НЕ доводить

- **Не** доводить еквівалентність усіх D2-програм семантичному оракулу: поточний `трити_форми` перевіряє лише обмежену форму.
- **Не** доводить оборотність за довжини понад 12 тритів або 8-байтової межі прототипу.
- **Не** доводить, що такий носій кращий за T5 за швидкістю, для багатоформних програм, або може прозоро замінити канонічний `.sens`.
- Довжина байтового запису кодує лише *дослідну* групу, а не закон EOF для всього SENS.
