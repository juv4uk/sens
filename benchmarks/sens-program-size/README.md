# Бенчмарк фізичних бінарних програм SENS

Основний вхід цього стенда — закомічена програма `.sens`, тобто фізичний
бінарний носій SENS. `.lisp` не парситься цим бенчмарком і не є його
виконуваним входом. Для CI список формують із виконуваних програм, змінених у
push/PR; перед вимірюванням наявний SENS↔Zig/T5M крок перевіряє відповідність
пари й фактичне виконання. Потім стенд повторно запускає саме `.sens` через
Zig/T5M reader та бінарний evaluator SENS.

Для кожної фізичної програми звітуються:

- `AST` — вузли AST, відновленого з точних бінарних слів SENS;
- `visits` — фактичні виклики evaluator-dispatch під час цього бінарного запуску;
- `words` і `bits` — кількість точних відновлених слів і сума їхніх ширин;
  доменне значення не виводиться лише з ширини;
- `trit2` — службові трити `2`: межі слів плюс фізичне кінцеве заповнення;
- `T5M` — фізичний розмір закоміченого `.sens` у байтах;
- `result` — результат того самого виконання `.sens`.

`benchmark-ast-visits` є opt-in Cargo feature. Звичайна збірка SENS не містить
лічильника та його накладних витрат. У CI фіча вмикається лише для вузького
бенчмарк-прогону; повна серія таймінгів не запускається. Цей звіт описує
виконання й розмір конкретних бінарних програм, а не автоматичний оптимізатор,
час виконання чи пам'ять.

Локальний запуск після збірки з пінованим Zig:

```sh
guix shell -m manifest.scm -- cargo build --locked -p sens-cli --bin sens --bin sens-trit --features benchmark-ast-visits
guix shell -m manifest.scm -- python3 -m unittest benchmarks/sens-program-size/test_run.py -v
guix shell -m manifest.scm -- python3 benchmarks/sens-program-size/run.py --binary lib/поміняти-перші-два.sens
```

Для кількох входів можна передавати `--binary` кілька разів. GitHub Actions
передає `--binary-list`, сформований лише з committed `.sens`, які пройшли
побайтову перевірку T5M-пари та окреме standalone-виконання з тим самим
результатом. Парні-only програми не потрапляють у бенчмарк.
Python-скрипт тут лише збирає лічильники та запускає готові інструменти; він
не парсить, не кодує й не визначає семантику програми.
