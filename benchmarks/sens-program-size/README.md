# Розмір повної програми SENS: AST і фізичний T5M

Цей невеликий стенд вимірює цілий український `.lisp`-файл, а не одну
вибрану форму. Поточний fixture містить дві десяткові D24+ арифметичні форми.
SENS reader і decimal projection будують повний AST; окремо рахується AST
після lowering. Потім `sens --t5m-mint` утворює фізичний `.sens` через
пінований Zig/T5M, `sens-trit open` повертає точні слова, а
`sens --t5m-pair` перевіряє парність і реальне виконання.

У звіті навмисно розділено різні розміри:

- `source`: байти людського UTF-8 джерела;
- `AST`: кількість вузлів усіх верхньорівневих форм до/після lowering;
- `words` і `bits`: точна кількість відновлених слів та їхня сумарна ширина;
  ширина не використовується для виведення доменної семантики;
- `T5M`: фактична кількість байтів фізичного `.sens`-файла.

«Повна програма» тут означає всі форми одного вхідного файла. Завантажувальне
середовище, бібліотеки та їхні транзитивні залежності до цього артефакту не
домішуються. Це облік розміру й перевірка виконання, не таймінг, не доказ
швидкодії та не порівняння з іншою мовою.

Локально після збірки `sens`, `sens-trit` та прикладу:

```sh
python3 -m unittest benchmarks/sens-program-size/test_run.py -v
python3 benchmarks/sens-program-size/run.py
```

Звичайний обов'язковий workflow `ci.yml` виконує лише цей малий smoke-набір,
без серій вимірювання часу, та показує один компактний GitHub Actions notice
і рядок у Summary.
