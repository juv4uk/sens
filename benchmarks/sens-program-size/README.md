# Оптимізація повної програми SENS: шлях AST і фізичний T5M

Стенд зіставляє два повні українські `.lisp`-файли з однаковим результатом:
`arithmetic-before.lisp` обчислює `3×7 + (9−7)`, а
`arithmetic-constant-folded.lisp` подає той самий точний результат `23` без
проміжних обчислень. Це вручну заданий constant-folding кандидат, не твердження,
що компілятор уже виконує таку оптимізацію автоматично.

Для обох файлів SENS reader і decimal projection будують повний AST; окремо
рахується AST після lowering. Opt-in feature `benchmark-ast-visits` рахує вузли,
які evaluator справді dispatch-ить під час виконання нижчого AST; це вимір
реального шляху, не оцінка за глибиною дерева й не час виконання. Потім
`sens --t5m-mint` утворює фізичний `.sens` через пінований Zig/T5M,
`sens-trit open` повертає точні слова, а `sens --t5m-pair` перевіряє
зворотність і виконання обох варіантів.

У звіті навмисно розділено різні розміри:

- `AST`: кількість вузлів повного файла до/після lowering для обох варіантів;
- `eval-visits`: фактична кількість evaluator-dispatch вузлів у виконуваному AST;
- `words` і `bits`: точна кількість відновлених слів та їхня сумарна ширина;
  ширина не використовується для виведення доменної семантики;
- `trit2`: кількість службових тритів `2` — межі між словами плюс фізичне
  кінцеве заповнення; значущі біти залишаються двійковими 0/1;
- `T5M`: фактична кількість байтів фізичного `.sens`-файла.

«Повна програма» означає всі форми кожного файла, але не завантажувальне
середовище, бібліотеки чи їхні транзитивні залежності. CI відхиляє пару, якщо
не збігаються результати виконання AST та фізичного T5M. Вищий домен корисний
лише за чинним законом/резидентом і виміряним виграшем у шляху та T5M, включно
з тритами `2`; сама ширина не визначає семантику. Перша пара демонструє
constant folding для фіксованих точних операндів; вона не доводить загальну
якість оптимізатора й не є таймінгом.

Локально після збірки `sens`, `sens-trit` та прикладу:

```sh
python3 -m unittest benchmarks/sens-program-size/test_run.py -v
python3 benchmarks/sens-program-size/run.py
```

Обов'язковий workflow `ci.yml` виконує цей малий парний smoke-набір без серій
вимірювання часу та показує одну компактну GitHub Actions анотацію і
порівняльну таблицю в Summary.
