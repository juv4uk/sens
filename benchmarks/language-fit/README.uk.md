# Добір мови за бенчмарками: Intel Core i5‑6400, Skylake

Мету не визначає назва мови. Для кожного завдання порівнюємо **однакову роботу,
правильність відповіді, час, вартість компіляції й підтримуваність**.
Перший експеримент — скалярний добуток двох масивів по 65536 чисел,
2048 повторів із зміною одного елемента перед кожним повтором.

## Реалізації

| Варіант | Техніка |
|---|---|
| Fortran | Вбудований `dot_product`, `real64` |
| C | Оптимізований послідовний цикл |
| Rust | `f64`, ітератори `zip`, `sum` |
| ASM SSE2 | Прямі `mulsd`/`addsd` на x86‑64 |
| ASM AVX2/FMA | Чотири векторні накопичувачі `vfmadd231pd` |

Для C й обох варіантів асемблера використовується **один драйвер `dot.c`**.
Функції у `dot-skylake.S` використовують System V x86‑64 ABI.
Усі компілятори отримують одну ціль `-march=skylake` або
`-C target-cpu=skylake`; без `-ffast-math`. AVX‑512 не використовується.

## Справжній вимір на власному комп'ютері

На UbuntuStudio встановити `gcc`, `gfortran`, `rustc`, якщо їх іще немає:

```bash
sudo apt install gcc gfortran rustc
cd /шлях/до/sens
bash benchmarks/language-fit/run.sh | tee language-fit-i5-6400.md
```

Перед запуском скрипт перевіряє `x86_64`, `avx2`, `fma`. За їх
відсутності він завершує роботу **без запуску несумісного машинного коду**.
Результат містить назву CPU, версії компіляторів і Git SHA.

Правильність порівнюємо з незалежним аналітичним розрахунком.
AVX2/FMA може змінювати порядок додавання чисел із рухомою комою,
тому застосовується явно вказаний відносний допуск `1e-10`.
Кожен варіант проходить прогрів і **п'ять чергованих вимірювань**;
звітуємо медіану часу повного процесу, час компіляції, розмір
виконуваного файла та SHA-256 відповідного джерела.

## Ручний CI

У наявному `.github/workflows/ci.yml`: **Actions → Run workflow →
`compare_math_languages: true`**. Запуск використовує той самий
`run.sh`, а не іншу реалізацію вимірювання. Звичайний push не запускає
цей бенчмарк, а ручний режим не запускає 19 важких частин.

**GitHub-hosted машина — не Intel Core i5‑6400.** Її результати лише
додаткове спостереження; остаточні висновки про власне залізо — за
локальними вимірами. Не робимо автоматичного «переможця» за одним
запуском і не переносимо нормативну семантику SENS до асемблера.

Далі варто порівняти змішані розміри L1/L2/L3/RAM, точну математику,
пакування бітів та потокове введення-виведення, перевіряючи
продуктивність і енергоспоживання окремо.
