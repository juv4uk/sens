# Яка мова підходить до задачі: перший малий порівняльний дослід

**Мета — зібрати факти, а не наперед призначити мову для всього SENS.**
Порівнюємо доступні реалізації конкретного математичного завдання: скалярного добутку масивів \`f64\` / \`real64\`.
Завдання можна виконати Fortran, C, Rust; нову мову додаємо лише з тією самою роботою та перевіркою результату.
Цей дослід **не** встановлює нормативну семантику SENS і не визначає мовну політику.

## Однаковий експеримент

- Два масиви по 65536 елементів, згенеровані однаковими формулами й порядком індексів.
- 2048 скалярних добутків; перед кожним змінюємо один елемент першого масиву на 1e-9.
  Це заважає компілятору замінити всю роботу заздалегідь обчисленою сталою.
- C: звичайний цикл; Fortran: ідіоматичний \`dot_product\`; Rust: ідіоматична композиція ітераторів.
- Однаковий результат перевіряється проти незалежної аналітичної суми:
  \`ROUNDS * initial_dot + 1e-9 * sum((ROUNDS - k) * b[k], k=0..ROUNDS-1)\`.
  Допуск до вимірювання часу — відносна похибка не більше \`1e-10\` із запасом для нуля.
- Компільовані оптимізовані виконувані файли; одна розминка кожного, п'ять повторів,
  циклічна перестановка порядку, медіана. Час компіляції та розмір бінарника — окремо.
  Час вимірює запуск цілого процесу на шумному спільному GitHub-hosted runner.
- Ні «переможця» з одного запуску, ні зміни продукційної мови, ні порога зупинки CI.
  Для обґрунтованого вибору додатково потрібні повтори на незалежних машинах,
  підтримуваність, доступність потрібних бібліотек, числова точність та споживання ресурсів.

## Як запустити

Вручну: **Actions → SENS — перевірки поверхні Lisp → Run workflow → compare_math_languages**.
Звичайні push/PR не виконують цей дослід; ручний запуск з прапорцем не запускає
19 важких частин CI та звичайні перевірки Lisp.
Результати й версії компіляторів зберігаються у GitHub Step Summary цього запуску.

Ніякого Python-оракула: контрольний вираз рахується окремо засобами AWK,
а три реалізації друкують лише одну суму. Зовнішня структурна перевірка
**не** може підміняти виконання законів SENS.

Наступні незалежні завдання для порівняння: точна математика, кодування бітів
і транспорт, потокове читання файлів. Zig, SENS та інші мови можна додавати
після появи справжнього еквівалентного ядра; не слід підставляти \`zig cc\`
як нібито бенчмарк вихідного коду Zig.
