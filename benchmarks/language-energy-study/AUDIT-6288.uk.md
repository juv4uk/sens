# ENERGY-03: аудит фізичного Python/C/Rust пілоту

Дата: 2026-10-28 · issue #6288 · **exploratory / preregistration #6286 ще в роботі**.

## Фактична функціональна одиниця та ризик оптимізатора

У трьох реалізаціях фізичне завдання — N разів (пілот N=8192)
перенести всі байти одного й того самого файлу `lib/core4.lisp`
у буфер призначення. Після кожного перенесення спостерігається
`dest[i % len(source)]`; фінальний `dest == source` — окремий
контроль. **Самих checksum та кінцевого збігу недостатньо**, щоб
довести 8192 реальних перенесень: «одна копія + 8192 читання»
могла б дати ідентичний підсумок.

З цієї причини у `copy.py`, `copy.c`, `copy.rs` перед **кожною**
копією змінюється один байт `dest[index]` операцією XOR 1.
Копіювання має відновити його до вихідного значення. У C додано
`volatile` вказівник на функцію `memcpy`, тому `-O2` не може
перетворити **виклик** на один поза циклом, якби він інлайнився;
у Rust наявні `black_box` на вході й виході. При цьому різні runtime
можуть виконувати різні фактичні кількості машинних інструкцій,
і однакові **байтові результати не доводять рівності механізмів**.
Для завершення аудиту ще потрібен object-level дизасемблерний
контроль Rust на конкретному `rustc` / LLVM і C на контрольованому host.

## Межа кожного показника

| Показник | Фізична межа |
| --- | --- |
| `wall_time_ns` | `time.perf_counter_ns` навколо запуску **зовнішнього** wrapper (`/usr/bin/time` або Rust RAPL meter). У всіх гілках *одна й та сама* зовнішня межа; це cold process + wrapper, не pure steady state. |
| `rapl_child_elapsed_ns` | Внутрішня тривалість дочірньої команди у Rust RAPL meter, **окрема від wall_time_ns**; не замінює останній. |
| `peak_rss_kib` | GNU `/usr/bin/time -f %M` для вимірюваної команди; не сумарні алокації/пам'ять хоста й не метрика `/usr/bin/time` чи зовнішнього meter. |
| `user_s`, `sys_s` | GNU time процесні CPU-часи, не wall-clock. |
| `energy_uj` | *Фактичний* `package-*` RAPL до/після процесу, **не енергія окремого процесу**; враховує фон та idle. |

Зібрані `copy.c` (`-std=c11 -O2 -Wall -Wextra`) і
`copy.rs` (`--edition=2021 -O -C target-cpu=x86-64`) не включають
компіляцію у cold wall-time; Python запускається як інтерпретатор
із відповідним startup. Однаковий алгоритм-постановка не
означає однакової роботи інтерпретатора/бібліотеки.

Три способи обліку процесів не слід змішувати: `/usr/bin/time`
обслуговує дочірню команду, Rust meter обслуговує `/usr/bin/time`,
а Python host читає час до й після запуску wrapper. Раніше
`study.py` **перезаписував wall_time_ns показником Rust Instant**
лише при доступному RAPL. Це забороняло порівнювати час
на машині з сенсором і без нього; виправлено: `wall_time_ns`
завжди зовнішній, а elapsed meter зберігається окремо.

## Парність і негативний контроль

`measure` приймає **рівно один** `PHYSICAL_COPY` із
відомим `bytes/copies/observed`; з meter допускає рівно один
додатковий `RUST_RAPL_PACKAGE` фізичного показника. Незбіг
байтів/кількості, зайвий stdout, exit ≠ 0, RSS=0, нульова
енергія/час, зламаний RAPL status/scope або відсутнє поле
спричиняють **BLOCKED**, а не публікацію чисел. Число
`--copies` явно 1..8192 у `study.py`, байтовий бюджет ≤3 GiB
на команду. Seed визначає відтворюваний локальний AB/BA
порядок, але 8 блоків одного shared runner **не означають**
8 незалежних машин чи експериментальних сесій.

`test_study.py` додає real C/Python smoke на 8192 байтових
копій та окремий реальний Rust smoke (при відсутності `rustc`
виводить видимий `RUST_NOT_VERIFIED` як skip, не PASS).
Моковані сценарії потрібні лише для **перевірки відмови
інструментування**, не для вимірювання часу або джоулів.
Мінімальна команда без дорогого повного досліду:

```sh
python3 -m unittest discover -s benchmarks/language-energy-study -p test_study.py -v
```

Фізичний C-контроль на локальному x86-64 з `gcc -O2 -S`:
після XOR-мутації та перед читанням зразка є `call *%rax`
через `physical_copy(%rip)`; при штучному corpus 271 B і
N=8192: `observed=1036693`, `copies=8192`, `bytes=271`.
Це **лише локальний C smoke і inspection**, не тривалий
реплікований вимір; source binary/cpu provenance цього
тесту не атестований у GitHub artifact. Rust objdump,
повний GitHub-run на точному SHA, час, RSS та справжня
енергія **ще не виміряні**.

Без валідного сенсора: `ENERGY_NOT_MEASURED`, без
0 J, TDP-імітації, J/op або оцінки SCI/CO₂e. Якщо датчик
наявний, але відмовив або дає невалідні проби, експеримент
**припиняється**. Цей фізичний пілот не визначає SENS-мовних
законів і не замінює окремих law+mutant через SENS REPL/Zig/T5M.

## Використана наукова основа (рішення → джерело)

- **Pereira et al. 2017** [DOI:10.1145/3136014.3136031](https://doi.org/10.1145/3136014.3136031): у доступній публікації досліджено *окремо* час, енергію і пам'ять для 27 мов / 10 задач. Тому наш один копіювальний пілот **не обґрунтовує загальну таблицю мов**.
- **Pereira et al. 2021** [DOI:10.1016/j.scico.2021.102609](https://doi.org/10.1016/j.scico.2021.102609): для порівняння застосовуються конкретні зіставні задачі з CLBG; звідси вимога однакового фізичного входу/виходу перед порівнянням.
- **Kalibera & Jones 2013** [DOI:10.1145/2464157.2464160](https://doi.org/10.1145/2464157.2464160): автори розглядають мінливість результатів, повторення різних рівнів та невизначеність; тому ми **не видаємо вкладені 8192 копії за 8192 незалежні експерименти**. Existing paired bootstrap не називаємо exact K–J estimator.
- **Wilkinson et al. 2016** [DOI:10.1038/sdata.2016.18](https://doi.org/10.1038/sdata.2016.18): FAIR поширюється на raw data, метадані й процедури; звідси вимога exact SHA, compiler flags, raw pairs, опису відмов.
- **Green Software Foundation SCI** [Specification](https://greensoftware.foundation/standards/sci/): потрібна функціональна одиниця; з одного RAPL CPU package без I/M/R та інших компонентів неможливо коректно отримати SCI.

**Залишкові ризики:** Rust optimizer-level witness; контроль CPU/governor/фонового шуму; окремі cold/warm та compile/time budgets; коректна незалежність session/machine; калібрування RAPL за #6289 і пререгістрація #6286. Поки вони не закриті, цей пілот **НЕ готовий до наукового рейтингу**.
