# SENS · продовження досліджень енергоефективності мов · пілот v1

**Статус: ДОСЛІД, НЕ РЕЙТИНГ і НЕ релізний гейт.**

## Чому

Власник 28.10.2026 зняв обмеження на мови програмування, щоб порівнювати
ціни виконання без попередньої упередженості. Відмова від Python-тестів
27.10.2026 через очікувані високі витрати енергії тепер перевірюється як
**гіпотеза**, а не припускається доведеним фактом.

Основні джерела:

- Pereira et al., *Energy Efficiency across Programming Languages*,
  SLE 2017, DOI https://doi.org/10.1145/3136014.3136031;
  подальше дослідження *Ranking programming languages by energy efficiency*,
  Science of Computer Programming 2021,
  DOI https://doi.org/10.1016/j.scico.2021.102609.
- Kalibera & Jones, *Rigorous Benchmarking in Reasonable Time*, ISMM 2013,
  DOI https://doi.org/10.1145/2464157.2464160.
- Green Software Foundation, SCI / ISO/IEC 21031:2024:
  https://greensoftware.foundation/standards/sci/.

## Попередньо фіксований протокол

**H0:** після контролю однакового corpus/workload та середовища немає
стійкої відмінності відносного часу, енергії або пікової пам'яті між
обраними реалізаціями.

**H1:** принаймні одна відмінність є на цьому конкретному фізичному
навантаженні. Висновок щодо загальної мови робити **не можна** навіть
якщо H1 отримає підтримку.

Функціональна одиниця — **8192 копій ідентичного буфера**
з `lib/core4.lisp` (не більше 3 GiB трафіку за один запуск), із повним byte-exact порівнянням кінцевого буфера
і однаковим спостережуваним checksum. Це **не виконання SENS** і не
мовний закон: ніхто не називає ці цифри «енергією логіки SENS».
Rust, C та Python виконують власні інструментовані копіювання
`copy.rs`, `copy.c`, `copy.py`.

Первинні метрики: **wall-time одного нового процесу з 8192 копіями**
в нс, **peak RSS** у KiB, CPU user/system час. Компіляція **поза**
вимірюваним вікном; startup/include interpreter входить у нього.
Вторинна метрика: **RAPL CPU package energy_uj** для того самого
процесного запуску. Це енергія **всього CPU package**, включно з
фоном/idle, а не енергія одного процесу. Використовуємо наявний
`benchmarks/mechanism/rapl-energy-bench.rs` для вимірювання і
відмови від неоднозначного rollover; Python-керівник лише
координує фізичні запуски/статистику.

**Зразки:** один непідрахований warmup кожної реалізації; далі
8 блоків × 4 пари *на кандидата*; порядок AB/BA збалансований і
попередньо визначений `seed=20261028`; A=Rust, B=Python або C.
Кожна проба запускає **новий процес** (128 виконань).
`benchmarks/measurement-triad/verdict.py` рахує ієрархічний
paired log-ratio bootstrap з 4000 реплікатів, seed зафіксовано;
повідомляємо B/A, 95% інтервали і сирі зразки, **не** p-values
без коректної моделі та **не** точний Kalibera–Jones estimator.
Асиметрія компіляторних оптимізацій, інтерпретатор, запуск,
системний allocator та фон є частиною дослідницьких обмежень.

Результати ділять три незалежні межі:
`PHYSICAL_PARITY` (той самий корпус і фізичне спостереження),
`TIME/RSS` (виміряно) і `ENERGY` (виміряно або NOT_MEASURED).
**RAPL відсутній → немає числа Дж, 0 Дж, J/op або CO₂e.**
Гіпотетичний power/TDP не є датчиком. Шум shared GitHub runners
не дозволяє висновку «мову X завжди економніше»; для такого
висновку потрібні фізичні повторні A/B з контрольованими
CPU/governor/turbo/температурою й окремі набори реальних задач.

Не нормалізувати результати між різними CPU; SCI не заявляти без
повної системної межі, джерела вуглецевої інтенсивності та
embodied emissions.

## Відтворення

На Linux x64 із Rust 1.99.0, C-компілятором, Python 3 і GNU time:

```bash
python3 -m unittest discover -s benchmarks/language-energy-study -p 'test_*.py' -v
python3 benchmarks/language-energy-study/study.py \
  --blocks 8 --pairs 4 --copies 8192 --seed 20261028 \
  --out .ci-physical-study
```

GitHub Actions автоматично запускає обмежені синтетичні перевірки для PR у
`main` і змін у `main`; вони перевіряють інструментарій, але не проводять
фізичний дослід. Для вимірювань використовуй окремий контрольований запуск
`study.py` на підготовленому Linux-хості з RAPL. Відсутній датчик означає
`ENERGY_NOT_MEASURED`; цей CI не запускає вимірювань і не публікує реліз.

Артефакт: `raw-samples.json`, `paired-report.json`,
`provenance.json`, `summary.md`; у Summary — короткий
зріз, а в Actions — лише інформаційна анотація без категоричного
переможця. Для строгого виробничого експерименту додати
комплект із 10+ різнорідних задач, нативний SENS-REPL track і
незалежні повтори на фізичних хостах; **пілот це не заміняє**.

Цей дослід не переносить мовну істину SENS у Python/C/Rust.
SENS REPL-програми та їхні позитивні/негативні свідки
перевіряються окремими чинними SENS jobs.
