# Конкурс бенчмарків: Rust — механізм, Zig — коридор, SENS — логіка

**Межа власності:** лише виконуваний SENS встановлює істину мовних законів.
Rust вимірює механізм (CPU, пам'ять, I/O, інструкції, фізичне
енергоспоживання). Zig вимірює коридор (T5M, ширини, точні біти, ABI,
кодування/декодування). Ніякі чужомовні результати не є оракулом SENS.

## Rust: фізичний механізм і джоулі

```sh
rustc -O benchmarks/mechanism/rust-byte-copy-bench.rs -o /tmp/sens-rust-bench
/tmp/sens-rust-bench
# Тільки за наявності доступного Linux RAPL package:
 /tmp/sens-rust-bench --rapl
```

Основний механічний стенд робить один прогрів, 11 проб по 512 точних
копій **бінарних байтів** `lib/core4.lisp` — того самого корпусу, який читає Zig. Цілісність байтів звіряє **після**
кожного таймера; друкує p50/p90/min/max (нс). Це не виконання мови.

`--rapl` додає окремий адаптивний енергетичний пакет тривалістю
щонайменше 300 мс. Linux powercap читається рівно **двічі** —
`energy_uj` до й після навантаження. `max_energy_range_uj` дозволяє
врахувати одне обертання лічильника. Потрібен рівно один доступний
`package-*` домен; при відсутності powercap, правах доступу,
неоднозначності кількох пакетів або нульовій дельті виводиться
**«енергію не виміряно»**, без вигаданого числа й без TDP-оцінок.

Число `measured_uj_per_copy` — сире **package-енергоспоживання на
копіювання**, яке включає фонові процеси, idle та сам бенчмарк.
Це **не енергія процесу**, не baseline-corrected marginal energy
і не енергія форми SENS. `energy-pkg` і `energy-cores` не сумувати.
Профіль процесора, частоти, температура, енергетична політика,
точний SHA, число копій, час і джерело лічильника потрібні для
будь-якого порівняння версій. Під WSL2 доступність RAPL не припускати.
За відсутності фізичного виміру значення Дж не публікувати.

## Zig: коридор, а не друга семантика

```sh
# Реальний T5M encode/decode на детермінованому наборі opaque бітових слів.
zig run -O ReleaseFast -lc bench_t5m.zig

# Лише допоміжна перевірка транспорту байтів (НЕ кодек T5M):
zig test -O ReleaseFast -lc benchmarks/mechanism/zig-byte-copy-bench.zig
```

Додатковий Zig byte-copy probe копіює сирі байти текстової проєкції
`lib/core4.lisp` (жодного виконання тексту) і має прогрів, 11 проб по 512
копіювань та точний byte parity; він не доводить T5M-відповідність
і не встановлює жодного мовного закону. Для T5M використовувати
`bench_t5m.zig`, який реально кодує та декодує детермінований фізичний T5M-корпус.

## SENS: семантика та логіка

Наявні `benchmarks/lists.lisp`, `benchmarks/arithmetic.lisp`,
`benchmarks/parser.lisp`, `benchmarks/recursion.lisp` разом з
нативними позитивними й негативними `tests/semantic/` свідками
проходять шлях **SENS → Zig/T5M → SENS**.
Відсутній нативний вердикт — **не доведено**, а не PASS.
Після нього можна звітувати T5M-байти, AST і visits: visits
не є кількістю машинних інструкцій CPU.

## Суддівство

Не порівнювати Rust p50/копія, Zig p50/T5M-операція та SENS
p50/програма як один рейтинг; відрізняються робота й знаменники.
Для швидкодії потрібні однакове навантаження, оточення,
warmup, парний порядок ABBA/BAAB і сирі вибірки.

У `benchmarks/contest-uk/judge.sh` досі є Bash-еталони очікуваних
чисел та `witnesses`. Поки відповідні закони не передані SENS,
нові перемоги не оголошувати семантично підтвердженими.
Не видаляти негативні свідки й не спрощувати релізні гейти.
Відкрита конкурсна координація — **#5934**, реліз — **#6183**.

## Вимірювання трьох крил на одному корпусі

Для ручного workflow `.github/workflows/native-rust-zig-sens-bench.yml`
додано ізольовані механічні перевірки: `rustc --test` для RAPL
(лише арифметика фізичних лічильників), Rust byte-copy для
`lib/core4.lisp`, Zig byte-copy для **тих самих байтів**, а потім
чинний нативний SENS закон. Ці три метрики не можна скласти в один
рейтинг без спільного workload і контролю умов вимірювання.

Окремий Rust-модуль `rapl-energy-bench.rs` підтримує
`--counter` та `--operations` для вже пакетованої програми.
Він **відхиляє кілька CPU package** замість довільного вибору
першого. На shared GitHub runner апаратні джоулі не припускаються.
Команда для нативного Linux з фізичним лічильником:

```sh
rustc -O benchmarks/mechanism/rapl-energy-bench.rs -o /tmp/sens-rapl
/tmp/sens-rapl -- ./target/release/sens --benchmark-physical benchmarks/lists.sens --core4-runtime
```

Це енергія **всього CPU package за один CLI-запуск**. Навіть коли
`--operations N` передано, сам Rust не засвідчує фактичну кількість
мовних операцій. Два RAPL-зчитування також не можуть виявити два
обертання лічильника: тривалі пакети треба скорочувати або
використовувати підтверджений енергетичний інтервал.
Жоден із цих вимірів не може видати SENS semantic PASS.
