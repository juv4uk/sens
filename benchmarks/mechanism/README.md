# Бенчмарки механізмів Rust і Zig та мови SENS

Механізми перевіряємо тією мовою, яка їх реалізує. `rust-byte-copy-bench.rs` та `zig-byte-copy-bench.zig` копіюють **ті самі байти** `lib/core4.lisp`, кожен має прогрів, 11 проб по 512 копій, p50/p90 та перевірку цілісності даних. Мовних законів у цих бенчмарках **немає**.

`rustc -O benchmarks/mechanism/rust-byte-copy-bench.rs -o /tmp/sens-rust-bench && /tmp/sens-rust-bench`

`zig test -O ReleaseFast -lc benchmarks/mechanism/zig-byte-copy-bench.zig`

**SENS:** наявні `benchmarks/lists.lisp`, `benchmarks/arithmetic.lisp`, `benchmarks/parser.lisp`, `benchmarks/recursion.lisp` запускаються окремо у CI. Їхні закони і мутанти належать `tests/semantic/`, виконання — виключно нативному SENS через Zig/T5M.

Числа Rust/Zig не є рейтингом мов: компілятор, цільова машина, виділення пам'яті та оптимізації відрізняються. Так само час повного SENS CLI, який містить bootstrap, не є чистим часом eval. На загальному GitHub runner не виставляємо автоматичних порогів прискорення, а зберігаємо p50/p90, розмір і SHA коміту. Інваріант — точне копіювання, а не задана швидкість.

Для подальшого розвитку: Criterion.rs (статистика та регресії), hyperfine (прогрів і зовнішні процеси), CL-Bench (окреме вимірювання виконання Lisp), офіційний Zig 0.16 (змінені API таймерів).


## Джоулі Linux RAPL для готового SENS workload (#6275)

Самодостатній Rust-бенчмарк без додаткових залежностей. Він не виконує
й не перевіряє семантику SENS: запускає вже визначену команду та читає
Linux powercap RAPL **до й після** кожного виміряного пакета.

```sh
rustc --edition=2021 -O benchmarks/mechanism/rapl-energy-bench.rs -o /tmp/sens-rapl
rustc --edition=2021 --test benchmarks/mechanism/rapl-energy-bench.rs -o /tmp/sens-rapl-tests
/tmp/sens-rapl-tests

# Перевірити доступні фізичні домени (на WSL2 можуть бути відсутні).
ls /sys/class/powercap/
cat /sys/class/powercap/intel-rapl:0/name
cat /sys/class/powercap/intel-rapl:0/max_energy_range_uj

# ОДНА команда SENS у кожній пробі => units=1 (ціна усього процесу).
/tmp/sens-rapl --units 1 --warmup 2 --samples 11 -- \
  ./target/release/sens --benchmark-physical benchmarks/lists.sens
```

`--domain /sys/class/powercap/intel-rapl:0` задає потрібний пакет, якщо
доступно кілька; можна вибрати інший наявний RAPL-домен за його фактичною
назвою. `--units N` **лише декларує** кількість одиниць роботи всередині
**одного запуску** команди: бенчмарк **не повторює** команду N разів і
**не знає**, скільки Lisp-форм вона виконала. Для чесного `мкДж/форму`
потрібен окремий справжній пакетний SENS workload, що виконує рівно N
форм, а також позитивний і негативний свідки SENS (#6276).

`RAPL_ПРОБА` містить сирі мікроджоулі і тривалість кожного процесу,
`RAPL_ПІДСУМОК` — медіану та p90 пакетної енергії. Прогрівальні процеси
не враховуються. Вивід дочірнього процесу stdout відкидається, stderr
залишається видимим. У час та джоулі входить запуск процесу, тому це
**не** гарячий час інтерпретатора. Лічильник RAPL належить
**пакету/фізичному домену, не процесу**: інші програми й ядро додають шум.
Вимір енергії не є паритетом результатів або позитивним доказом SENS.

Обчислення різниці враховує **одне** переповнення
`max_energy_range_uj`; кілька переповнень між двома читаннями неможливо
відновити з двох чисел. Підбирайте достатньо короткий пакет або частіші
контрольні проби. Для дуже коротких пакетів / нульової дельти програма
припиняється з помилкою. Відсутність RAPL на WSL2, помилка прав доступу,
відмова SENS або відсутність `energy_uj` також дають **помилку, не PASS**.

Порівнювати лише один і той самий workload при однакових умовах:
конкретні SHA, процесор, kernel, частота, governor, температура й фонова
активність. Не додавати `energy-cores` до `energy-pkg` як незалежні
витрати; вони перетинаються. Базова енергія простою, якщо віднімається,
має звітуватися окремо від повних фізичних джоулів. Немає автоматичного
релізного порога, JSON-квитанції чи нового CI workflow. До завершення
релізного P0 цей бенчмарк — P2, окрема гілка/PR.
