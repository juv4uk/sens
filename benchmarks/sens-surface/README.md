# Бенчмарки SENS — канонічний фізичний маршрут

Після M8 старе порівняння EN-text / SENS-text / SENS-FASL не є джерелом
семантичного висновку: людська поверхня має зводитися до канонічного виклику
SENS. Старий Python-звітник, JSON summary та SHA-256-квитанції з маршруту
post-M8 вилучено.

## Запуск

Зберіть нативні виконавці й запустіть канонічний фізичний суд:

```sh
cargo build --locked -p sens-cli --bin sens --bin sens-trit
SENS_BIN=target/debug/sens SENS_TRIT_BIN=target/debug/sens-trit \
  sh benchmarks/sens-surface/post_m8_three_way.sh
```

Для одного або кількох відомих фізичних учасників передайте їхні шляхи
`benchmarks/contest-uk/*.sens` як аргументи. Без аргументів перевіряються всі
чинні фізичні учасники. Точна тотожність перевіряється прямим порівнянням
байтів; далі Zig виконує open/verify-view, а SENS — paired і standalone.

## Межі доказу

- Позитивний результат не може замінити негативний свідок: мутант має бути відхилений.
- Відсутня або неповна фізична пара є помилкою, а не успішним пропуском.
- Суддя SENS/Zig/T5M є канонічним маршрутом вимірювання для цього проєкту.
- Цей runner лише передає керування канонічному судді; семантика залишається в SENS.
- Не створюються Python-артефакти, JSON-звіти чи SHA-256-квитанції.
