# Поточна SENS-програма проти Python-вихідного тексту: D5 LABEL COPY

Це вузький source-to-result пілот, не рейтинг мов. Попереднє D24 зіставлення
та окреме lowered-exec вимірювання не відповідали питанню про актуальну
тритову програму SENS проти Python `.py` source; їхні коефіцієнти відкликано
як докази швидкості сучасного SENS. Тут Python запускається із `.py` source;
внутрішні механізми CPython не трактуються як відповідник тритового
представлення SENS.

## Що є програмою і що є доменом

SENS-вхід — програма, представлена тритовим потоком. Runner бере вже наявний
приклад `examples/binary/d5-label-copy.bits`, де exact-width слова доменів
записані двійковою проєкцією, і поза таймером формує фізичний T5 `.sens`
носій. Двійкові доменні слова — семантичні координати; вони не є байткодом
програми. T5-байти тут лише упаковують трити та роздільники.

SENS-код рекурсивно копіює proper pair-list, що містить D1:1, D1:0 і
структурну порожнечу. Python source робить те саме над вкладеними 2-tuples
(head, tail), з `True`, `False` і `None`; tuple є Python-представленням пари,
а не твердженням про однакове розміщення в пам'яті. Обидві програми мають
видати той самий спостережуваний результат: `(1 0 ())`.

Після цього production `sens-trit open` перевіряє, що фізичний T5 носій
відкривається в точні слова джерела, а `sens-trit eval` виконує сам `.sens`
файл. Python запускається безпосередньо на `.py` вихідному файлі. Немає
окремого `compile()`-режиму, попередньо збереженого `.pyc` чи порівняння
Python bytecode із SENS. CPython може використовувати власні внутрішні
механізми для запуску `.py`; вони не подаються як представлення SENS і не
зіставляються з тритовою програмою.

## Межа вимірювання

Один зразок — новий процес від запуску CLI/інтерпретатора до готового stdout.
Включено процесний старт, читання вихідного файла, SENS T5 decode/D2 parse/
execution або CPython source parse/execution, друк результату, захоплення
stdout і завершення процесу. Створення T5-файла, correctness gate і збірка не
входять. Прогріви прогрівають також кеш ОС; cold disk cache не вимірюється.

Отже, це вимір конкретного повного виклику, а не чистого evaluator, не часу
завантаження ізольованого формату і не загальної швидкості мов. Реалізації
мають однакову рекурсивну задачу та результат, але різні runtime, структури
даних, формат джерела й принтер. Результат стосується лише цієї пари програм,
цього хоста і SHA.

парний вимір із перемішаним порядком SENS/Python: **126 пар**, усі пройшли
байтовий parity gate на `(1 0 ())`. Усі шість мали ідентичні Git SHA, T5

## Відтворення

```sh
ZIG="$(guix package -I | awk '$1 == \"zig\" { print $4 \"/bin/zig\"; exit }')"
ZIG="$ZIG" cargo build --locked --release -p sens-cli --bin sens-trit --jobs 2
python3 -m unittest discover \
  -s benchmarks/cross-language/reality-matrix/physical-sens \
  -p 'test_source_copy.py' -v
python3 benchmarks/cross-language/reality-matrix/physical-sens/source_copy_bench.py \
  --sens-trit target/release/sens-trit --reps 21 --warmups 3 \
  --seed 20261018 \
  --out benchmarks/cross-language/reality-matrix/physical-sens/evidence/run.json
```

Дані тут — локальний WSL2 research pilot, не CI-gate та не підтверджений
статистичний мовний speedup. Розширення має додавати окремі паритетні
програми/алгоритми, а не переносити цей коефіцієнт на SENS загалом.
