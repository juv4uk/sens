# survey-19 — локальний міжмовний survey: fib / sieve / collatz

Один і той самий алгоритм реалізовано **19 разів на 18 мовах** (Python двічі —
3.10 і 3.14) і виміряно на одній машині одним PowerShell-харнесом.

## ⚠️ Що це НЕ є (прочитати перш ніж посилатися)

- Це **не** доказ Contract 11.9 і не заміна чинному `benchmarks/cross-language/run.py`.
- Це **не** глобальний рейтинг мов. Це вимір **конкретних реалізацій** на
  **конкретному залізі** (Intel i5-6400, Windows 11) у режимі **окремих
  короткоживучих процесів**.
- Це **не** семантичне свідчення SENS і не має жодної мовної влади.
  SENS-семантику доводять лише SENS-свідки через Zig/T5M.
- Числа між різними машинами/прогонами порівнювати не можна. Різні CPU —
  різні результати.

Розділ додано на **прямий запит власника** як самостійний локальний survey.
Він не підключений до жодного автоматичного CI-workflow і не змінює
Cargo-воркспейс.

## Що міряється

Три навантаження, кожне запускається **окремим процесом** (щоб бачити, де
саме мова провалюється), розміри передаються аргументами CLI (щоб компілятори
не могли обчислити результат на етапі компіляції):

| Навантаження | Що робить | Розмір | Що перевіряє |
|---|---|---|---|
| `fib(n)` | наївна **рекурсія** без мемоізації | n = 34 | швидкість викликів/стека |
| `sieve(n)` | решето Ератосфена, байтовий масив | n = 5 000 000 | масиви та пам'ять |
| `collatz(n)` | сумарна довжина послідовностей Коллатца 1…n | n = 500 000 | щільні цілочисельні цикли |

Усі реалізації друкують **однаковий текст** — це і є перевірка паритету:

```
fib(34) = 5702887
sieve(5000000) = 348513
collatz(500000) = 62134795
```

## Методика

- Кожне навантаження — **окремий процес**, міряється повний wall-clock
  (включно зі стартом рантайму).
- **1 прогрів**, потім **3 прогони**, береться **мінімум**.
- Компільовані мови — релізні прапорці (`/O2`, `-O3`, `-O ReleaseFast`,
  `opt-level=3`, `-O`).
- Однакова функціональна одиниця: той самий алгоритм, той самий тип даних
  (64-бітні цілі / байтові масиви).
- Харнес працює у **свіжому середовищі** (Machine + User PATH, як у новому
  терміналі) і сам знаходить тулчейни; якщо інструмента немає — мова
  позначається `SKIP`, а не вигадується.

## Як відтворити

```powershell
# усе: збірка + прогін + таблиця + results/<дата>-survey-19-<cpu>/
powershell -ExecutionPolicy Bypass -File .\run-bench.ps1

# тільки прогін, без перезбірки
powershell -ExecutionPolicy Bypass -File .\run-bench.ps1 -SkipBuild

# швидка перевірка (малі розміри)
powershell -ExecutionPolicy Bypass -File .\run-bench.ps1 -Smoke

# окремі мови
powershell -ExecutionPolicy Bypass -File .\run-bench.ps1 -SkipBuild -Only Swift,Rust,Zig

# інші розміри / більше прогонів
powershell -ExecutionPolicy Bypass -File .\run-bench.ps1 -Fib 35 -Sieve 10000000 -Runs 5
```

Скрипт пише результат у `results/<YYYYMMDD>-survey-19-<cpu>/`:
`survey-19.csv` (сирі мінімуми + усі прогони) та `environment.json`
(CPU, ОС, версії навантажень, еталонний вивід).
