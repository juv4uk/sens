# Спостереження RSS: SENS, CPython і Guile на бінарному дереві

**Статус: архівний вимір із поточної сесії; не відтворюваний benchmark-пакет.**
Цей файл зберігає фактично отримані спостереження, щоб вони не губилися в чаті.
Початкові скрипти й повні журнали запусків не збереглися, тому не слід
трактувати числа як незалежно відтворений або опублікований benchmark.

## Що вимірювалося

Піковий RSS процесу в KiB (GNU `time`, `%M`) для нового процесу інтерпретатора:
окремо idle baseline та виконання рекурсивної побудови/перевірки бінарного
дерева глибини 18. За описом запуску дерево містило 262,143 внутрішні pair-вузли
та 262,144 листки. Виконуваний результат перевірявся на всіх трьох мовах.
Було по п'ять запусків кожного режиму для кожної мови.

Це вимір **піку всього процесу**, а не вимір обсягу самої програми, дерева,
представлення значень чи сторінок пам'яті за типом вмісту. RSS включає runtime,
завантажені бібліотеки, парсер/евалюатор, аллокатор та об'єкти workload. Без
heap profiler або аналізу `/proc/<pid>/smaps` не можна сказати, яка частина RSS
належала конкретному компоненту.

## Обережне прочитання

У цьому конкретному запуску повний процес SENS мав приблизно 2.40× пікового RSS
CPython і 2.56× Guile. Різниця між workload та idle-медіанами SENS була приблизно
3.97× CPython і 4.12× Guile. Це не ізольована «ціна представлення SENS»:
idle-віднімання не усуває різниці в базових runtime, аллокаторах, GC, завантажених
бібліотеках і спосібах побудови дерева. Результат також не перевіряє гіпотезу,
що компактніше вихідне подання автоматично зменшує робочу пам'ять.

SENS тут запускався як interpreter executable із вихідним кодом; окремого
бінарника workload не було. Водночас CLI використовує вбудоване перевірене
представлення Core4, а CPython і Guile виконують власні внутрішні кроки
компіляції/підготовки. Це не є порівнянням чистого інтерпретаційного ядра чи
фізичного виконання тритів. Числа часу з цього виміру не публікуються.

## Raw measurements

Масиви вище — всі збережені первинні RSS-спостереження цієї сесії. Єдині
агрегати — медіани п'яти значень і їхня різниця. Не вимірювалися heap-профілі,
PSS, USS, allocation counts, bytes per node або дамп вмісту пам'яті. Точні
вихідні fixtures, команди, stdout, повний Git/build provenance та profiler
траси не були збережені під час первинного запуску; тому цей запис не можна
відтворити лише з репозиторію.

Для наступного валідного досліду треба зберігати разом: однаковий source fixture
на кожну мову, точні команди й версії, Git SHA та binary SHA, сирі RSS/PSS/USS
samples, process tree, перевірку семантичного результату й окрему heap-атрибуцію.
