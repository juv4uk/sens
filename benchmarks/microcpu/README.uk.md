# SENS-µCPU — перший фізичний слотовий експеримент

**Статус:** окремий дослідницький прототип, **не** ратифіковане ядро SENS, не заміна семантичного оракула, не FPGA-бітстрим і не обіцянка прискорення.

## Що справді працює

Файл `.sens` — це фізичні канонічні T5-байти. Відкривається існуючим перевіреним `scripts/sens_t5_codec.py`. Далі:

1. Зчитуються точні слова D1/D3 і структурні токени D2. Жодні англомовні чи історичні восьмибітні імена не потрапляють у виконувану програму.
2. D2-форма компілюється в **плоску слотову стрічку**. Слоти мають внутрішні машинні теги й не приписуються до доменів SENS.
3. Стрічка виконується повторно без повторного декодування T5, повторного парсингу D2 чи пошуку Lisp-імен.
4. Незалежний Rust-виконавець `sens program.sens` перевіряє результати **на тих самих фізичних байтах**.

Перший зріз підтримує D1:0/1, D3:000 та всі сім функцій D3: `001 QUOTE`, `010 ATOM`, `011 CDR`, `100 CAR`, `101 EQ`, `110 COND`, `111 CONS`. Вбудована підтримка цитованих даних не означає дозвіл на виклик текстових імен.

**COND** приймає тільки пари `(test expression)`; D1:1 вибирає, D1:0 пропускає, структурне `()` як умова — помилка домену. Наступна гілка виконується лише за потреби; відсутність вибраної гілки повертає структурне `()`. **EQ** не приймає пари, **CAR/CDR** вимагають пару. Обмеження на глибину та кількість слотів — явні.

**Не підтримано:** D4–D10, замикання, DEFINE, середовища, GC, рекурсію, крапкові пари, ефекти ОС, CUDA та FPGA. Спроба такого виконання повертає `BLOCKED`, а не переходить тихо в старий Lisp.

## Відтворення

З кореня репозиторію:

```sh
python3 -m unittest discover -s tests -p 'test_microcpu_slots.py' -v
python3 benchmarks/microcpu/slot_cpu.py tests/fixtures/migration-quote-cohort-main/quote-legacy.sens
python3 benchmarks/microcpu/bench.py --samples 11 --loops 80 --warmup 3 --out /tmp/sens-microcpu.json
```

Для незалежного оракула:

```sh
cargo build --locked -p sens-cli --bin sens
SENS_CLI_PATH="$PWD/target/debug/sens" python3 -m unittest discover -s tests -p 'test_microcpu_slots.py' -v
```

GitHub Actions **SENS microCPU physical D1-D3 slot research** запускає обидва сценарії та зберігає JSON з фактичними p50/p95, SHA, CPU, кількістю T5-байтів і слотів. Підміна результатів чи відключення невдалих негативних перевірок заборонена.

## Методологія

Порівнюються **окремі фази одного Python-двигуна на однаковому T5**: (а) декодування+компіляція; (б) декодування+компіляція+виконання; (в) повторне виконання вже зібраних слотів. Фаза (в) не включає роботу фаз (а)/(б), тому співвідношення цих чисел **не можна називати прискоренням усієї SENS**. Порівняння з Rust SENS, GPU чи FPGA буде можливе лише після зіставлення однакових семантичних результатів, однакових режимів запуску й обладнання.

**Наступна перевірювана мета:** сформувати однакові безіменні слотові інструкції як нижчий механічний рівень із поточного семантичного оракула, виміряти вартість запуску слотів у Rust/native CPU, потім лише переносити той самий набір слотів на FPGA. Семантика — власність ратифікованої мови.

## Дослідні інтервали невизначеності (2026-10-10)

У JSON тепер зберігаються сирі `raw_ns_per_operation` для кожного раунду та відтворюваний парний процентильний bootstrap (4096 повторних вибірок, фіксований seed) відношення **повної фази декодування+компіляції+виконання** до **повторного виконання вже зібраної стрічки**. Це дві різні фази однієї реалізації, не два рівноцінні інтерпретатори. Інтервал показує лише *пілотну внутрішньопроцесну невизначеність*, а не системний CI для прискорення мови.

Для повноцінних effect-size інтервалів за Kalibera–Jones потрібні незалежні запуски процесу, за потреби незалежні збірки, піновані середовища й визначення рівня випадковості. Джерела: Kalibera & Jones, *Rigorous Benchmarking in Reasonable Time* (ISMM 2013, doi:10.1145/2464157.2464160); *Quantifying Performance Changes with Effect Size Confidence Intervals* (2020, https://arxiv.org/abs/2007.10899). Зміни статусу доказу без цих даних не робити.

Негативні статистичні свідки: `python3 -m unittest discover -s tests -p 'test_microcpu_stats.py' -v`. Збираються в уже наявному workflow; нового workflow не створено.
