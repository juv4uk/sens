## 1. Фізична однобайтова мікропрограма `0x45`

- **Програма:** точні слова `10 100 10 111 1 000 01 01`;
  значення у реальному SENS evaluator = D1 `1`.
- **Два носії тієї самої програми:** зовнішньо вибраний
  експериментальний `.f3m` 1 фізичний байт проти чинного T5 5 байтів.
  Перший **не** універсальний `.sens` і не враховує сам декодер,
  вартість вибору профілю, номер версії чи CRC.
- **Hardware:** Intel Xeon Platinum 8370C @ 2.80 GHz,
  Linux 6.17.0-1022-azure x86_64, rustc 1.99.0, Rust Release.
- **Метод:** 300 warmup викликів; **19 серій по 300 повторів**;
  wall-time на операцію, медіана p50 і найближчий ранг p95,
  `black_box` над входами/результатами, in-memory,
  **без filesystem I/O чи cold start**.
- **Результати:** [raw 1B proof, binary, TSV](https://github.com/juv4uk/sens/actions/runs/38165269659/artifacts/11711633740).

| Операція | p50, нс | p95, нс |
|---|---:|---:|
| `.f3m` encode exact D1/D2/D3 words → 1B | 2716.57 | 2757.39 |
| T5 encode typed words → 5B | 93.16 | 184.73 |
| `.f3m` decode 1B → exact words | 161.68 | 230.71 |
| T5 decode 5B → typed words | 270.18 | 293.25 |
| `.f3m` decode + canonical parse + fresh Session + execute | 132108.37 | 148936.49 |
| T5 physical decode + canonical parse + fresh Session + execute | 131552.66 | 136934.67 |

**Висновок:** `.f3m` decode на цьому випадку
приблизно **1.67× швидший** за T5 decode; дослідний
`.f3m` encode **29.2× повільніший** за T5 encode.
Повний uncached decode/execute практично однаковий (~0.13 мс).
Справедливість: перший шлях відновлює `Vec<String>`,
другий — typed words; виміряні різні транспортні API,
хоча обидва подають точну початкову програму.
**Теплий кодек ≠ виконання інтерпретатора ≠ запуск процесу.**
Поточний micro encode лінійно шукає код (декодує кандидатів
до знаходження тотожного); цей вузький O(256) search —
очевидне місце для прямого обчислення рангу.

## 2. Оригінальна F3 та T5 на звичайних Git-tracked `.sens` файлах

- **Hardware:** AMD EPYC 7763 64-Core Processor, GitHub
  ubuntu-24.04, Linux 6.17.0-1022-azure x86_64, rustc 1.99.0,
  Rust Release. Цей runner — **інший CPU**, ніж micro-профіль.
- **Метод:** **15 серій по 16 викликів**, прогрів 16,
  p50/p95 in-memory encode та decode, `black_box`.
  Час декодування та кодування не включає execution,
  запуск програми, файлове I/O, ініціалізацію Rust чи компіляцію.
- **Файли:** усі **23** Git-tracked фізичні `.sens`,
  кожен пройшов production T5 decoder/D2 admission і
  byte-exact перевірку T5. **12** відновила початкова F3 зі
  справжнім `senc::decode_senc` exact-word roundtrip;
  **11** F3 не підтримує/відхиляє. Непідтримані не враховуються
  в суму байтів і не вважаються успіхом.
- **Джерело:** [повна per-file TSV + provenance](https://github.com/juv4uk/sens/actions/runs/38165269659/artifacts/11711528987).

| Властивість | Результат |
|---|---:|
| T5 physical total для **12/23** підтриманих F3 файлів | 94 Б |
| F3 physical total для **тих самих** файлів (вкл. мітку) | 83 Б |
| Економія на підтриманій підмножині | **11.702%** |
| Медіана пофайлових F3/T5 ratios encode p50 | **337.63× повільніше** |
| Медіана пофайлових F3/T5 ratios decode p50 | **502.95× повільніше** |

Пофайлові приклади, **p50 наносекунди/op**, обидва носії
перевірено на однаковому вмісті:

| Файл | Б T5/F3 | Кодування T5/F3, нс | Декодування T5/F3, нс |
|---|---:|---:|---:|
| `core1-domain-canary/second.sens` | 22 / 20 | 789 / 266391 | 1176 / 918562 |
| `migration-quote-cohort-main/quote-legacy.sens` | 4 / 3 | 162 / 35425 | 450 / 120932 |
| `migration-pair-cohort/pair-cons.sens` | 10 / 9 | 192 / 133466 | 530 / 451332 |

**Статистична обережність:** на shared hosted runners
частота CPU, фонова завантаженість, cache/thermal state,
allocator і порядок вимірювань впливають на p50/p95;
це не турнір із гарантованою відтворюваною абсолютною
кількістю ns. У файлах є повторювані cohort fixtures,
тому 12/23 — не 12 незалежних семантичних програм.
Не переносити цей коефіцієнт на великі файли, GPU/FPGA,
AOT/native execution чи інший CPU.

## Блокер та пріоритет

1. Однобайтовий дослідний profile: прямий deterministic
   grammar rank замість перебору дозволених кодів;
   незмінні bit widths, file bytes і fail-closed negative tests.
2. Оригінальна F3: профілювання гарячих rank/unrank,
   DP-count caching і видалення повторних алокацій,
   **без** заміни математичної Рамки‑3 на S3/v2/v3.
3. Підтримка **всіх 23** файлів і великих реальних програм;
   вартість profile/version/EOF/integrity має входити
   до **повного** фізичного розміру.
4. Незалежна parity Rust↔Python (раніше 1062/1703
   невідповідностей) потребує окремого виправлення;
   цей успішний speed run її не підтверджує.

Весь дослід доданий лише у Rust examples і GitHub Actions;
чинний production `.sens` і ratified domains не змінювалися.
