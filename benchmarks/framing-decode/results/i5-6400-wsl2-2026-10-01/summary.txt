# #1993 framing decode — first full matrix

Environment:
- Intel Core i5-6400 @ 2.70 GHz
- WSL2
- rustc 1.98.1
- Valgrind 3.27.0

Method:
- correctness before timing;
- Width3+escape and gamma-only word codecs;
- raw / stop-bit / outer-gamma-length / container-valid-bits message boundaries;
- widths 1..9,16,32,64,65,128 plus repeated3/mixed/corpus and truncated rejection;
- 10,000 iterations for single/rejection rows, bounded lower repetition for multiword programs;
- 3 Cachegrind prepare/full differential samples;
- all 144 measured rows had zero I-ref spread across the three samples.

In this implementation the CPU crossover is exactly width 11:
- widths 1..10: Width3+escape decodes cheaper;
- width >=11 in the measured set: gamma-only decodes cheaper.

Mechanical wire law:
- gamma-only wins width 1;
- tie at widths 2..3;
- Width3+escape wins widths 4..10;
- gamma-only wins from width 11 onward.

Thus CPU and wire crossover align at width 11 except width 1, where gamma-only
uses fewer wire bits but Width3+escape is cheaper to decode.

## Message-boundary wrappers are a separate axis

Container valid-bits adds approximately 8 I-refs per message across both codecs
and across single/multiword rows.

Representative Width3+escape overhead versus raw:
- single width3: container +8, stop +33, outer gamma +227 I-ref/message;
- single width16: container +8, stop +93, outer gamma +305;
- corpus: container +8, stop +63, outer gamma +413;
- mixed: container +8, stop +18, outer gamma +386.

Wire trade-off is different:
- stop-bit often uses about 3 fewer total bits than the 3-bit container metadata;
- container needs the outer byte length but has nearly constant tiny decode cost;
- outer gamma length is self-contained but costs the most decode machinery here.

This confirms the 2D model:
word codec choice and message-boundary choice should not be collapsed.

## Limits
