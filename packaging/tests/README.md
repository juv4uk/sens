# Перевірка оновлення інсталятора (#1035)

Запуск: `python3 -m unittest discover -s packaging/tests -v` (Python 3.11+).
`bash -n packaging/install.sh` додатково перевіряє синтаксис.

Тести запускають справжній `install.sh` у тимчасовому каталозі з пробілами
в шляху. Ізольований `PATH` містить заглушки `uname`, `curl`, `apt-get`,
`brew` та старого CLI. Заглушка завантаження записує маленький shell CLI;
справжні пакетні менеджери й мережа недоступні. Наявність CLIPS імітована
порожніми файлами, тому перевірка не підтверджує працездатність островів.

Перевіряються вибір релізного артефакту Linux x86_64 / macOS arm64 / x86_64,
використання нового CLI замість старого з `PATH`, рання відмова для
непідтримуваної архітектури та збереження попереднього файла після
помилки завантаження, порожньої відповіді або невдалого `--version`.
Після відмови тимчасовий файл має бути прибраний.

Новий CLI спочатку завантажується у випадковий файл **поруч із ціллю**.
Після перевірки запуску `mv` замінює попередній файл у тій самій файловій
системі. Наявний CLI поза `~/.local/bin` не переписується. Це захист від
частково записаного завантаження, а не перевірка походження артефакту;
checksum і справжнє встановлення островів на чистих ОС лишаються окремими
задачами. Пакети та CLIPS можуть бути встановлені ще до невдалого CLI download;
транзакційне відкочування всієї системи не реалізоване.

## TECH-SCAN: 2026-09-20

Тема: обмежене в часі завантаження й заміна CLI без втрати попереднього файла.
Живо перевірене первинне джерело:
[curl man page](https://curl.se/docs/manpage.html), опції `--fail`,
`--connect-timeout`, `--max-time`, `--output`.
Рішення: застосувати наявні опції curl та тимчасовий файл; нових залежностей
не потрібно. Спроба відкрити GNU mktemp manual через web інструмент
повернула помилку, тому її не використано як підтверджене джерело.

## Локальний доказ

База: `e237c462`. До виправлення перші три тести дали шість невдалих
перевірок: старий CLI для трьох цілей, знищення старого файла після
часткового download та два сценарії непідтримуваної архітектури.
Після виправлення всі чотири тести проходять на Linux; macOS перевіряється
окремим CI job. Підміна `uname` у Linux сама по собі не є доказом запуску
на macOS. Цільовий workflow перевіряє shell-сценарій, а не реальні kernels.

## Питання для розбору коду

1. Чому `CLI_TEMP` створюється в `INSTALL_DIR`, а не в системному `/tmp`?
2. Що лишиться у `MY_LISP_TARGET`, якщо curl запише половину файла і поверне помилку?
3. Чому `EXE` містить точний шлях, хоча інсталятор уже додав каталог до `PATH`?
