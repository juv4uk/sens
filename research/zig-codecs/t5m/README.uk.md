# Zig ↔ asm ↔ Rust T5M · механічний парний бенчмарк

**T5M — дефолтний фізичний носій SENS:** 5 трітів/байт (`3^5 = 243 < 256`),
роздільник-трит 2. Це **окрема тека**, яка **не чіпає** чинний харнес
`research/zig-codecs/t5/`. Бенчмарк використовує **дефолтний T5M-кодек**
`research/zig-codecs/t5m.zig` (5 трітів/байт); 3-байтовий варіант — окремий,
`research/zig-codecs/t5m3.zig` (T5M3).

## Бекенди

| бекенд | джерело | що міряє |
|---|---|---|
| `zig` | `research/zig-codecs/t5m_bench.zig` (кодек `t5m.zig`, дефолтний T5M) | word → byte (end-to-end) |
| `asm` | `research/zig-codecs/t5m/bench_asm.zig` + `research/asm-t5m/t5m_words.S` + `t5m_pack.S` | word → byte (end-to-end) |
| `rust` | `crates/sens/examples/zig_t5_matched_bench.rs` | word → byte (end-to-end) |

Усі бекенди міряють той самий шлях **слово→байт / байт→слово**, тож рядки
прямо порівнювані; спільний інваріант — рівність фізичних байтів.

## Запуск (ручний; потрібні Linux x86_64, Zig 0.16.0, Rust/Cargo, `as`, libc)

```bash
python3 research/zig-codecs/t5m/run_paired_bench.py \
  --out-dir /tmp/sens-zig-asm-rust-t5m --pairs 3
cat /tmp/sens-zig-asm-rust-t5m/STATUS
cat /tmp/sens-zig-asm-rust-t5m/summary.md
```

Драйвер збирає всі бекенди, **звіряє повну рівність фізичних байтів і
фікстур між ними ДО таймінгу** і лише тоді публікує таблицю. Якщо паритет не
пройшов — `BLOCKED_NO_TIMING`, а не вигаданий speedup. Можна обмежити бекенди:
`--impls zig,asm` (без Rust).

## Статистика звіту

Поточний генератор `summary.md` виводить **p50 (медіану) і p90
(nearest-rank)** окремо для кожного бекенда, розміру корпусу та операції.
За `--pairs 3` це 15 сирих значень на одну клітинку (5 проб у кожному з
трьох запусків); p90 вибирає ранг `ceil(0.90 × n)` після сортування.
Це описова статистика малого дослідницького набору, **не** довірчий інтервал,
не повний Kalibera–Jones аналіз і не вимір швидкості семантики SENS.
Сирі проби та точне середовище залишаються в `samples.jsonl` і
`environment.json`; історичні числа нижче — попередній зріз, вони не
перераховані заднім числом.

Перевірка самої статистичної функції не збирає бекенди та не вимірює кодек:

```bash
python3 -m unittest discover -s research/zig-codecs/t5m -p 'test_*.py' -v
```

## Негативний профіль T5M (окремо від A/B)

`research/zig-codecs/t5m_bench.zig` додатково вимірює відмову Zig-кодека
на двох реальних некоректних фізичних байтах: `243` (поза діапазоном
`0..242`) і `242` (неприпустимий хвіст із п'яти роздільників).
Формат запису: `negative impl=zig case=... op=decode-reject error=... elapsed_ns=... reps=...`.
Вимірюється лише механіка **відхилення**, не семантичний вердикт SENS.

Це по три серії для кожного негативного входу з точним очікуваним кодом
`InvalidPhysicalByte` або `InvalidTail`. Не можна змішувати ці
`negative` з `sample` позитивних `encode/decode` або заявляти speedup;
парний A/B-драйвер зберігає свої 40 позитивних зразків на один бекенд.
Негативні записи залишаються у сирому виводі `pair-XX-zig.txt`.

Для контрольованих мікробенчмарків механізму Rust див. ізольований стенд
`benchmarks/measurement-triad/benches/wall_time_lane.rs` на Criterion:
256/1024/4096 звернень до D3 owner-map, 50 статистичних зразків, прогрів;
він **не** є оракулом Lisp. Власна мова вимірюється окремо фізичним SENS.

## Що НЕ доведено

Пам'ять/алокації, cachegrind, cold startup, bootstrap CI — **NOT_MEASURED**.
Це транспортна механіка, **не** SENS-семантика і **не** дозвіл на production
cutover. Важкі бенчмарки — лише ручний режим; нових автоматичних workflow не
додано (єдина автоматична точка — наявна `ci.yml`).

Raw samples: `samples.jsonl`; environment/SHA: `environment.json`.
