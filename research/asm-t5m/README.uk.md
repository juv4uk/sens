# T5M на асемблері — і бенчмарк проти Zig / Rust / C

Асемблерна реалізація ядра кодека **T5M** (дефолтний фізичний носій SENS) на
x86-64 і порівняння швидкості з референсними реалізаціями.

## Що таке T5M (дефолтний)

**5 трітів (0/1, роздільник 2) → 1 байт.** `3^5 = 243 < 256`, тож 5 трітів точно
вміщаються в байт; `value = value*3 + trit`, перший тріт — старший. Це
дзеркалить `lib/core4.lisp` (`трітів-у-байті 5`) і `scripts/sens_t5_t5m_codec.py`
(`encode_words`/`decode_bytes`).

Це **механізм транспорту**, а не джерело семантики SENS.

Окремо існує **T5M3**: 15 тритів → 3 байти little-endian. Його реалізація
лежить у `research/zig-codecs/t5m3.zig`, а Lisp-свідки мають префікс `т5м3-`.
Це окремий варіант; він не є дефолтом REPL чи фізичного носія.

## Файли

| файл | що це |
|---|---|
| `t5m_pack.S` | асемблерний pack/unpack (x86-64 SysV, без libc) |
| `t5m_ref.zig` | Zig-реалізація з C-ABI |
| `t5m_ref.rs` | Rust-реалізація з C-ABI (`#![no_std]`) |
| `bench.c` | спільний харнес: міряє asm, Zig, C (і Rust за `-DHAVE_RUST`) |
| `check_asm.py` | локальна перевірка: mmap `.text`, звірка з `scripts/sens_t5_t5m_codec.py` |

## Збірка й запуск

```sh
as --64 -o t5m_pack.o t5m_pack.S
zig build-obj t5m_ref.zig -O ReleaseFast -femit-bin=t5m_ref.o
rustc -O --edition 2021 --crate-type lib --emit obj -C panic=abort -o rust_t5m_ref.o t5m_ref.rs
zig cc -O2 -DHAVE_RUST bench.c t5m_pack.o t5m_ref.o rust_t5m_ref.o -o bench
./bench
```

## Результати

### CI (ubuntu-24.04, один процесор, 1 млн тритів, 200 повторів)

Коректність: asm, Zig, C і Rust дають **байт-у-байт ідентичний** результат, і всі
unpack повертають вихідні трити.

| реалізація | pack, M трит/с | unpack, M трит/с |
|---|---|---|
| асемблер | 4224 | 1664 |
| Zig | 3925 | 1740 |
| C | 6127 | 9871 |
| Rust | 3290 | 4303 |

Спостереження: ручний асемблер **на рівні Zig** (на pack навіть трохи попереду) і
попереду Rust, але C далеко виграє — для 5 трітів/байт компілятор повністю
розгортає й векторизує критичний цикл. Ділення на 3 в unpack замінено магічним
множенням `(x*0xAAAAAAAB)>>33`; без цього (через `div`) unpack був у рази
повільніший.

### Локально в сендбоксі (інший процесор)

pack: asm ~2077, zig ~1908, c ~3567. unpack: asm ~819, zig ~848, c ~3474.
