# Архів PR #2316 — reduce під строгим D1

**Статус: АРХІВОВАНО / ЖИВИЙ БЛОКЕР НЕ ВИРІШЕНО.**

PR містить трискладовий fix для reduce: порожній список має повертати accumulator, non-empty atom — структурне `()`, а pair — рекурсію. Це окрема семантична межа; її не слід закривати лише тим, що гілка чи patch існують.

Точні branch-head версії `lib/core.lisp` і `lib/core4.lisp` збережені як `.source.txt`, binary `lib/core4.lisp.fasl` — як Base64 з оригінальним Git blob SHA у manifest. Їх не можна скопіювати цілком поверх current main: базовий source era застарів, і FASL мусить бути згенерований із поточного Core4 після атомарного replay. Позитивна умова: зберегти всі три стани; негативні свідки мають відкинути випадкове спрощення empty list/non-empty atom/pair.

Проблема лишається в наявній #2295/#2298/#5041 черзі. Архів зберігає гілку для exact-source replay, але не заявляє blocker resolved. Нову гілку не створено.
